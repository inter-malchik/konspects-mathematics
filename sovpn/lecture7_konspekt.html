§1. Обучаемое разреженное внимание (сл. 3–7)

1.1. От шаблонного к обучаемому разреженному вниманию (сл. 3)

Продолжение Лекции 6: шаблонное разреженное внимание разобрано в конспекте Лекции 6, §6.1 (сл. 34) — lecture6_konspekt.html#p6.

Шаблоны связей в шаблонном разреженном внимании задаются независимо от входных данных заранее. Однако разные токены могут требовать разного набора связей, поэтому логичнее позволить модели самостоятельно отбирать, какие связи оставлять, а какие отбрасывать (сл. 3).

Из записи лекции [00:03–01:02]

Лектор напоминает, что на прошлой лекции разбиралось шаблонное разреженное внимание — архитектура, названная им «довольно устаревшей». Сейчас на практике используется в основном обучаемое разреженное внимание, и в качестве примера лектор разбирает недавно вышедший DeepSeek Sparse Attention (DSA). Если в шаблонном разрежении механизм разрежения задаётся заранее и не зависит от входных данных, что «довольно странно», раз цель — отбрасывать именно ненужные токены, то логично поручить отбор токенов самой модели.

На пальцах

Шаблонное разрежение — это как заранее распечатанный трафарет, через который всегда подсвечиваются одни и те же слова страницы, независимо от того, что на ней написано. Обучаемое разрежение — это скорее маркер в руках у читателя, который каждый раз сам решает, что на этой конкретной странице важно.

1.2. Lightning Indexer (сл. 4)

DeepSeek Sparse Attention предлагает индексатор Lightning Indexer, вычисляющий приближённую оценку между текущим вектором запроса и предыдущими токенами (сл. 4):

$$I^{t,s} = \sum_{j=1}^{n_h} w_j^t \operatorname{ReLU}(q_j^t k_j^s)$$

По форме это похоже на механизм внимания, но дешевле: оценка $I^{t,s}$ считается по всем головам $j$ с обучаемыми весами $w_j^t$, а $\operatorname{ReLU}$ обеспечивает неотрицательность вклада каждой головы.

Из записи лекции [01:03–02:15]

Индексатор вычисляет оценку между текущим вектором запроса и предыдущими токенами; по сути, это приближённая и более дешёвая оценка того же механизма внимания. Параметры $w_j^t$, с которыми складываются оценки внимания по головам, нужно обучать.

На пальцах

Индексатор — это дешёвый «предварительный тест», который прикидывает, какие токены вообще стоит проверять полным (дорогим) механизмом внимания, вместо того чтобы сразу считать точный, но дорогой результат для всех пар токенов.

1.3. Обучение индексатора: стадия 1 — плотное внимание (сл. 5)

Индексатор необходимо обучить, чтобы он работал корректно. На первой стадии слой внимания замораживается и остаётся плотным; обновляются только параметры индексатора, который выучивает распределение весов плотного внимания $p^{t,:}$ (сл. 5):

$$L^I = \sum_t D_{KL}\langle p^{t,:} \| \operatorname{Softmax}(I^{t,:})\rangle$$

Из записи лекции [02:16–03:22]

Индексатор обучается в две стадии. На первой внимание заморожено и остаётся плотным, задача индексатора — выучить распределение весов этого плотного внимания. Для измерения расстояния между желаемым распределением и текущим используется дивергенция Кульбака — Лейблера; лектор отмечает, что формулу можно переписать и обучать, например, через кросс-энтропию — это эквивалентная переформулировка той же задачи.

На пальцах

Стадия 1 — это стажёр (индексатор), которого учат предсказывать оценки уже опытного эксперта (полного внимания), не позволяя пока принимать решения самостоятельно: цель — научиться просто копировать поведение эксперта.

Вне слайдов

Дивергенция Кульбака — Лейблера $D_{KL}(p\|q) = \sum_i p_i \log(p_i/q_i)$ неотрицательна и равна нулю тогда и только тогда, когда распределения совпадают, но несимметрична ($D_{KL}(p\|q) \ne D_{KL}(q\|p)$), поэтому важен порядок аргументов: здесь приближаемое распределение индексатора $\operatorname{Softmax}(I^{t,:})$ подгоняется под целевое $p^{t,:}$ настоящего внимания.

1.4. Обучение индексатора: стадия 2 — top-k отбор (сл. 6)

На второй стадии веса внимания размораживаются; теперь для каждого токена индексатор выбирает множество из $k$ самых важных позиций (сл. 6):

$$s^t = \operatorname{Top}_k(I^{t,:})$$

Распределение выходов внимания меняется, поэтому распределение индексатора тоже нужно обновлять под новое, уже отфильтрованное множество позиций:

$$L^I = \sum_t D_{KL}\langle p^{t,s^t} \| \operatorname{Softmax}(I^{t,s^t})\rangle$$

Из записи лекции [03:23–04:32]

Отбор $k$ позиций лектор называет «чем-то вроде фильтрации». Поскольку распределение выходов механизма внимания при этом меняется, распределение индексатора тоже приходится переобучать: теперь оно считается уже только по отфильтрованным (оставленным) токенам, а не по всем.

На пальцах

Стажёр переходит от полного копирования эксперта к работе по сокращённому списку: теперь он сам отбирает $k$ самых важных дел из всех и подстраивает свою оценку важности уже только под этот сокращённый список, а не под всё сразу.

1.5. Эффективность DSA (сл. 7)

Такой индексатор требует дополнительных вычислений, синхронизаций и, возможно, коммуникаций при обучении на длинном контексте. Эффективность индексатора напрямую зависит от того, насколько дёшево он устроен и насколько эффективно реализованы его вычисления на GPU — например, можно считать индексатор в более низкой точности по сравнению с механизмом внимания, скажем, fp8 или даже fp4 (сл. 7).

Из записи лекции [04:33–07:48]

Дополнительные вычисления — очевидная цена такого индексатора, но менее очевидна необходимость дополнительной синхронизации и коммуникации при обучении на длинном контексте. При отборе top-k позиций нужно просуммировать оценки индексов по всем элементам последовательности; если используется контекстный параллелизм (последовательность режется на 2, 4, 8 частей по рангу параллелизма), для такой редукции нужно собрать эти элементы на одном устройстве (например, через all-reduce или reduce-scatter) — а это уже коммуникация и, соответственно, синхронизация, которая неизбежно замедляет работу механизма. Поэтому эффективность разреженного внимания зависит от дешевизны реализации индексатора на GPU — например, вычисления можно вести в пониженной точности (fp8), но не в fp4: считать в fp4 сам механизм внимания лектор называет «смерти подобно» — слишком большая ошибка, а вот держать его в bf16 — рабочий вариант. Тему смешанной точности и квантизации лектор сознательно не разбирает на этой лекции («на лекции мы не будем разбирать вычисления в смешанной и низкой точности») и отсылает к отдельной главе об этом в письменных конспектах.

На пальцах

Если разбить работу между несколькими людьми (устройствами), а затем всё равно нужно, чтобы каждый посмотрел на общий список перед тем, как принять решение, — время на согласование («кто главный по каждому вопросу») никуда не девается, даже если сама работа была распределена. Это и есть цена синхронизации при контекстном параллелизме.

Вне слайдов

Контекстный параллелизм — способ распределённого обучения, при котором последовательность токенов одного примера делится на части между разными устройствами (в отличие от параллелизма по данным, где между устройствами делятся разные примеры), что и создаёт необходимость обмена данными между рангами при операциях, требующих информации по всей последовательности целиком, как в описанном отборе top-k.

§2. Сжатое внимание (сл. 9–16)

2.1. Идея: сжатие входа механизма внимания (сл. 9)

Вместо того чтобы отсеивать токены целиком, как в разреженном внимании, можно сжимать поступающую на вход механизма внимания информацию: развивая идею Multi-Head Latent Attention (MLA), входы проецируются в пространство меньшей размерности (сл. 9):

$$C = HW^{KV}, \qquad C \in \mathbb{R}^{n \times d_c}$$

Матрица $H$ сжата по оси $d$ (размерность признаков); дальше сжимают ещё и по оси $n$ (число токенов последовательности) — например, объединяя 4 токена в один вектор простым усреднением:

$$c_1^{\text{comp}} = 0{,}25c_1 + 0{,}25c_2 + 0{,}25c_3 + 0{,}25c_4$$

Из записи лекции [07:49–08:59]

В разреженном внимании некоторые токены отфильтровываются полностью, хотя даже слабо информативный токен обычно несёт не нулевую информацию — поэтому логичнее не отбрасывать, а сжимать. Развивая идею Multi-Head Latent Attention, входы механизма внимания проецируются в пространство меньшей размерности — получается матрица $C$: это сжатие входной матрицы $H$ по оси $d$.

На пальцах

Разреженное внимание — это «выбросить часть страниц конспекта», сжатое внимание — «уместить содержание тех же страниц в более короткий пересказ», не выбрасывая ни одной темы целиком.

2.2. Сжатие по оси n: от наивного среднего к обучаемым векторным коэффициентам (сл. 10)

Простое усреднение — «слишком наивный» и не зависящий от входных данных подход. Вместо скалярных весов вводятся обучаемые векторные коэффициенты: вход преобразуется матрицей $W^Z$ и берётся $\operatorname{Softmax}$ по столбцам (сл. 10):

$$S^\top = \operatorname{Softmax}\big[(HW^Z)^\top\big], \qquad S \in \mathbb{R}^{n \times d_c}$$

Тогда сжатые векторы получаются как взвешенная (а не простая усреднённая) сумма по группе из 4 токенов, с покомпонентным умножением $\odot$:

$$c_1^{\text{comp}} = \sum_{i=1}^{4} s_i \odot c_i, \qquad c_2^{\text{comp}} = \sum_{i=5}^{8} s_i \odot c_i, \quad \ldots$$

Из записи лекции [09:00–10:04]

Простые скалярные веса не зависят от входных данных, к тому же их хочется сделать обучаемыми — поэтому коэффициенты делаются векторными: входная матрица преобразуется матрицей $W^Z$, и по столбцам берётся $\operatorname{Softmax}$. Запись транспонирована, потому что $\operatorname{Softmax}$ нужно брать именно по столбцам полученной матрицы $HW^Z$; лектор прямо признаёт, что запись получилась не самой изящной («не придумал, как лучше это записать»).

На пальцах

Простое среднее — это «каждое из четырёх слов абзаца одинаково важно при пересказе». Векторные коэффициенты через $\operatorname{Softmax}$ — это «пересказ учитывает, что какие-то из четырёх слов важнее для смысла, чем остальные», причём то, какие именно, определяется самими данными, а не жёстко зашито заранее.

2.3. Пересекающиеся группы (сл. 11)

Деление токенов на непересекающиеся четвёрки создаёт искусственные границы между группами. Чтобы группа «видела» контекст предыдущей группы, группы делают пересекающимися: например, для второго сжатого вектора берут уже 8 токенов вместо следующих четырёх, и матрицы проекций $W^{KV}$ и $W^Z$ разделяют на отдельные матрицы для текущей и для прошлой группы (сл. 11):

$$c_1^{\text{comp}} = \sum_{i=1}^{4} s_{\text{curr},i}\odot c_{\text{curr},i}, \qquad c_2^{\text{comp}} = \sum_{i=1}^{8} s_{\text{curr},i}\odot c_{\text{curr},i} + \sum_{i=1}^{4} s_{\text{prev},i}\odot c_{\text{prev},i}, \quad \ldots$$

Из записи лекции [10:05–12:12]

Разбиение на непересекающиеся четвёрки — это произвольная искусственная граница («а почему четвёрка? почему мы их так делим?»). Чтобы группа сохраняла немного контекста от предыдущей, группы делают пересекающимися: например, следующий сжатый вектор строится уже из восьми, а не из четырёх токенов. Чтобы явно разделить вклад «текущей» и «прошлой» групп, проекционные матрицы $W^{KV}$ и $W^Z$ делят на отдельные версии для текущей и для прошлой группы.

На пальцах

Непересекающиеся группы — это как делить книгу на главы, не позволяя ни одному предложению «заглянуть» в предыдущую главу. Пересекающиеся группы — это скользящее окно пересказа: следующий абзац пересказа помнит и то, что было в предыдущем.

2.4. Почему матрицу S считают из H, а не из C (сл. 12)

Матрицу $S$ можно было бы вычислять и как проекцию уже сжатого латентного представления $C$ — размерности совпали бы, а параметров и вычислений потребовалось бы меньше. Но вычисляется она именно из входа $H$ (сл. 12):

$$S_{\text{curr}}^\top = \operatorname{Softmax}\big[(HW_{\text{curr}}^Z)^\top\big], \qquad \text{а не} \qquad S_{\text{curr}}^\top = \operatorname{Softmax}\big[(C_{\text{curr}}W_{\text{curr}}^Z)^\top\big]$$

В первом случае вычисление пары матриц $S$ и $C$ можно сделать параллельно в одном GPU-ядре; во втором — придётся считать их последовательно.

Из записи лекции [12:13–13:22]

Казалось бы, вычислять $S$ из уже сжатого пространства $C$ логичнее — размерности те же, а вычислений и параметров нужно меньше. Но если считать $S$ и $C$ из одного и того же входа $H$, оба вычисления можно слить в одно GPU-ядро и выполнить параллельно; если же $S$ зависит от результата вычисления $C$, их приходится считать строго последовательно. Лектор отмечает, что слияние двух ядер в одно обычно эффективнее, чем запускать их по отдельности, «хотя это не всегда так, особенно для матричных умножений» — но в этом конкретном случае правило работает.

На пальцах

Это разница между «сделать два независимых замера одновременно» и «сначала получить результат первого замера, и только потом на его основе сделать второй» — первое быстрее просто потому, что не создаёт очереди.

2.5. Применение сжатия в механизме внимания (сл. 13)

Сжатые входы подаются на все K- и V-головы механизма внимания, что позволяет увеличить размерность самих голов K и V. Но матрица $W^Q$, проецирующая входы в пространство запросов, при этом становится огромной (сл. 13).

Из записи лекции [13:23–14:34]

Раз входы сжаты по последовательности, вычислений меньше, и «сэкономленную» ёмкость можно направить на увеличение размерности голов K и V. Оценивая размер получающейся матрицы $W^Q$ на числовом примере (вход размерностью 8192, скрытое пространство 512, 128 голов), лектор отмечает, что даже для одного слоя и одной матрицы $Q$ параметров получаются миллиарды — «с этим надо что-то делать».

На пальцах

Увеличение размерности K/V-голов за счёт сжатия последовательности — это как освободившееся время в расписании потратить на то, чтобы каждую встречу сделать длиннее и подробнее; но тогда сама «повестка» встречи ($W^Q$) распухает пропорционально.

2.6. Низкоранговая матрица $W^Q$ (сл. 14)

Чтобы матрица $W^Q$ не становилась огромной, применяется низкоранговый подход: она раскладывается на две матрицы меньшего размера (сл. 14):

$$Q = HW_{\text{down}}^Q W_{\text{up}}^Q$$

Из записи лекции [14:35–15:57]

Матрица $W^Q_{\text{down}}$ проецирует вход в существенно меньшее пространство (например, 128 вместо 512), а $W^Q_{\text{up}}$ проецирует уже из этого сильно сжатого пространства обратно в рабочую размерность запросов.

На пальцах

Вместо одной гигантской таблицы перевода «вход → запрос» используются две небольшие: сначала «сожми смысл до сути» (down), потом «разверни суть в нужный формат» (up) — как конспект, а не дословный пересказ, на промежуточном шаге.

2.7. Группировка выходных проекций (сл. 15)

Аналогичная проблема роста размера возникает и с выходной матрицей $O$: её делят на группы и проецируют матрицей $W_{\text{down}}^O$ в пространство меньшей размерности, затем группы конкатенируют и проецируют обратно в исходное пространство матрицей $W_{\text{up}}^O$ (сл. 15):

$$O_i \in \mathbb{R}^{n \times \left(\frac{c\times h}{g}\right)}, \qquad W_{\text{down}}^O \in \mathbb{R}^{\left(\frac{c\times h}{g}\right)\times n_g}, \qquad O_i^G = O_i W_{\text{down}}^O, \qquad O_i^G \in \mathbb{R}^{n\times n_g}$$

Из записи лекции [15:58–18:15]

Подход, симметричный низкоранговому разложению $W^Q$, но применённый к матрице $O$ и по группам голов. Каждую группу проецируют матрицей $W^O_{\text{down}}$ в пространство меньшей размерности $n$, конкатенируют результаты всех групп, а объединённый результат проецируют в исходную размерность матрицей $W^O_{\text{up}}$. Такой подход называется группировкой выходных проекций; его главная польза — почти без потери качества уменьшить размер матриц $W^Q$ и $W^O$ почти в 6,5 раза.

На пальцах

Вместо того чтобы у каждой из сотен голов внимания была своя полноразмерная «выходная форма», головы объединяют в небольшие группы с общим, компактным форматом вывода — экономия на масштабе за счёт разумного обобществления параметров.

2.8. CSA и HCA: итоговый механизм (сл. 16)

Три механизма — сжатие токенов, обучаемое разреженное внимание (DSA, §1) и группировка выходных проекций — вместе с многоголовым вниманием образуют сжатое разреженное внимание (CSA). CSA имеет коэффициент сжатия 4 к 1. DeepSeek также представили механизм сильно сжатого внимания (HCA) со сжатием 128 к 1, при котором разреженное внимание уже не требуется (сл. 16).

Из записи лекции [18:16–19:28]

Объединение трёх рассмотренных механизмов — сжатия токенов, разреженного внимания и группировки выходных проекций — с многоголовым вниманием даёт механизм сжатого разреженного внимания CSA; используется он, по словам лектора, в DeepSeek V4. HCA отличается от CSA практически только степенью сжатия (128 векторов в один вместо 4), и при таком сжатии контекстное окно можно довести до миллиона токенов вообще без разреженного внимания.

Вне слайдов

В опубликованных технических материалах о DeepSeek-V4 (сентябрь 2026 г.) сжатие 4:1 в CSA описывается как компрессия KV-кэша каждые $m=4$ токена в одну запись с последующим отбором top-k через Lightning Indexer, а HCA — как компрессия с $m=128$ и плотным вниманием уже без top-k-отбора внутри сжатой последовательности; это согласуется с изложением на слайдах и в записи лекции.

§3. Self-supervised learning (сл. 18–21)

3.1. Что такое SSL (сл. 18)

Supervised learning — обучение с учителем, то есть по размеченным данным. Unsupervised learning — обучение без учителя, то есть когда размеченных данных нет. Self-supervised learning — обучение с самоконтролем: размеченных данных как бы нет, но задачу supervised learning можно получить из самих имеющихся данных на предлоговой задаче (pretext task), чтобы подготовить веса модели к прикладной задаче (downstream task) (сл. 18).

Из записи лекции [19:29–24:04]

Лектор поясняет SSL на примере: пусть есть табличные данные для предсказания стоимости жилья, но самой колонки со стоимостью нет — зато есть похожая по смыслу фича, например рейтинг жилья. Эту фичу можно временно сделать целевой переменной (убрав её из признаков и подставив вместо неё фиктивную, чтобы сохранить размерность), и обучить модель предсказывать её — это и есть предлоговая задача. Полученные так веса дальше дообучают на маленьком размеченном датасете с реальной стоимостью жилья — это уже прикладная (downstream) задача, требующая куда меньше размеченных данных, чем обучение с нуля.

На пальцах

SSL — это как тренироваться на старых экзаменационных билетах по смежной теме перед настоящим экзаменом: разметки «правильных ответов» для реального экзамена ещё нет, но потренировать нужные навыки на похожей задаче уже можно, и вступать в реальный экзамен придётся не с нуля.

3.2. Архитектура BERT (сл. 19)

Рисунок (сл. 19). Архитектура BERT. Две панели «Pre-training» и «Fine-Tuning»: на входе последовательность токенов с эмбеддингами $E_{[CLS]}, E_1, \dots$ (пара замаскированных предложений A и B, разделённых токеном [SEP]), они проходят через блок BERT, на выходе — векторы $C, T_1, \dots$; при предобучении из выходов решаются задачи NSP и Masked LM (MLM), при дообучении те же выходы используются для задач MNLI/NER/SQuAD с классификацией начала/конца ответа (Start/End Span).

BERT — трансформер-кодировщик; часто используется для того, чтобы сжать предложение в один вектор (сл. 19).

Из записи лекции [24:05–25:33]

Архитектурно BERT — это трансформер-кодировщик с добавленным обучаемым токеном CLS, который лектор уже разбирал ранее (в контексте Vision Transformer) как способ сжать предложение или изображение в один вектор.

Из конспектов лектора (§1.1.1)

Модель спроектирована как предобученный кодировщик для векторных представлений неразмеченного текста с учётом контекста слева и справа одновременно. Двунаправленное внимание важно там, где смысл слова зависит от окружения с обеих сторон: например, в предложении «Он пошёл в ___, чтобы купить хлеб» для восстановления пропуска нужен контекст и до, и после него. Именно поэтому двунаправленное внимание неприменимо для автогенерации текста, как в GPT, где будущий текст заранее не может быть учтён.

3.3. Предобучение BERT: MLM и NSP (сл. 20)

Для предобучения BERT использовались две задачи: обучение на маскированной языковой модели и определение, является ли поданное предложение следующим предложением для текущего текста (сл. 20).

Из записи лекции [25:34–26:46]

Первая задача — обучение на маскированной языковой модели: случайно маскируется часть токенов текста, и модель учится восстанавливать исходный текст; никакой ручной разметки для этого не требуется, только сам текст. Вторая задача — модели подают кусок текста и рядом с ним отдельное предложение и обучают предсказывать, является ли поданное предложение реальным продолжением этого текста. По смыслу первая задача учит модель контексту внутри одного предложения, а вторая — контексту между предложениями.

Из конспектов лектора (§1.1.3–1.1.4)

Для Masked Language Modeling (MLM) специальный тренировочный генератор случайно выбирает 15% токенов последовательности и модифицирует их так: в 80% случаев токен заменяется на служебный токен [MASK], в 10% — на случайный токен из словаря, в оставшихся 10% токен остаётся неизменным; минимизируется кросс-энтропия между предсказаниями модели на месте маскированных токенов и исходными (немаскированными) токенами. Для Next Sentence Prediction (NSP) предложения A и B выбираются так, что в половине случаев B действительно продолжает A (IsNext), а в другой половине B — случайное предложение (NotNext); предложения разделяются токеном [SEP], а для самой классификации IsNext/NotNext используется токен [CLS].

На пальцах

Если бы маскировался всегда один и тот же служебный токен, модель на инференсе (где токена [MASK] вообще не существует) могла бы «лениться» и полагаться на сам факт наличия маски, а не на контекст. Правило 80/10/10 не даёт ей опереться на этот костыль: иногда вместо маски — случайный мусорный токен, иногда — вообще ничего не изменилось, и предсказывать «что должно быть здесь» приходится по контексту в любом случае.

Вне слайдов

Использование Masked Multi-Head (Self) Attention, которое в декодировщике не даёт «подглядывать» в будущие токены, для двунаправленной модели неприменимо в принципе — иначе модель могла бы напрямую увидеть маскированный токен через тот же контекст, для восстановления которого она обучается; поэтому BERT использует не маскированное (в архитектурном смысле), а полное внимание кодировщика, а маскирование происходит только на уровне входных данных (замена токенов), а не на уровне self-attention.

3.4. GPT: декодировщик и предсказание следующего токена (сл. 21)

Рисунок (сл. 21). Архитектура GPT. Блок из 12 повторяющихся ($\times 12$) слоёв: Text & Position Embed → Masked Multi Self Attention → Layer Norm (с residual-связью) → Feed Forward → Layer Norm (с residual-связью); на выходе блока — Text Prediction и Task Classifier.

GPT — трансформер-декодировщик, обучается на задаче предсказания следующего токена (сл. 21).

Про GPT студенты уже знают по лабораторным работам курса. Предсказание следующего токена — это тоже предлоговая задача self-supervised learning: датасеты вроде WikiText или Common Crawl никогда не размечались вручную, но, обучая модель считать функцию потерь и обновлять параметры по градиентам на задаче предсказания следующего токена, студенты уже решали SSL-предлоговую задачу — именно на ней сейчас предобучаются все большие языковые модели. Если коротко: предобучение LLM — это и есть предлоговая задача SSL, а пост-обучение / alignment — прикладная (downstream) задача, устроенная существенно сложнее и использующая методы обучения с подкреплением.

Из конспектов лектора (§1.2)

Через год после появления трансформеров, в 2018 году, исследователи OpenAI опубликовали статью «Improving Language Understanding by Generative Pre-Training», представив GPT-1; несмотря на относительно небольшой размер (117 млн параметров), модель показала высокую производительность в нескольких задачах NLP и проложила путь к моделям с многомиллиардным числом параметров.

На пальцах

BERT «читает» предложение целиком сразу в обе стороны, чтобы понять контекст (годится для понимания текста, но не для его порождения по одному слову за раз). GPT читает только слева направо и учится продолжать текст — поэтому годится для генерации, но каждое слово видит лишь то, что было до него.

§4. Мультимодальность (сл. 23–27)

4.1. Что такое мультимодальность (сл. 23)

Мультимодальность в нейронных сетях означает способность модели обрабатывать информацию из разных типов данных — модальностей (изображения, текст, аудио, видео и т. д.). Граница между модальностями часто зыбкая: правильнее говорить не о строгой категоризации, а о переходе от более однородных и схожих данных к структурно более разнородным (сл. 23).

Из записи лекции [30:22–31:46]

Модальностями могут быть изображения, текст, аудио, видео, облака точек 3D и так далее. Граница между модальностями зыбкая: например, можно ли считать код отдельной модальностью или это просто отдельный домен языка? Видео вообще содержит и аудиодорожку, и визуальный ряд из отдельных изображений. Поэтому лектор предпочитает говорить не о жёсткой категоризации, а о переходе от более однородных данных к более разнородным.

Из конспектов лектора (§2)

Иллюстрация степени однородности: два снимка мелких камней на конвейере одного завода в один день — почти неотличимы, это точно одна модальность. Текст на естественном языке и программный код различаются по структуре и синтаксису, но оба кодируются последовательностью символов (например, в UTF-8) и одна модель может обучаться на обоих — это, скорее, разные домены одной модальности, чем разные модальности. Текст и изображения же требуют принципиально разных архитектур обработки — это точно разные модальности.

На пальцах

Спектр «однородность → разнородность» удобно представлять как шкалу: два фото одного и того же конвейера — почти одна точка на шкале; текст и код на одном алфавите — уже заметно дальше друг от друга, но ещё в одной «стране»; текст и картинка — разные «страны» с разным языком описания.

4.2. CLIP: контрастное обучение (сл. 24)

Рисунок (сл. 24). Схема CLIP. Текст («Pepper the aussie pup») проходит через Text Encoder и даёт токены $T_1 \ldots T_N$; батч изображений проходит через Image Encoder и даёт токены $I_1 \ldots I_N$; на пересечении строится матрица попарных произведений $I_i{\cdot}T_j$ — по главной диагонали лежат пары, которые должны совпадать.

Если закодировать изображения с помощью Vision Transformer (ViT), их токены будут лежать в одном семантическом пространстве; если закодировать текст с помощью BERT — в другом, даже если размерности совпадают (сл. 24).

Из записи лекции [31:47–39:00]

Чтобы сблизить токены модальности изображений с токенами модальности текста, применяется контрастное обучение: строится матрица попарных сходств между токенами изображений и токенами текста в батче. Для пар с совпадающими индексами (главная диагональ) косинусное расстояние между векторами минимизируется, для всех остальных пар — максимизируется. В ходе разбора студент (Speaker 2) уточнял, как именно определяется «совпадение» пары: лектор пояснил, что совпадение — это совпадение индексов внутри батча (первый токен изображения — с первым токеном текста и т. д.), а не какое-то заранее заданное свойство самой картинки, то есть для любого другого набора изображений в батче диагональ строится точно так же, но сами векторы на ней будут другими. Итог обучения — кодировщик изображений (например, ViT) обучается выдавать вектора в том же семантическом пространстве, что и текстовые векторы; лектор подчёркивает, что процесс лишь стремится минимизировать это расстояние, не гарантируя точного совпадения, но результат оказывается лучше, чем при обучении того же ViT на посторонней задаче вроде классификации текста.

Из конспектов лектора (§2.3)

CLIP (Contrastive Language-Image Pre-training, OpenAI, статья 2021 года) обучался на 400 миллионах пар «изображение — текст». Формула косинусного сходства пары векторов:

$$\operatorname{cosine\_similarity}(I_k, \tau_j) = \frac{(I_k, \tau_j)}{\|I_k\|\cdot\|\tau_j\|}$$

CLIP способен к обобщению и распознаванию образов без явного дообучения (zero-shot), включая, по данным конспектов, распознавание геолокации и действий на изображении, но не распознавание текста на изображении.

На пальцах

Обучение CLIP — это как расставлять точки на карте так, чтобы город и его правильное название на этой карте оказались рядом, а город и чужое название — подальше друг от друга; после многих таких «подвижек» для миллионов пар город и правильное имя в среднем оказываются ближе, чем случайно выбранная пара.

Вне слайдов

В конспектах лектора отдельно рассматривается более ранняя задача image-captioning через архитектуру кодировщик-декодировщик (например, ViT-кодировщик + GPT-2-декодировщик) с перекрёстным вниманием, где матрица ключей строится из выхода ViT ($K = X_{\text{ViT}}W^K$), а матрица запросов — из уже сгенерированного текста ($Q=X_{\text{GPT}}W^Q$); проблема ровно та же, что мотивирует CLIP — нет гарантии, что $X_{\text{ViT}}$ и $X_{\text{GPT}}$ лежат в одном семантическом пространстве, из-за чего вся нагрузка по «состыковке» ложится на проекции $W^Q, W^K$. Также в конспектах упомянута модель BLIP (Bootstrapping Language-Image Pre-training), которая по этой же причине улучшает качество обучающих данных: сначала обучается модель, генерирующая подписи к изображениям, затем модель-фильтр отсеивает некачественные подписи, что снижает влияние шумной ручной разметки и одновременно обогащает датасет. Эта тема не прозвучала устно на лекции.

4.3. Кросс-модальность трансформеров (сл. 25)

Трансформеры способны успешно обрабатывать и текст, и изображения. Текст — это последовательность, изображение — двумерная структура, но трансформер воспринимает любые входные данные как неупорядоченное множество; главное — поставить задачу так, чтобы данные разных модальностей лежали в одном семантическом пространстве (сл. 25).

Из записи лекции [39:00–41:22]

Порядок в этом множестве задаётся отдельно, позиционным кодированием. Текстовых данных много и на них удобно обучать большие модели, поэтому в мультимодальных системах текст обычно и есть основная модальность, вокруг которой предобучается основная модель; к ней затем добавляют другие модальности — изображения, аудио, видео, синтез речи из текста.

На пальцах

Текст для трансформера — как бусины на нитке, а изображение — как рассыпанные бусины без нитки вовсе; но раз трансформер и так смотрит на «бусины» (токены) как на множество, а порядок восстанавливает отдельно (позиционным кодированием), ему в этом смысле почти всё равно, откуда взялось множество — из предложения или из кусочков картинки.

4.4. Фьюз модальностей (сл. 26)

Рисунок (сл. 26). Три схемы фьюза. Early fusion: кодировки модальностей A и B подаются на вход основной модели вместе. Deep fusion: кодировки модальностей подаются внутрь основной модели на промежуточных слоях (стрелки внутрь Core Model). Late fusion: каждая модальность обрабатывается отдельной моделью, а результаты объединяются уже на выходе.

Есть три способа подмешать дополнительную модальность к основной модели: early fusion, deep fusion и late fusion. В LLM в основном используется early fusion (сл. 26).

Из записи лекции [41:23–48:37]

Текст — основная модальность, потому что текстовых данных много и на них дёшево обучать; для изображений энкодер обучают через CLIP-подобный подход. Для видео и аудио обучать такой же CLIP-подобный кодировщик дорого: нужны размеченные пары «данные + подробное описание», а для видео с таймкодами такое собрать особенно тяжело. Решение — адаптер: небольшая сеть, которая проецирует токены модальности в пространство текста; основная модель и кодировщик модальности замораживаются, обучается только адаптер, обычно на задаче предсказания следующего токена. Early Fusion — основной подход в LLM; Deep Fusion чаще используется в диффузионных моделях (например, Stable Diffusion), а не в языковых моделях; Late Fusion в лекции упомянут третьим вариантом, но подробно не раскрывался.

Из конспектов лектора (§2.6.3)

Про late fusion, не прозвучавший подробно устно: объединение происходит на самом последнем этапе, перед финальным выходом модели (например, объединение логитов в задаче классификации). Это самый дешёвый в реализации способ, но на практике почти не даёт прироста качества, поскольку связи между модальностями внутри модели почти не учитываются.

На пальцах

Early fusion — это «сразу перевести иностранный текст на общий язык и читать всё вместе». Deep fusion — «держать переводчика рядом и советоваться с ним на каждом шаге чтения». Late fusion — «прочитать оба текста по отдельности до конца и только затем сравнить общие выводы».

Подход применим не только к изображениям, но и к видео, аудио, 3D-данным и другим модальностям — вопрос в том, что разные кодировщики можно дообучать под разные домены.

Из конспектов лектора (§2.6.4)

Конспекты лектора перечисляют конкретные обучаемые правила объединения эмбеддингов помимо гейтинга: pixel-shuffle (увеличение ширины эмбеддингов за счёт уменьшения длины последовательности через реорганизацию векторов, с последующим единым адаптером вместо отдельных на каждый кодировщик), аддитивное смешивание $z=\sum_{i=1}^k w_i x_i$ с обучаемыми весами $w_i$, мультипликативное смешивание $z = w(x_1 \times x_2)$, и gated fusion $z=\sum_{i=1}^k g_i(x_1,\ldots,x_k)x_i$, где $g_i$ — уже не число, а функция внимания.

На пальцах

Это похоже на консилиум врачей разных специализаций, которым показывают один и тот же снимок: общий терапевт (базовый CLIP) даёт грубую оценку, а профильный специалист (медицинский кодировщик) поправляет её там, где терапевт мог ошибиться из-за нехватки узкой экспертизы.

§5. Законы масштабирования (сл. 29–37)

5.1. Предпосылки масштабирования (сл. 29)

Есть данные (получаемые в том числе с помощью SSL и мультимодальности), есть удачно масштабируемая модель — трансформер со всеми рассмотренными архитектурными и инженерными улучшениями, — и есть вычислительные мощности и способ их организации. Время масштабироваться до LLM (сл. 29).

Из записи лекции [50:43–52:51]

Мультимодальность и SSL нужны, помимо прочего, чтобы расширить объём доступных данных: текстов в интернете много, но конечное количество, а с других модальностей (например, видео на YouTube) можно получить дополнительные данные для моделей генерации изображений, видео и LLM с общими знаниями. Вычислительные мощности и распределённое обучение упоминаются со ссылкой на отдельную лекцию курса про распределённое обучение, где рассматривался кластер порядка (по словам лектора, неточно, «по-моему») 65 тысяч GPU — по масштабу достаточный для обучения модели на пару триллионов параметров.

На пальцах

Три условия масштабирования — это как для постройки дома нужны одновременно материалы (данные), удачный проект (архитектура) и бригада с техникой (вычисления): нехватка любого из трёх не даст просто «долить» два оставшихся и получить тот же результат.

5.2. Законы масштабирования: рост данных, параметров, компьюта (сл. 30–31)

Если увеличивать размер модели, зафиксировав количество данных, — лосс падает. Если увеличивать количество данных, зафиксировав размер модели, — лосс тоже падает. Если увеличивать и то, и другое одновременно — лосс падает ещё сильнее. Вопрос — насколько именно и по какому закону (сл. 30–31).

Из записи лекции [52:52–55:18]

Такие эмпирически полученные зависимости и называют законами масштабирования. На лог-лог графике зависимость выглядит как прямая линия — характерное свойство степенного закона. На числовом примере: увеличение объёма данных в 10 раз снижает лосс с 3,6 до примерно 2,8 (лектор округляет на слух); повторное увеличение ещё в 10 раз снизит лосс на сопоставимую величину, но при приближении к нулю кривая выходит на асимптоту, и для полного приближения к нулю потребовалось бы увеличивать данные ещё в сотни раз — задача уже нетривиальная. Аналогичная логика применима к масштабированию по компьюту и по числу параметров.

Вне слайдов

Проверка примера в песочнице: по формуле со слайда 32, $L(D) \propto D^{-0{,}095}$, увеличение $D$ в 10 раз даёт множитель $10^{-0{,}095}\approx 0{,}8035$; из $L_0=3{,}6$ получаем $L_1 \approx 3{,}6 \times 0{,}8035 \approx 2{,}89$ — лектор на слух округлил это до 2,8, расхождение укладывается в обычную для устного изложения точность.

На пальцах

Похоже на разбавление краски водой: первое удвоение объёма воды сильно осветляет цвет, следующее удвоение — тоже осветляет, но уже не так сильно, потому что краски и так осталось немного; полностью «обесцветить» так и не получится за конечное число разбавлений.

По сути, это теоретическое обоснование того, что большие языковые модели вообще осуществимы: когда статья вышла (по словам лектора, в 2018–2019 годах), решение обучать модель вроде GPT-3 со 175 миллиардами параметров при тогдашней дороговизне обучения лектор сравнивает со ставкой в казино «на зелёное». Уточнение. Работа «Scaling Laws for Neural Language Models» (Kaplan, McCandlish, Henighan и др., OpenAI, январь 2020) обычно цитируется по первому автору — Джареду Каплану; Алек Рэдфорд действительно указан в списке соавторов, но не как первый/ведущий автор. Формулы на слайде по структуре ($L\propto X^{-\text{показатель}}$) соответствуют степенным законам именно из этой статьи.

На пальцах

«Ставка на зелёное» — образное сравнение лектора: до появления количественного обоснования вложение огромных денег в обучение одной гигантской модели действительно было скорее верой в интуицию, чем расчётом; после законов масштабирования это стало (хотя бы приблизительно) считаемым наперёд решением.

5.4. Совместный закон масштабирования (сл. 33)

Эмпирически можно получить совместный закон масштабирования для данных и параметров при фиксированном компьюте (сл. 33):

$$\begin{cases} \mathcal{L}(N,D) = c + AN^{-\alpha} + BD^{-\beta}, \\ C(N,D) = C_0 ND \end{cases}$$

Из записи лекции [57:44–58:49]

Раньше были получены отдельные законы масштабирования для каждого из трёх аргументов (компьют, размер датасета, число параметров) по отдельности; эмпирически их можно объединить в один совместный закон для данных и параметров при фиксированном компьюте.

На пальцах

Слагаемые $AN^{-\alpha}$ и $BD^{-\beta}$ можно читать как «штраф за недостаток параметров» и «штраф за недостаток данных» соответственно: каждый убывает по мере роста своего аргумента, а $c$ — то, ниже чего лосс в принципе не опустить (об этом — в 5.5–5.6).

5.5. Bias-variance trade-off через закон масштабирования (сл. 34)

Через совместный закон масштабирования можно продолжить идею bias-variance trade-off: увеличение количества параметров снижает смещение (bias), увеличение количества данных снижает разброс (variance) (сл. 34):

$$\operatorname{bias} \sim N^{-\alpha}, \qquad \operatorname{variance} \sim D^{-\beta}, \qquad R(N,D) = \frac{\operatorname{variance}}{\operatorname{bias}} \sim N^{\alpha}D^{-\beta}$$

Из записи лекции [58:50–59:57]

Это не строго математически однозначный, но логически обоснованный переход от того же bias-variance разложения, которое разбиралось на первой лекции курса. По отношению $R$ можно судить о недо- и переобучении: при $R \ll 1$ — недообучение, при $R \gg 1$ (лектор проговаривает это как «много меньше единицы» для обратного отношения) — переобучение; хотелось бы прикинуть баланс заранее, до того как потратить значительные средства на обучение по-настоящему большой модели.

На пальцах

Если модель слишком маленькая относительно объёма данных — она физически не может выучить все закономерности (высокое смещение, недообучение). Если данных мало относительно размера модели — модель начинает запоминать шум конкретной выборки вместо общих закономерностей (высокий разброс, переобучение).

5.6. Закон Шиншиллы: вывод (сл. 35)

Лектор прямо отмечает, что «закон Шиншиллы сейчас не очень верен» и сильно зависит от архитектуры: для смеси экспертов (Mixture of Experts, тема следующей лекции) он в исходном виде уже не работает — а сама идея MoE как раз и вырастает из желания наращивать число параметров, не увеличивая пропорционально данные и компьют.

Из конспектов лектора (§3.3)

Обучив Chinchilla 70B при $D=20N$ и бюджете вычислений на уровне Gopher, авторы получили модель, заметно превосходящую перечисленные.

Вне слайдов

Уточнение. Значение $L_0=1{,}82$ из конспектов лектора ближе не к числу, приведённому в самой статье Hoffmann et al. (2022) ($E\approx1{,}69$ в опубликованном тексте), а к переоценённому значению ($E\approx1{,}82$), которое получила независимая попытка воспроизведения расчётов той же статьи (Besiroglu и др., 2024) — при этом $A=406{,}4$ и $B=410{,}7$, действительно взятые из оригинальной статьи, совпадают в обоих источниках. Для порядковых прикидок в разделе 4.5 это различие не критично.

На пальцах

«Не железное правило» в устах лектора значит примерно следующее: 20 токенов на параметр — хорошая отправная точка для прикидки «на глаз», но перед тем как тратить настоящий бюджет на конкретную архитектуру, соотношение стоит перепроверить экспериментально именно на ней, а не считать константой на все случаи жизни.

Раздел 3. Вопросы для подготовки к защите лабораторных (теория)

Формат ответа: сначала тезис (1–2 предложения), затем аргументация от лица студента, со ссылками на слайды и таймкоды для самопроверки. Вопрос 7 воспроизводит реальный диалог студента и лектора из записи.

1. Зачем понадобилось обучаемое разреженное внимание, если шаблонное разреженное внимание уже решает проблему квадратичной сложности полного внимания?

Тезис: шаблонное разрежение задаёт связи заранее и одинаково для всех входов, а разным токенам на практике нужны разные наборы связей.

Аргументация: если шаблон разрежения не зависит от входных данных, модель не может отбросить именно ненужные в данном конкретном контексте токены — она вынуждена следовать фиксированному паттерну, который для одного входа окажется удачным, а для другого нет. Обучаемое разреженное внимание (DSA, сл. 3–4) поручает сам выбор связей индексатору, обучаемому по данным (00:03–01:15).

2. Почему индексатор Lightning Indexer обучается в два отдельных этапа, а не сразу с top-k отбором?

Тезис: на первом этапе индексатор учится приближать распределение весов ещё плотного (то есть полного) внимания, и только когда это распределение выучено, включается отбор top-k.

Аргументация: если сразу разморозить внимание и включить top-k-фильтрацию, у индексатора не будет надёжного «эталона», который он приближает, — распределение весов внимания и без того будет меняться в процессе обучения непредсказуемо. Двухэтапная схема (сл. 5–6, 02:16–04:32) сперва стабилизирует индексатор на плотном внимании, а затем адаптирует его уже к отфильтрованному множеству позиций.

3. В сжатом внимании матрицу $S$ можно было бы считать из уже сжатого латентного $C$ — по размерности выйдет то же самое. Почему её всё равно считают из исходного входа $H$?

Тезис: вычисление из $H$ позволяет считать пары матриц $S$ и $C$ параллельно в одном GPU-ядре, а не последовательно.

Аргументация: если бы $S$ строилась из $C$, для её получения сначала пришлось бы дождаться вычисления $C$ — то есть вычисления шли бы строго последовательно. При вычислении обеих матриц напрямую из $H$ (сл. 12, 12:13–13:22) они не зависят друг от друга и могут быть слиты в одно ядро, что на GPU обычно эффективнее двух отдельных запусков, особенно для операций такого рода.

4. В чём принципиальная разница между CSA и HCA, если оба используют один и тот же набор механизмов (сжатие + разреженное внимание + группировка проекций)?

Тезис: единственное существенное отличие — коэффициент сжатия по оси последовательности: 4:1 у CSA против 128:1 у HCA, из-за чего HCA вообще не нуждается в разреженном отборе.

Аргументация: CSA (сл. 16, 18:16–19:28) схлопывает четыре токена в один вектор и после этого всё ещё применяет top-k отбор поверх сжатой последовательности. HCA схлопывает 128 токенов в один — сжатая последовательность становится настолько короткой, что дальнейшая фильтрация уже не нужна, и именно это позволяет доводить контекст до миллиона токенов.

5. BERT называют моделью с «маскированной языковой моделью» (MLM) — но разве это не то же самое маскирование, что и Masked Multi-Head Attention в GPT?

Тезис: нет — это два разных уровня маскирования, и Masked Multi-Head Attention для двунаправленного BERT в принципе неприменим.

Аргументация: Masked Multi-Head Attention в декодировщике (GPT) не даёт токену «видеть» позиции справа от себя — это маскирование на уровне архитектуры внимания. MLM в BERT — маскирование на уровне входных данных: часть токенов заменяется на [MASK] (или на случайный/неизменный токен, правило 80/10/10) ещё до подачи в модель, а внимание при этом остаётся полным, двунаправленным (сл. 19–20, конспекты лектора §1.1.3) — иначе двунаправленный контекст, ради которого и строился BERT, был бы недостижим.

6. Зачем в MLM нужно правило 80% / 10% / 10% (замена на [MASK] / случайный токен / без изменений), если можно было бы просто всегда подставлять [MASK]?

Тезис: если бы маскировался только специальный токен [MASK], модель могла бы «опираться на сам факт маски», а не на реальный контекст — а на инференсе токена [MASK] не существует вовсе.

Аргументация: постоянное присутствие 10% случайных токенов и 10% немаскированных вынуждает модель предсказывать «что здесь должно быть» по контексту в любом случае, а не только тогда, когда видит явный маркер пропуска (конспекты лектора §1.1.3). Это снижает разрыв между тем, что модель видит при предобучении, и тем, что она увидит на реальных данных при использовании.

7. Как в CLIP определяется, что пара «изображение — текст» совпадает, если для любого набора изображений в батче диагональ строится одинаково?

Тезис: «совпадение» — это не свойство самой картинки, а совпадение индексов внутри конкретного батча: i-й текст обучающего примера сопоставлен с i-м изображением того же примера.

Аргументация: этот вопрос буквально прозвучал на лекции от студента, потребовавшего уточнения дважды (34:09, 34:36, 35:29). Лектор пояснил: для любого батча диагональ матрицы сходств задаётся индексами пар, а не каким-то заранее известным свойством картинки — «доворачиваются» (36:48, 37:22) именно параметры кодировщика изображений так, чтобы вектор конкретной картинки лёг ближе к вектору её собственного описания, а не к описанию любой другой картинки батча.

8. Почему в больших языковых моделях для подключения новых модальностей используется в основном Early Fusion, а не Deep Fusion?

Тезис: Early Fusion экономичнее и проще интегрируется в уже предобученную текстовую модель, тогда как Deep Fusion требует более глубокой переработки и обычно применяется там, где генерация изначально устроена иначе — например, в диффузионных моделях.

Аргументация: при Early Fusion (сл. 26, 41:23–48:37) токены разных модальностей просто приводятся к общему пространству токенов текста ещё до подачи в основную модель, и обучается по сути только адаптер при заморозке остального. Deep Fusion предполагает вмешательство во внутренние слои основной модели (например, через cross-attention), что для LLM используется реже и чаще встречается в моделях генерации изображений вроде Stable Diffusion.

9. Если уже есть обученный CLIP, зачем для медицинских изображений использовать ещё и специализированный кодировщик, а не дообучить сам CLIP?

Тезис: базовый CLIP обучен на данных общего домена и плохо обобщается на снимки, устроенные принципиально иначе (например, рентген), поэтому специализированный кодировщик компенсирует эту ошибку, а не заменяет CLIP полностью.

Аргументация: подход Merge of Encoders (сл. 27, 48:38–49:39) не отказывается от CLIP, а объединяет его выход с выходом специализированного кодировщика — по необучаемому правилу (усреднение) или по обучаемому (гейтинг, а также, по конспектам лектора §2.6.4, pixel-shuffle, аддитивное и мультипликативное смешивание). Так модель получает и общую, и узкодоменную экспертизу одновременно, вместо того чтобы жертвовать одной ради другой.

10. Почему степенной закон масштабирования на графике «лосс — компьют/данные/параметры» выглядит как прямая линия, и почему лосс всё равно нельзя опустить до нуля, сколько бы данных ни добавляли?

Тезис: прямая линия на лог-лог шкале — это визуальный признак степенной зависимости $L\propto X^{-a}$; а предел снизу задаёт слагаемое $c$ (энтропия/несводимая ошибка данных), которое не зависит ни от $N$, ни от $D$, ни от $C$.

Аргументация: если прологарифмировать обе части $L=kX^{-a}$, получится линейное уравнение $\log L = \log k - a\log X$ — прямая с наклоном $-a$ (сл. 32, 55:19–57:43). В совместном законе (сл. 33) есть слагаемое $c$, которое масштабированием $N$ или $D$ не убрать: сколько текста ни возьми, для многих продолжений текста в принципе существует несколько правдоподобных вариантов, и вероятность 1.0 для «правильного» токена недостижима в принципе.

11. Почему закон Шиншиллы ($D=20N$) не работает «в исходном виде» для архитектуры Mixture of Experts?

Тезис: соотношение $D=20N$ найдено эмпирически для конкретной (GPT-подобной, плотной) архитектуры, и по словам лектора оно существенно зависит от архитектуры — MoE вводит принципиально другую связь между числом параметров и объёмом вычислений на токен.

Аргументация: MoE-модель может наращивать общее число параметров, почти не увеличивая компьют и данные на один шаг обучения (активна лишь часть экспертов на каждый токен) — а вывод $D=20N$ (сл. 36–37, 01:01:05–01:03:17) опирался именно на связь $C=C_0ND$ с одним и тем же $N$, отвечающим за все вычисления. Лектор явно анонсирует разбор MoE как тему следующей лекции.

4.5. Проверяемый расчёт: закон Шиншиллы для объёма данных ЛР2 (исполнено в песочнице без ошибок)

Курс не задаёт явно число параметров модели ЛР2, поэтому ниже — не рекомендация, а иллюстративный, легко пересчитываемый под любой реальный размер инструмент: сколько токенов «требует» модель заданного размера по правилу $D=20N$ (сл. 36) и как это соотносится с объёмом WikiText-103 (103 млн токенов), уже фигурирующего в пайплайне ЛР1.

"""
Раздел 4.5. Оценка объёма данных для ЛР2 по закону Шиншиллы (D = 20N).

В лекции 7 нет прямых указаний лектора к лабораторным (проверено полнотекстовым
поиском по транскрипту). Единственная проверяемая числовая связь с ЛР2 (обучение
GPT-like LM с нуля, курс МNNA) — прикинуть по D=20N, сколько токенов "стоило бы"
модели заданного размера, и сравнить с реальным объёмом WikiText-103 (103 млн
токенов, Merity et al. 2016 - используется в курсе как источник данных).
"""
import numpy as np

C0 = 6            # C(N, D) = C0 * N * D, C0=6 -- со слайдов/конспектов лектора (§5.4, §5.7)
WIKITEXT103_TOKENS = 103_000_000

def chinchilla_tokens(n_params: float) -> float:
    """D = 20N -- закон Шиншиллы (сл. 36-37); не 'железное правило', см. §5.7."""
    return 20 * n_params

def flops(n_params: float, n_tokens: float) -> float:
    return C0 * n_params * n_tokens

print(f"{'N, параметров':>15} | {'D=20N, токенов':>16} | {'C=6ND, FLOPs':>12} | {'D / WikiText-103':>16}")
for n in (1e7, 2.5e7, 5e7, 1.24e8):
    d = chinchilla_tokens(n)
    c = flops(n, d)
    ratio_wt103 = d / WIKITEXT103_TOKENS
    print(f"{n:15,.0f} | {d:16,.0f} | {c:12.2e} | {ratio_wt103:15.2f}x")

print("\nДля сравнения (конспекты лектора, §3.3): D/N GPT-3=1.7, Gopher=1.1, Jurassic-1=1.7, Megatron=0.5, Chinchilla=20.0")

Результат прогона: для $N=10$ млн параметров $D=20N=2\times10^8$ токенов ($\approx$ 1,94$\times$ WikiText-103); для $N=25$ млн — $5\times10^8$ токенов ($\approx$4,85$\times$); для $N=50$ млн — $1\times10^9$ токенов ($\approx$9,71$\times$); для $N=124$ млн (масштаб GPT-1/GPT-2-small) — $2{,}48\times10^9$ токенов ($\approx$24,08$\times$ WikiText-103). Для моделей меньше $\sim$50 млн параметров одного WikiText-103 может не хватить до «шиншилла-оптимального» объёма данных даже с однократным проходом — стоит держать это в уме при выборе числа эпох или при добавлении Common Crawl, если ЛР2 предполагает модель такого масштаба.
