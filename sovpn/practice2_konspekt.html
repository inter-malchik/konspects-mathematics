§1. Данные для обучения языковой модели

1.1. От чего отказываемся: почему не seq2seq/машинный перевод

Из записи семинара [49:14–51:44]

Начали с установки библиотек: datasets (для загрузки датасетов с Hugging Face), transformers, а также заново lightning, ClearML и TensorBoard («слетел kernel» — пришлось переустанавливать). Разделение труда по лабораторным: в ЛР1 — токенизация и очистка данных, подготовка к обучению; в ЛР2 — подготовка модели и инфраструктуры, обучение модели на этой инфраструктуре. Для обучения языковых моделей нужны данные, и чем больше модель, тем больше данных требуется (о пропорциях — позже, при законах масштабирования). На лекции рассматривали обучение трансформера для машинного перевода — но такая задача требует больших корпусов размеченных (parallel) текстов, а это дорого и тяжело: некачественная разметка повышает энтропию данных и поднимает минимально достижимый порог функции потерь.

1.2. Self-supervised: предсказание следующего токена

Из записи семинара [51:44–52:34]

Поэтому в семинаре идут другим путём: обучают модель предсказывать следующий токен текстовой последовательности — задача авторегрессионной генерации текста. Для неё из полной архитектуры трансформера нужна только часть с декодировщиком, причём даже без блока перекрёстного внимания (кодировщик вообще не нужен). Главное преимущество: разметка данных не требуется — такое обучение называется self-supervised learning. Большие языковые модели обучаются на огромных корпусах текста, вплоть до «всего интернета» — веб-страницы, книги, статьи, код с GitHub (публичный и не очень), документация, чаты, форумы.

На пальцах

Разметка для перевода — это пары «предложение на языке A → то же предложение на языке B», которые нужно готовить вручную. А для предсказания следующего слова разметку не нужно готовить отдельно: сам текст уже и вход, и ответ — только сдвинутый на одну позицию.

1.3. Учебный датасет WikiText: структура и проблемы

Из записи семинара [52:34–55:01]

В качестве учебного датасета взяли WikiText — уже разбитый на train/validation/test. Среди первых объектов — фрагмент об игре Valkyria Chronicles (JRPG) и статья из Википедии про Гражданскую войну в США. В этих текстах сразу видны проблемы: пустые строки (иногда по две подряд), заголовки разделов, вкрапления текста на других языках (в примере — японский). Текст «грязный, неочищенный», и если модель должна быть только англоязычной (мультиязычные модели требуют существенно больше параметров), его нужно чистить: убирать пустые строки, короткие обрывки (особенно обрывающиеся на полуслове), заголовки (сами по себе бесполезны, а разметка заголовков может и навредить), фрагменты на незнакомых языках и дубликаты подстрок между текстами.

1.4. Очистка и потоковая загрузка больших датасетов

Из записи семинара [55:01–57:16]

Полная очистка — задача тяжёлая, неудобная и на чистом Python медленная, поэтому в семинаре ограничились удалением пустых строк (оказалось, что пустой была целая треть строк). WikiText сам по себе небольшой — около 36–37 тысяч строк в train, но для обучения больших языковых моделей используют датасеты, которые весят терабайты и петабайты — целиком их не загрузить, поэтому используется потоковая загрузка (streaming=True при вызове загрузки датасета). В таком режиме получают IterableDataset — не список объектов, а итератор, по которому нужно проходиться, а не индексировать. Пример огромного, неочищенного архива — Common Crawl (архив веб-страниц): его нужно чистить не только синтаксически, но и семантически — данные бывают не просто «грязные», а вредные (not safe for work контент), и обучать на них ассистента нельзя. В рамках семинара ограничились только токенизацией и только WikiText.

На пальцах

Обычный Dataset — это книга, которую можно открыть на любой странице; IterableDataset в режиме streaming — это лента конвейера: можно смотреть только по одному объекту за раз, по порядку, не заглядывая вперёд и не возвращаясь назад.

§2. Токенизация

2.1. Готовые токенизаторы вместо самописных

Из записи семинара [57:16–59:25]

Текстовые данные подготовлены — но это всё ещё текст, а не тензоры; нужен токенизатор. В библиотеке transformers базовый класс, от которого наследуются все токенизаторы, называется AutoTokenizer — он сам подбирает нужный токенизатор по названию модели или репозиторию, где он лежит. Писать токенизатор с нуля для типовых задач гораздо хуже, чем взять готовый: BPE-токенизаторы применяют сотни тысяч merge-правил, и если делать это циклами на чистом Python — будет очень медленно; поэтому у готовых токенизаторов сама логика реализована бэкенд-кодом на C или Rust.

2.2. Токенизатор GPT-2 на практике: pad-токен, кодирование/декодирование

Из записи семинара [59:25–1:00:41]

У токенизатора GPT-2 нет отдельного pad-токена — в семинаре его заменили на токен конца последовательности (eos_token). Пример прогнали на посте Андрея Карпатого про «вайб-кодинг»: текст токенизируется в тензор индексов, и этот тензор можно декодировать обратно без каких-либо потерь. У токенизатора есть свои параметры и специальные токены; на выходе — некоторый «энкод-список» (словарь), из которого можно достать индексы.

2.3. Attention mask и специальные токены

Из записи семинара [1:00:41–1:01:47]

Один из ключей выходного словаря токенизатора — input_ids (индексы токенов); также хранится информация о специальных токенах (pad, eos, bos — у каждого свой ID; в данном случае pad и eos совпадают) и об attention_mask, который применяется к последовательности тензоров. В конце последовательности после паддинга видно много повторяющихся pad-токенов — они нужны только для того, чтобы дополнить последовательность до необходимой длины.

Указание к ЛР (1:01:47). Паддинг-токены бесполезны и даже вредны: не хотелось бы, чтобы они участвовали в механизме внимания — сами по себе они не несут информации, зато способны «размазывать» по себе агрегированную полезную информацию и ничего не отдавать взамен; кроме того, вычислять что-то для них — трата вычислительных ресурсов. Поэтому создают attention_mask, по которой в дальнейшем считаются и внимание, и другие модули (FFN, LayerNorm) — то есть паддинг-позиции исключаются из соответствующих вычислений.

2.4. Размер словаря GPT-2

Из записи семинара [1:01:47–1:02:50]

Размер словаря для GPT-2 лектор называет «50 тысяч». Текст снова кодируется и без потерь раскодируется обратно; так токенизируется весь датасет.

Вне слайдов

Точный размер словаря GPT-2 (общеизвестный факт, документация Hugging Face / OpenAI) — 50 257 токенов; названные лектором «50 тысяч» — округление, а не расхождение.

На пальцах

«Энкод-список» токенизатора — это как квитанция из химчистки: одна и та же вещь (текст) превращается в номер (индексы), по которому её потом можно без потерь забрать обратно (декодировать).

2.5. Как устроены токенизаторы «под капотом» — см. конспект Лекции 2

В семинаре готовый токенизатор GPT-2 только используется (§2.1–2.4), но не объясняется, как он устроен внутри. §3. Подготовка батчей фиксированной длины

3.1. Три способа выравнивания длины

Из записи семинара [1:02:50–1:03:58]

Чтобы все последовательности в датасете были одинаковой длины, лектор называет способ, а затем поправляется, что их на самом деле три: (1) обрезка всех последовательностей до заданного размера (например, до размера минимальной по длине последовательности); (2) паддинг коротких последовательностей pad-токенами до максимальной длины; (2.5) их комбинация — задать значение максимальной длины, обрезать всё, что длиннее, и падить всё, что короче.

3.2. Альтернатива — склейка последовательностей и её риски

Из записи семинара [1:03:58–1:04:50]

Третий способ — склеивать короткие последовательности в одну и вешать на них специальные attention-маски, показывающие, где заканчивается один текст и начинается другой. В семинаре сделали похожий, но упрощённый вариант — без attention-масок между склеенными кусками, просто цельным текстом; лектор прямо оговаривает, что это «не самое лучшее решение», поскольку так можно склеить два не связанных друг с другом текста и сломать грамматику и смысл получившегося куска.

На пальцах

Склейка без масок — это как вырезать два разных абзаца из разных книг и склеить их встык в один без знака абзаца: читать можно, но конец одной мысли незаметно перетекает в начало совсем другой.

4.5. Что хранит чекпоинт и как им пользоваться дальше

Из записи семинара [1:10:20–1:12:27]

Чекпоинты можно сохранять в двух категориях по метрикам: (а) лучший по одной выбранной основной метрике, либо (б) лучшие отдельно по каждой метрике; плюс отдельно можно сохранять (в) последний чекпоинт. Чекпоинт хранит: состояние модели, состояние оптимизатора, номер эпохи, текущий шаг обучения и состояние callback'ов — то есть всё необходимое, чтобы продолжить обучение именно с этой точки (передав чекпоинт в Trainer.fit) либо загрузить из него модель отдельно, например для инференса.

Лектор подтвердил, что постарается выложить запись лекции и семинара, скорее всего в Telegram-группу, когда доберётся до дома с нормальным интернетом; про выкладку на VK Видео или YouTube пока не решил.

На пальцах

Чекпоинт — это не просто фотография весов модели, а полный «слепок памяти» тренировки: если сохранить только веса, а оптимизатор запустить заново, обучение продолжится рывком, как будто заново разгоняется с нуля; сохранив ещё и состояние оптимизатора с номером эпохи, обучение возобновляется плавно, как будто его и не прерывали.

Раздел 3. Вопросы для подготовки к защите лабораторных (теория)

Формат ответа: сначала тезис (1–2 предложения), затем аргументация от лица студента, со ссылками на таймкоды записи для самопроверки.

1. Почему для обучения языковой модели предсказанию следующего токена не нужна разметка данных?

Тезис: сам исходный текст одновременно служит и входом, и целевым значением — целью на каждой позиции является следующий токен того же текста.

Аргументация: в отличие от машинного перевода, где нужны пары «текст на языке A — текст на языке B», подготовленные вручную, здесь достаточно взять текстовый корпус и сдвинуть его на один токен, чтобы получить целевую последовательность (49:14–51:44). Это и называется self-supervised learning — учиться без внешней разметки, эксплуатируя саму структуру данных.

2. Зачем нужна потоковая загрузка (streaming=True) при работе с большими датасетами вроде Common Crawl?

Тезис: датасеты для больших языковых моделей весят терабайты и петабайты, и их физически невозможно загрузить на диск целиком перед началом работы.

Аргументация: при streaming=True получают IterableDataset — данные подгружаются по одному объекту («шарду») в момент обращения к ним, а не заранее все сразу; за это приходится расплачиваться тем, что по такому датасету можно только последовательно проходиться итератором, а не обращаться по индексу как к списку (55:01–56:09).

3. Почему нельзя просто взять «сырой» текст из интернета без очистки для обучения модели?

Тезис: неочищенный текст содержит структурный мусор (пустые строки, заголовки, обрывки, чужой язык, дубликаты) и может содержать вредный контент — оба типа проблем портят обучение по-разному.

Аргументация: структурный мусор напрямую повышает энтропию данных и минимально достижимое значение функции потерь, поскольку часть «сигнала», который должна выучить модель, на самом деле случайный шум разметки (52:34–55:01); вредный (not safe for work) контент — отдельная, смысловая проблема, которую одними синтаксическими правилами не отловить, нужна ещё и семантическая фильтрация (56:09–57:16).

4. Зачем в токенизаторе GPT-2 используют eos_token в качестве pad-токена?

Тезис: у токенизатора GPT-2 нет отдельного, специально выделенного pad-токена, поэтому вместо него переиспользуют уже существующий токен конца последовательности.

Аргументация: пока паддинг-позиции корректно исключены из вычислений через attention_mask, не важно, какое конкретно значение стоит в этих позициях — главное, что модель никогда не должна использовать его как содержательный сигнал (59:25–1:00:41).

5. Зачем нужен attention_mask, если пад-токены и так просто «пустое место» в конце последовательности?

Тезис: без явной маски паддинг-токены участвовали бы в вычислениях механизма внимания (и FFN, LayerNorm) наравне с настоящими, что вредно и бесполезно.

Аргументация: паддинг-токены не несут информации, зато способны «размазывать» по себе агрегированную информацию от настоящих токенов и ничего не отдавать взамен, а вычисления для них — чистая трата ресурсов; attention_mask явно исключает эти позиции из соответствующих вычислений (1:00:41–1:01:47).

6. В чём риск склейки коротких последовательностей в одну без масок — по сравнению с обрезкой или паддингом?

Тезис: при склейке без масок можно случайно соединить встык два никак не связанных друг с другом текста, что портит грамматику и смысл получившегося куска.

Аргументация: правильный вариант такого подхода предполагает специальные attention-маски, показывающие границы между склеенными кусками; демонстрация в семинаре сознательно упрощена и такие маски не использует — сам лектор называет это «не самым лучшим решением» (1:03:58–1:04:50).

7. Зачем в лабораторной работе обязательно использовать ClearML (или аналог), если модель и так обучается без него?

Тезис: без инструмента вроде ClearML/TensorBoard нет возможности отслеживать метрики, графики и аппаратное профилирование по ходу обучения, до того как оно завершится.

Аргументация: это отдельная задача от собственно обучения модели — инфраструктура наблюдаемости; лектор явно указывает, что в лабораторной работе использование ClearML обязательно (1:07:09–1:07:21).

8. Что именно сохраняет чекпоинт и почему этого достаточно, чтобы продолжить обучение с прерванного места?

Тезис: чекпоинт хранит не только веса модели, но и состояние оптимизатора, номер эпохи, шаг обучения и состояние callback'ов — то есть весь контекст, необходимый для продолжения именно с этой точки, а не для старта заново.

Аргументация: если сохранить только веса модели, при возобновлении обучения оптимизатор (например, с адаптивными моментами) начал бы «с нуля», что не эквивалентно бесшовному продолжению; поэтому чекпоинт передают целиком в Trainer.fit, а не восстанавливают модель вручную по частям (1:10:20–1:11:28).

9. Почему при вычислении функции потерь важно исключить паддинг-позиции (например, меткой -100), а не оставить их как есть?

Тезис: если паддинг-позиции остаются в целевой последовательности с обычными значениями, модель будет учиться предсказывать сам pad-токен на этих позициях, что бессмысленно и портит обучение.

Аргументация: паддинг — техническое дополнение, а не часть реального текста; логика та же, что и с attention_mask у входа (вопрос 5) — паддинг-позиции нужно исключать и на выходе, из функции потерь, а не только из внимания.

10. Почему в семинаре не пишут собственный BPE-токенизатор с нуля, а берут готовый из transformers?

Тезис: готовые токенизаторы реализуют применение сотен тысяч merge-правил на быстром бэкенде (C/Rust), тогда как на чистом Python то же самое было бы медленным.

Аргументация: AutoTokenizer сам подбирает нужную реализацию по имени модели или репозитория; переиспользование готового, проверенного инструмента избавляет и от повторной разработки, и от проблем с производительностью (57:16–59:25).

11. Почему BPE считается компромиссом между посимвольной токенизацией и токенизацией по словам, а не отдельным независимым методом?

Тезис: BPE наследует происхождение от посимвольного разбиения (стартовый словарь — это алфавит), но в процессе обучения «выращивает» из него частотные сочетания символов, приближаясь по смысловой ценности токенов к словам — не доходя, впрочем, до взрыва словаря, характерного для чистой токенизации по словам.

Аргументация: посимвольная токенизация даёт маленький словарь ценой длинных последовательностей и низкой смысловой ценности каждого токена; токенизация по словам — обратный компромисс (короткие последовательности, но огромный словарь из-за словоформ и редких слов). BPE стартует со словаря символов и итеративно объединяет самые частые соседние пары в корпусе, останавливаясь при достижении заданного размера словаря, — получается словарь заданного размера, чьи элементы часто совпадают с морфемами (приставками, корнями, суффиксами), то есть с осмысленными частями слов, а не с ними целиком и не с отдельными буквами (подробный разбор — конспект Лекции 2, §1.2–1.6).

токенизация с паддингом и attention mask + мини-GPT-2 конфиг + инфраструктура
обучения на PyTorch Lightning (ModelCheckpoint, LearningRateMonitor).

Реальный токенизатор GPT-2 (transformers.AutoTokenizer.from_pretrained("gpt2"))
в этой песочнице недоступен: huggingface.co не входит в разрешённые сетевые домены.
Поэтому механика паддинга/attention mask (запись, 1:00:41-1:01:47) показана на
маленьком самодельном словарном токенизаторе — это НЕ настоящий BPE-словарь GPT-2,
только демонстрация той же логики на реальном исполняемом коде. Конфигурация модели
(transformers.GPT2Config/GPT2LMHeadModel) и вся инфраструктура Lightning — настоящие,
библиотечные, сети не требуют (в самом семинаре модель тоже строилась "с нуля" по
конфигу, а не подгружалась предобученной).

Версии: torch 2.14.0+cu130, transformers 5.17.0, lightning 2.6.6 (проверено в песочнице).
"""
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader
from transformers import GPT2Config, GPT2LMHeadModel
import lightning.pytorch as pl
from lightning.pytorch.callbacks import ModelCheckpoint, LearningRateMonitor

torch.manual_seed(0)

# ---------------------------------------------------------------------------
# 1) Игрушечный словарный токенизатор — демонстрирует именно то, о чём говорится
#    в записи: свой pad-токен отсутствует -> берём eos как pad (сл./запись 59:25),
#    attention_mask отделяет реальные токены от паддинга (запись, 1:00:41-1:01:47).
# ---------------------------------------------------------------------------
SPECIAL = ["<pad>", "<bos>", "<eos>", "<unk>"]

class ToyWordTokenizer:
    """Мини-токенизатор по словам — только для демонстрации паддинга/маски,
    НЕ настоящий BPE-словарь GPT-2 (см. docstring модуля)."""
    def __init__(self, corpus):
        vocab = list(SPECIAL)
        for line in corpus:
            for w in line.lower().split():
                if w not in vocab:
                    vocab.append(w)
        self.stoi = {w: i for i, w in enumerate(vocab)}
        self.itos = {i: w for w, i in self.stoi.items()}
        self.pad_token_id = self.stoi["<pad>"]
        self.eos_token_id = self.stoi["<eos>"]
        # как в записи: отдельного pad-токена у GPT-2 нет -> pad = eos
        self.pad_token_id = self.eos_token_id
        self.vocab_size = len(vocab)

    def encode(self, text):
        return [self.stoi.get(w, self.stoi["<unk>"]) for w in text.lower().split()] + [self.eos_token_id]

    def decode(self, ids):
        return " ".join(self.itos[i] for i in ids if i != self.pad_token_id)

    def pad_batch(self, seqs, max_len=None):
        max_len = max_len or max(len(s) for s in seqs)
        input_ids, attn = [], []
        for s in seqs:
            s = s[:max_len]
            pad_n = max_len - len(s)
            input_ids.append(s + [self.pad_token_id] * pad_n)
            attn.append([1] * len(s) + [0] * pad_n)
        return torch.tensor(input_ids), torch.tensor(attn)


CORPUS = [
    "архитектура трансформер решает задачу авторегрессионной генерации текста",
    "модель предсказывает следующий токен по предыдущим токенам",
    "паддинг токены не несут информации и должны быть замаскированы",
]

tok = ToyWordTokenizer(CORPUS)
ids = [tok.encode(line) for line in CORPUS]
input_ids, attention_mask = tok.pad_batch(ids)

# labels = input_ids, но паддинг помечаем -100, чтобы он не входил в кросс-энтропию
# (частая ловушка: без этого loss считается и по бесполезным pad-позициям)
labels = input_ids.clone()
labels[attention_mask == 0] = -100


# ---------------------------------------------------------------------------
# 2) Мини-GPT-2 по конфигу (как в семинаре: "конфиг с уменьшенными параметрами",
#    а не предобученные веса) + обёртка LightningModule.
# ---------------------------------------------------------------------------
class TinyGPT2LM(pl.LightningModule):
    def __init__(self, vocab_size, pad_token_id):
        super().__init__()
        cfg = GPT2Config(
            vocab_size=vocab_size, n_positions=32, n_embd=32, n_layer=2, n_head=2,
            bos_token_id=pad_token_id, eos_token_id=pad_token_id,
        )
        self.model = GPT2LMHeadModel(cfg)

    def forward(self, input_ids, attention_mask, labels=None):
        return self.model(input_ids=input_ids, attention_mask=attention_mask, labels=labels)

    def training_step(self, batch, batch_idx):
        input_ids, attention_mask, labels = batch
        out = self(input_ids, attention_mask, labels)
        self.log("train_loss", out.loss, prog_bar=False)
        return out.loss

    def configure_optimizers(self):
        return torch.optim.AdamW(self.parameters(), lr=1e-3)


class ToyDataset(Dataset):
    def __init__(self, input_ids, attention_mask, labels):
        self.x, self.m, self.y = input_ids, attention_mask, labels

    def __len__(self):
        return len(self.x)

    def __getitem__(self, i):
        return self.x[i], self.m[i], self.y[i]


class ToyDataModule(pl.LightningDataModule):
    """Аналог LightningDataModule из семинара (запись, 1:04:50) — на игрушечных данных."""
    def __init__(self, input_ids, attention_mask, labels, batch_size=2):
        super().__init__()
        self.ds = ToyDataset(input_ids, attention_mask, labels)
        self.batch_size = batch_size

    def train_dataloader(self):
        return DataLoader(self.ds, batch_size=self.batch_size, shuffle=True)


if __name__ == "__main__":
    print(f"torch {torch.__version__} | transformers через GPT2Config/GPT2LMHeadModel | lightning {pl.__version__}")
    print(f"Игрушечный словарь: {tok.vocab_size} токенов; pad_token_id=eos_token_id={tok.pad_token_id}")
    print(f"input_ids:\n{input_ids}")
    print(f"attention_mask:\n{attention_mask}")
    print(f"labels (pad -> -100):\n{labels}\n")

    dm = ToyDataModule(input_ids, attention_mask, labels, batch_size=2)
    lm = TinyGPT2LM(vocab_size=tok.vocab_size, pad_token_id=tok.pad_token_id)
    n_params = sum(p.numel() for p in lm.parameters())
    print(f"Параметров в мини-модели: {n_params}")

    ckpt_dir = "/home/claude/work2/checkpoints"
    checkpoint_cb = ModelCheckpoint(dirpath=ckpt_dir, filename="ckpt-{epoch}", every_n_epochs=1,
                                     save_top_k=-1, save_last=True)
    lr_cb = LearningRateMonitor(logging_interval="epoch")

    trainer = pl.Trainer(max_epochs=3, callbacks=[checkpoint_cb, lr_cb], enable_progress_bar=False,
                          logger=pl.loggers.CSVLogger(save_dir="/home/claude/work2/logs", name="run"),
                          accelerator="cpu", enable_model_summary=False)
    trainer.fit(lm, datamodule=dm)

    import os
    saved = sorted(os.listdir(ckpt_dir))
    print(f"\nПоследний train_loss (эпоха {trainer.current_epoch}): {trainer.callback_metrics.get('train_loss')}")
    print(f"Сохранённые чекпоинты в {ckpt_dir}: {saved}")

    # Продолжение обучения с последнего чекпоинта (запись, 1:11:28)
    last_ckpt = os.path.join(ckpt_dir, "last.ckpt")
    trainer2 = pl.Trainer(max_epochs=4, callbacks=[ModelCheckpoint(dirpath=ckpt_dir, save_last=True)],

                           accelerator="cpu", enable_model_summary=False)
    trainer2.fit(lm, datamodule=dm, ckpt_path=last_ckpt)

class WikiTextDataModule(LightningDataModule):
    def __init__(
        self,
        tokenizer_name: str = "gpt2",
        block_size: int = 128,
        batch_size: int = 8,
        train_size: int = 2000,
        val_size: int = 300,
    ):
        super().__init__()
        self.tokenizer_name = tokenizer_name
        self.block_size = block_size
        self.batch_size = batch_size
        self.train_size = train_size
        self.val_size = val_size

    def prepare_data(self):
        load_dataset("wikitext", "wikitext-2-raw-v1")
        AutoTokenizer.from_pretrained(self.tokenizer_name)

    def setup(self, stage=None):
        self.tokenizer = AutoTokenizer.from_pretrained(self.tokenizer_name)
        self.tokenizer.pad_token = self.tokenizer.eos_token

        raw_dataset = load_dataset("wikitext", "wikitext-2-raw-v1")

        train_raw = raw_dataset["train"].filter(lambda example: len(example["text"].strip()) > 0)
        val_raw = raw_dataset["validation"].filter(lambda example: len(example["text"].strip()) > 0)

        train_raw = train_raw.select(range(min(self.train_size, len(train_raw))))
        val_raw = val_raw.select(range(min(self.val_size, len(val_raw))))

        def tokenize_batch(batch):
            return self.tokenizer(batch["text"])

        tokenized_train = train_raw.map(
            tokenize_batch,
            batched=True,
            remove_columns=train_raw.column_names,
        )

        tokenized_val = val_raw.map(
            tokenize_batch,
            batched=True,
            remove_columns=val_raw.column_names,
        )

        def group_texts(examples):
            all_input_ids = []

            for input_ids in examples["input_ids"]:
                all_input_ids.extend(input_ids)

            total_length = len(all_input_ids)
            total_length = (total_length // self.block_size) * self.block_size

            chunks = [
                all_input_ids[i : i + self.block_size]
                for i in range(0, total_length, self.block_size)
            ]

            return {
                "input_ids": chunks,
                "labels": [chunk.copy() for chunk in chunks],
            }

        self.train_ds = tokenized_train.map(
            group_texts,
            batched=True,
            remove_columns=tokenized_train.column_names,
        )
        self.val_ds = tokenized_val.map(
            group_texts,
            batched=True,
            remove_columns=tokenized_val.column_names,
        )

        self.train_ds.set_format(type="torch")
        self.val_ds.set_format(type="torch")

    def train_dataloader(self):
        return DataLoader(
            self.train_ds,
            batch_size=self.batch_size,
            shuffle=True,
            collate_fn=default_data_collator,
        )

    def val_dataloader(self):
        return DataLoader(
            self.val_ds,
            batch_size=self.batch_size,
            shuffle=False,
            collate_fn=default_data_collator,
        )

class TinyLM(LightningModule):
    def __init__(
        self,
        vocab_size: int,
        block_size: int = 128,
        n_layer: int = 2,
        n_head: int = 2,
        n_embd: int = 128,
        lr: float = 3e-4,
        pad_token_id: int | None = None,
        bos_token_id: int | None = None,
        eos_token_id: int | None = None,
    ):
        super().__init__()
        self.save_hyperparameters()

        config = GPT2Config(
            vocab_size=vocab_size,
            n_positions=block_size,
            n_ctx=block_size,
            n_layer=n_layer,
            n_head=n_head,
            n_embd=n_embd,
            pad_token_id=pad_token_id,
            bos_token_id=bos_token_id,
            eos_token_id=eos_token_id,
        )

        self.model = GPT2LMHeadModel(config)

    def forward(self, input_ids, labels=None):
        return self.model(
            input_ids=input_ids,
            labels=labels,
        )

    def configure_optimizers(self):
        return torch.optim.AdamW(self.parameters(), lr=self.hparams.lr)

    def training_step(self, batch, batch_idx):
        start_time = time.time()

        outputs = self(
            input_ids=batch["input_ids"],
            labels=batch["labels"],
        )

        loss = outputs.loss

        tokens = batch["input_ids"].numel()
        elapsed = max(time.time() - start_time, 1e-6)
        tokens_per_sec = tokens / elapsed

        self.log("train/loss", loss, on_step=True, on_epoch=False, prog_bar=True)
        self.log("speed/tokens_per_sec", tokens_per_sec, on_step=True, on_epoch=False, prog_bar=False)

        return loss

    def validation_step(self, batch, batch_idx):
        outputs = self(
            input_ids=batch["input_ids"],
            labels=batch["labels"],
        )

        loss = outputs.loss

        perplexity = torch.exp(torch.clamp(loss, max=20))

        self.log("val/loss", loss, on_step=False, on_epoch=True, prog_bar=True)
        self.log("val/perplexity", perplexity, on_step=False, on_epoch=True, prog_bar=True)
