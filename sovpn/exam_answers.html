Категория 1. Глубокое обучение

1.1. Полносвязные нейронные сети, функции активации. Обучение нейронной сети: градиентный спуск, функции потерь, алгоритм обратного распространения ошибки

Тезис. Полносвязный слой — аффинное отображение $y=xW+b$; композиция таких слоёв снова аффинна, поэтому между слоями нужна нелинейная дифференцируемая функция активации. Обучение — цикл «прямое распространение → функция потерь → обратное распространение градиента по цепному правилу → шаг градиентного спуска». Функция потерь выбирается по модели шума в данных (MSE — гауссов шум, MAE — лапласов, кросс-энтропия — классификация), а не из удобства производной.

Полносвязный слой. Каждый нейрон считает взвешенную сумму входов: $y_j=\sum_i x_iw_{ij}$, в матричной форме $y=xW$; на весь курс принята row-major запись — вектор есть строка, поэтому $xW$, а не $Wx$ (Л1 §1.2, сл. 7). Без смещения $b$ преобразование — гиперплоскость через начало координат, поэтому слой записывают как $y=xW+b$ (сл. 8). Полносвязная сеть, MLP и feedforward network — синонимы (письменный конспект лектора).

Зачем активация. Два линейных слоя схлопываются в один: $(xW_1+b_1)W_2+b_2=x\tilde W+\tilde b$, $\tilde W=W_1W_2$, $\tilde b=b_1W_2+b_2$ (сл. 11–12). Значит, глубина без нелинейности бессмысленна; если обернуть слои в $\phi$, получаем $y_2=\phi(\phi(xW_1+b_1)W_2+b_2)$, и вынести $\phi$ наружу нельзя (сл. 15). Два обязательных условия на $\phi$: нелинейность и дифференцируемость — второе понадобится при обратном распространении (сл. 13–15).

Функции активации (Л1 §2): сигмоида $\sigma(x)=\frac{1}{1+e^{-x}}$ — область значений $(0,1)$, в нуле $0{,}5$, быстро насыщается (производная при больших $|x|$ близка к нулю); $\tanh$ — центрирован в нуле, насыщается ещё быстрее; поэтому внутри сети их не ставят, сигмоида уместна только на выходе бинарной классификации. $\mathrm{ReLU}(x)=\max(0,x)$ — не насыщается, производная $1$ при $x\gt0$ и $0$ при $x\lt0$, в нуле не определена; она кусочно-линейна, но нелинейна: для $x=-1$, $y=2$ имеем $\mathrm{ReLU}(x+y)=1\ne\mathrm{ReLU}(x)+\mathrm{ReLU}(y)=2$. $\mathrm{LeakyReLU}(x)=\max(0{,}1x,\,x)$ убирает «мёртвую» нулевую ветвь; PReLU делает наклон обучаемым; ELU сглаживает излом ($\alpha(e^x-1)$ при $x\lt0$). $\mathrm{SiLU}_\beta(x)=x\,\sigma(\beta x)$: при $\beta\to\infty$ переходит в ReLU, при $\beta\to0$ — в прямую $x/2$. $\mathrm{Softmax}(x_i)=\frac{\exp(x_i)}{\sum_j\exp(x_j)}$ превращает логиты в распределение (сумма 1) — для классификации.

Шаг обучения (сл. 28): прямое распространение $x\to\hat y$, функция потерь $\mathcal L(\hat y,y)$, обратное распространение — градиент $\nabla_w\mathcal L$, шаг спуска $w_t=w_{t-1}-\lambda\nabla\mathcal L_{w_{t-1}}$ (сл. 65).

Функции потерь (Л1 §3). Регрессия: $\mathrm{MAE}=\frac1N\sum|y_i-\hat y_i|$, $\mathrm{MSE}=\frac1N\sum(y_i-\hat y_i)^2$. Выбор — через метод максимального правдоподобия: данные порождаются как $y=f(x)+\varepsilon$; при $\varepsilon\sim\mathcal N(0,\sigma^2)$ негативное лог-правдоподобие $$\mathrm{NLL}=-\sum_i\log p(y_i|x_i)=\frac N2\log(2\pi\sigma^2)+\frac{1}{2\sigma^2}\sum_i(y_i-f_w(x_i))^2,$$ первое слагаемое от $w$ не зависит, множитель $2\sigma^2$ не сдвигает точку минимума — остаётся MSE (сл. 36–41); при лапласовом шуме тем же путём получается MAE (сл. 42). Довод «у модуля нет производной в нуле» лектор отвергает: производную доопределяют через $\operatorname{sign}$, «для компьютеров разницы особой нет». Классификация: выход — вектор вероятностей, потеря — кросс-энтропия $H(p,q)=-\sum_ip_i\log q_i$, для one-hot разметки $=-\log q_c$ (сл. 45–48); она раскладывается как $H(p,q)=H(p)+D_{KL}\langle p\|q\rangle$, где $H(p)=-\sum p_i\log p_i$ — энтропия данных, не зависящая от модели, поэтому лосс нельзя опустить ниже $H(p)$ (сл. 49–51). $D_{KL}$ несимметрична, расстоянием не является; обучение минимизирует $D_{KL}\langle p\|q\rangle$ с истинной разметкой $p$ впереди.

Обратное распространение (Л1 §3.9–3.12, сл. 52–62). Градиент по весу $k$-го слоя — произведение по цепному правилу $$\frac{\partial L}{\partial w_k}=\frac{\partial L}{\partial y}\frac{\partial y}{\partial z_1}\frac{\partial z_1}{\partial z_2}\cdots\frac{\partial z_{k-1}}{\partial w_k},$$ на каждом слое нужны две производные — по параметру (для градиента) и по входу (чтобы продолжить цепочку); каждый множитель считается из предыдущего, поэтому распараллелить по слоям нельзя. Из той же цепочки — затухание/взрыв градиента: пример лектора $1\cdot0{,}8\cdot0{,}1\cdot0{,}2=0{,}016$ уже на четырёх слоях; насыщающиеся активации его усугубляют.

Где в конспектах: Л1 §1 (слои, схлопывание, условия на активацию), §2 (активации, Softmax, RNN), §3 (потери, MLE, кросс-энтропия, backprop); вопросы к защите 1–7, 11.

Уточняющие вопросы

«Два линейных слоя схлопываются — значит, глубокие сети невозможны?» Выкладка верна только для линейных слоёв; с активацией между ними композиция не сворачивается (сл. 12–15; вопрос лектор задавал аудитории, 04:20). «Куда девается $\sigma$ при выводе MSE?» Она зафиксирована и не оптимизируется: константа $\frac12\log 2\pi\sigma^2$ и множитель $2\sigma^2$ не влияют на $\operatorname{argmin}$. «Почему Softmax нельзя ставить перед nn.CrossEntropyLoss?» Softmax уже встроен в лосс; модель должна возвращать сырые логиты, второй Softmax ухудшит обучение (Практика 1, 02:31:30).

Ловушки

На сл. 50 KL описана как «расстояние от $p$ к $q$», а в записи (38:04) лектор поправился на «от $q$ к $p$» — словесное направление в литературе называют по-разному, отвечать надёжнее формулой $D_{KL}\langle p\|q\rangle=\sum_i p_i\log\frac{p_i}{q_i}$. 1.2. Оптимизаторы: GD, SGD, Momentum, RMSProp, Adam. Что такое состояние оптимизатора

Тезис. Аналитического решения нет (данные зашумлены, генеральная выборка недоступна), метод Ньютона неприменим (гессиан «параметры × параметры» не помещается в память), поэтому минимум ищут итеративно градиентным спуском по мини-батчам. Momentum накапливает антиградиент в «скорость», RMSProp адаптирует шаг по скользящему среднему квадратов градиента, Adam объединяет обе идеи. Состояние оптимизатора — те переменные, которые он хранит между шагами на каждый параметр ($v$, $r$); у Adam их две, то есть состояние весит вдвое больше самой модели.

Почему итеративно (Л1 §4.1, сл. 64). Задача — не занулить, а минимизировать лосс (ниже энтропии данных всё равно не опуститься), и «нам недоступна генеральная выборка — мы владеем лишь малой её частью». Метод Ньютона требует гессиан — матрицу вторых производных размера $N\times N$: для $N=10^9$ параметров это $10^{18}$ чисел, $4\cdot10^{18}$ байт в float32; вдобавок гессиан должен быть положительно определён, что в невыпуклой задаче не гарантировано (запись 01:00:37–01:01:13).

GD / SGD / мини-батч (сл. 65–66): $w_t=w_{t-1}-\lambda\nabla L_{w_{t-1}}$; градиент по всей выборке дорог (датасет может содержать триллионы объектов «ради одного шага спуска»); стохастический спуск в исходном смысле — градиент по одному объекту, очень шумный; на практике — оценка $\nabla\hat L$ по мини-батчу из 2…512 объектов. Шум оценки помогает выбираться из седловых точек (письменный конспект лектора).

Momentum — «метод тяжёлого шарика» (сл. 67): $$v_t=\alpha v_{t-1}-\lambda\nabla L_{w_{t-1}},\qquad w_t=w_{t-1}+v_t.$$ Антиградиент накапливается в переменной-скорости; минус уже спрятан внутри $v_t$, поэтому в обновлении весов стоит плюс. Мотивация адаптивности: расписание learning rate под конкретную ситуацию не подстраивается — нужен спуск, который адаптируется сам (запись 01:06:31).

RMSProp (сл. 68): $$r_t=\beta r_{t-1}+(1-\beta)\bigl(\nabla L_{w_{t-1}}\bigr)^2,\qquad w_t=w_{t-1}-\frac{\lambda}{\sqrt{r_t+\epsilon}}\nabla L_{w_{t-1}},$$ $r_t$ — скользящее среднее поэлементных квадратов градиента; деление на $\sqrt{r_t}$ выравнивает шаги по координатам: «шумные» координаты притормаживаются, «тихие» разгоняются.

Adam (сл. 69) — скорость из Momentum плюс адаптивный шаг из RMSProp: $$v_t=\beta_1v_{t-1}-(1-\beta_1)\nabla L_{w_{t-1}},\qquad r_t=\beta_2r_{t-1}+(1-\beta_2)\bigl(\nabla L_{w_{t-1}}\bigr)^2,$$ $$\hat v_t=\frac{v_t}{1-\beta_1},\qquad \hat r_t=\frac{r_t}{1-\beta_2},\qquad w_t=w_{t-1}+\lambda\frac{\hat v_t}{\sqrt{\hat r_t+\epsilon}}.$$ Знак в обновлении — плюс, как у Momentum (см. «Ловушки»). Квадрат градиента — поэлементный. За рамками слайдов, но в письменном конспекте лектора: Nesterov momentum (градиент считается в точке, куда привёл бы импульс), Adagrad (накапливает квадраты без скользящего среднего — предшественник RMSProp), расписание learning rate с warm-up (старт с околонулевых значений, разогрев до пика, затухание); Adam назван там «серебряной пулей».

Состояние оптимизатора. Всё, что оптимизатор хранит между шагами помимо самих весов: у Momentum — $v$, у RMSProp — $r$, у Adam — обе «памяти» на каждый параметр («куда в среднем движемся» и «насколько сильно параметр дёргается»). Отсюда прямое следствие для памяти: состояние Adam весит вдвое больше модели (Л1 §4.5). В смешанной точности на параметр приходится 16 байт: 2 (fp16-вес) + 2 (fp16-градиент) + 12 (fp32-копия веса, $v$, $r$ по 4 байта) — так на слайде ZeRO для модели 7,5 млрд параметров получаются 120 ГБ, и именно состояние оптимизатора (8 байт из 16) шардируют первым — ZeRO-1 (Л5 §3.2, сл. 26–27). Практически: состояние хранится в чекпоинте вместе с весами (Практика 2 §4.5), а при обучении в PyTorch optimizer.zero_grad() очищает градиенты, но не состояние.

Где в конспектах: Л1 §4 (сл. 63–69), вопрос к защите 8; память на состояние — Л5 §3.2.

Уточняющие вопросы

«Градиент по всей выборке — это хорошо или плохо?» Не всё равно: при триллионах объектов один шаг стоит целого прохода по данным (01:02:31). «Почему не метод Ньютона, ведь он сходится квадратично?» Не из-за сходимости, а из-за памяти на гессиан и его положительной определённости. «Зачем поправка на смещение $\hat v,\hat r$?» Скользящие средние стартуют с нуля и на первых шагах занижены; поправка это компенсирует (в оригинале Kingma–Ba знаменатели $1-\beta^t$, см. «Ловушки»).

1.3. Bias-variance trade-off. Регуляризация. Нормализация

Тезис. Ожидаемая ошибка раскладывается на $(\text{bias})^2+\text{variance}+\text{noise}$: bias — систематическая ошибка модели на любых данных, variance — её неустойчивость к смене выборки, noise — неустранимый шум. Переобучение — низкий bias при высоком variance (модель сложнее данных), недообучение — наоборот. Лечится изменением сложности модели или регуляризацией: L1/L2 сжимают пространство параметров, Dropout случайно выключает часть выходов, BatchNorm/LayerNorm нормируют активации и заодно смягчают затухание градиентов.

Разложение ошибки (Л1 §5.2, сл. 72). Для $y=f(x)+\varepsilon$, $\varepsilon\sim\mathcal N(0,\sigma^2)$: $$\text{expected loss}=(\text{bias})^2+\text{variance}+\text{noise}.$$ Bias — насколько модель систематически ошибается на любых данных генеральной выборки; variance — насколько она меняется при смене обучающей выборки (запись 01:09:49). Численная иллюстрация из конспекта: полином степени 1 даёт $\text{bias}^2=0{,}2004$ при $\text{variance}=0{,}0349$, степени 6 — $0{,}0080$ при $\text{variance}=62{,}4$.

Диагностика по кривым (сл. 71): тренировочный лосс продолжает падать, а валидационный разворачивается вверх — переобучение (на слайде кривые расходятся примерно с 7-й эпохи, валидационная проходит минимум около $0{,}38$ и растёт до $0{,}55$); высоки оба — недообучение. Причина по лектору: модель слишком сложная или слишком простая для данных; лечение — менять сложность или регуляризовать (01:12:50). В терминах законов масштабирования то же самое: $\text{bias}\sim N^{-\alpha}$, $\text{variance}\sim D^{-\beta}$ — параметры снижают bias, данные снижают variance (Л7 §5.5).

Регуляризация (Л1 §5.3, сл. 73): $$L_{reg_1}=L+c\lVert w\rVert_1,\qquad L_{reg_2}=L+c\lVert w\rVert_2^2.$$ L1 способна занулять веса (производная штрафа постоянна, $\pm c$, и дотягивает мелкие веса до нуля), L2 только уменьшает их (производная $2cw$ у нуля исчезает). Геометрический смысл коэффициента $c$ — по лектору (01:15:30–01:20:24): график штрафа, наложенный на функцию потерь, сжимает область параметров, где вообще имеет смысл искать минимум; «если сделаем $c$ больше, график будет круче, а интервал — уже». Dropout — случайное зануление части выходов слоя на шаге обучения; через выключенные веса градиент не проходит (01:23:50); пример лектора: из 5 нейронов выкинули 40 % — осталось 3, и матрица $3\times5$ действует как $3\times3$. Побочный признак: валидационный лосс ниже тренировочного обычно означает не чудо, а включённый Dropout на трейне.

Нормализация (Л1 §5.4, сл. 74). Данные: $\tilde x=\frac{x-\mu}{\sigma+\epsilon}$. Активации — BatchNorm: $\hat z=\frac{z-\mu_B}{\sigma_B+\epsilon}$, $\tilde z=\gamma\hat z+\beta$, где $\mu_B,\sigma_B$ считаются по батчу, а обучаемые $\gamma,\beta$ возвращают сети предсказательную силу после нормировки. Побочный эффект — данные остаются в разумном диапазоне, поэтому нормализация помогает бороться с затуханием градиентов. На инференсе BatchNorm использует накопленную статистику (буферы running mean/std), а не батчевую — отсюда разница model.train() / model.eval() (Практика 1). В трансформере вместо BatchNorm — LayerNorm по признакам одного токена, $y_j=\gamma_j\frac{x_j-\mu}{\sqrt{\sigma^2+\varepsilon}}+\beta_j$: не зависит от размера батча и одинаково работает при обучении и генерации токен за токеном, где «батча из будущих токенов» нет (Л2 §3.2, сл. 39–40). Дальнейшее развитие — пре-/пост-/сэндвич-нормализация и RMSNorm без вычитания среднего (см. вопрос 5.1); на GPU наивный LayerNorm — цепочка из пяти memory-bound операций и может занимать больше половины времени обучения (Л3 §4.5).

Где в конспектах: Л1 §5 (сл. 70–74), вопросы 9–10; LayerNorm — Л2 §3.2; стоимость на GPU — Л3 §4.5; связь с масштабированием — Л7 §5.5.

Уточняющие вопросы

«Почему в трансформере LayerNorm, а не BatchNorm?» Статистики по одному токену, а не по батчу: нет зависимости от размера батча и длины последовательностей, нет накопленных статистик для инференса (Л2, вопрос 7). «Что делает noise в разложении?» Это тот же неустранимый уровень, что энтропия данных $H(p)$ в кросс-энтропии: ни одна модель ниже него не опустится. «L1 или L2?» L1 — если нужен отбор признаков (зануление), L2 — если нужно просто ограничить веса.

Ловушки

Иллюстрация LayerNorm на сл. 40 Лекции 2 — стандартная CNN-картинка с осями $C,H,W,B$; лектор сам назвал её «не совсем корректной» для трансформера, где нормируется один $D$-мерный вектор-токен. Не путать регуляризацию (ограничение весов) с нормализацией (перемасштабирование данных/активаций): на слайде плана они стоят рядом как «инструменты» одного раздела, но действуют на разное.

Категория 2. Трансформер

2.1. Токенизация текста: посимвольная, по словам, BPE. Embedding-слой трансформера

Тезис. Нейросеть работает только с тензорами, поэтому текст сначала режется на токены, а токены — на индексы словаря. Посимвольная токенизация даёт маленький словарь, но очень длинные последовательности; пословная — короткие последовательности, но огромный словарь, где каждая словоформа — отдельный токен. BPE — компромисс: словарь стартует с алфавита и спецтокенов, а затем выучивает merge-правила, склеивая самые частые пары; byte-level BPE делает то же над байтами UTF-8. Embedding-слой превращает индекс в обучаемый вектор, убирая ложный порядок индексов.

Крайние варианты (Л2 §1.1–1.3, сл. 3–5). Посимвольная: словарь — алфавит, удобно для иероглифических языков, но последовательность в большом документе — миллионы символов, что тяжело и для внимания, и для памяти. По словам: последовательность короткая, но словарь огромен — каждая форма слова (падеж, род, число) становится отдельным токеном, для русского языка особенно болезненно; незнакомая форма целиком уходит в <UNK>.

BPE — Byte-Pair Encoding (§1.4–1.6, сл. 6–11). Стартовый словарь: алфавит плюс специальные токены (паддинг, начало/конец текста, <UNK>). Обучение: текст разбивается на пары соседних элементов, находится самая частая пара (в примере лектора — «e»+«n» в тексте «Byte-pair encoding tokenization»), она объединяется в новый токен, который добавляется в словарь; повторяем, пока словарь не достигнет нужного размера. Выученные merge-правила запоминаются и применяются к новому тексту в порядке обучения. Гарантия: любой текст можно собрать из элементов словаря, потому что стартовый алфавит уже в словаре, а каждое merge-правило склеивает только уже известные элементы; символ, которого не было при обучении, заменяется на <UNK>. Byte-level BPE (сл. 12): мультиязычный текст и эмодзи дают слишком большой стартовый словарь, поэтому текст переводят в байты UTF-8 и применяют BPE к байтам — стартовый словарь фиксирован (256 байт) и покрывает всё; так устроен токенизатор GPT-2, который на семинаре берётся через AutoTokenizer (П2 §2.1).

Embedding-слой (§1.7–1.8, сл. 13). Индекс токена — просто число, а числа задают отношение «больше/меньше», которого между токенами нет (пример лектора на доске: токены «tok», «en», «a» с индексами 28, 411, 29 — ложный псевдопорядок). Поэтому индекс переводится в вектор через обучаемую матрицу: строка с номером индекса — вектор токена. Размерность вектора эмпирически связана с размером модели (ответ лектора студенту, запись 28:49). После обучения близкие по смыслу токены оказываются близкими векторами — семантическое пространство; близость измеряется косинусом $\cos(\widehat{a,b})=\langle a,b\rangle/(|a||b|)$, и в таком пространстве работает векторная арифметика: «король» − «мужчина» + «женщина» ≈ «королева».

Связь с лабораторными. В ЛР1 реализуется собственный BPE (посимвольный, с маркером конца слова), в ЛР2 — обучение GPT-подобной модели на токенах GPT-2; на семинаре 2 показано, что у токенизатора GPT-2 нет отдельного pad-токена и его подменяют eos (П2 §2.2).

Где в конспектах: Л2 §1 (сл. 3–13), вопрос к защите 8; практика — П2 §2.

Уточняющие вопросы

«Почему BPE гарантирует отсутствие OOV, а пословная токенизация — нет?» Стартовый алфавит целиком в словаре, merge-правила добавляют только склейки известного; при byte-level BPE алфавит — все 256 байт. «Почему нельзя просто подать индексы в сеть?» Индексы навязывают порядок и расстояния, которых нет; embedding даёт обучаемую геометрию. «Что такое merge-правило?» Запомненная пара «что склеить во что», применяемая к новому тексту строго в порядке обучения.

Ловушки

Число merge-правил, а не букв, определяет размер словаря BPE: словарь = алфавит + спецтокены + по одному токену на правило. Косинусная близость — не расстояние: близость к 1 означает малый угол, а не малую разницу норм.

2.2. Позиционное кодирование: абсолютное, обучаемое, относительное, RoPE

Тезис. Самовнимание, FFN и LayerNorm перестановочно-инвариантны, поэтому порядок токенов нужно вводить явно. Абсолютное синусоидальное кодирование прибавляет к токену фиксированный вектор $PE(pos)$, у которого сдвиг на $k$ позиций выражается линейно; обучаемое абсолютное — таблица векторов, не масштабируемая за пределы обучающего контекста; относительное кодирует расстояние $i-j$ прямо в оценке внимания; RoPE поворачивает пары координат $q$ и $k$ на угол, пропорциональный позиции, так что в $QK^{\top}$ выживает только разность позиций.

Зачем (Л2 §3.6, сл. 47–48). Ни в одном блоке слоя трансформера нет информации о номере токена; пример лектора «Er kommt morgen nicht» / «Er kommt nicht morgen» показывает, что порядок меняет смысл.

Абсолютное синусоидальное (Л2 §3.7–3.8, сл. 49–52): $\hat x_{pos}=x_{pos}+PE(pos)$, $$PE(pos,2i)=\sin\!\Bigl(\frac{pos}{10000^{2i/D}}\Bigr),\qquad PE(pos,2i+1)=\cos\!\Bigl(\frac{pos}{10000^{2i/D}}\Bigr).$$ Выведено из двух желаний: каждая позиция кодируется уникально, и из кодировок можно восстановить отношение позиций. Второе даёт тригонометрия: $\sin(\omega(pos+k))=\sin(\omega pos)\cos(\omega k)+\cos(\omega pos)\sin(\omega k)$ — кодировка позиции $pos+k$ есть линейное преобразование кодировки $pos$, поэтому модели легко выучить относительные сдвиги; просто номер позиции числом такого свойства не имеет.

Обучаемое абсолютное (Л6 §3.1, сл. 11): таблица (длина контекста)×$d$. Две проблемы: размер растёт линейно с контекстом (при $d=8192$ и миллионе токенов — порядка 8 млрд «лишних» параметров), и на последовательности длиннее обучающей модель либо явно падает, либо — хуже — молча даёт разным токенам одинаковый вектор позиции (запись 19:15–21:42). Так же устроено кодирование в ViT (Л2 §4).

Относительное (Л6 §3.2, сл. 12): в оценку внимания добавляется обучаемый вектор расстояния $a_{ij}$, $$score(i,j)=\frac{x_iW_Q\,(x_jW_K+a_{ij})^{\top}}{\sqrt d},$$ кодируется не номер позиции, а расстояние между $i$ и $j$ — поэтому такое кодирование переносится на длинные контексты.

RoPE (Л6 §3.3, сл. 13–14): вектор $q$ на позиции $p$ умножается на блочно-диагональную матрицу поворотов, $k$-я пара координат поворачивается на угол $p\,\omega_k$. Абсолютное вращение — техническое средство: при вычислении $q_pk_l^{\top}$ поворот у $k$ транспонируется (знак угла меняется), и произведение зависит только от $(p-l)\omega_k$; в комплексной записи $q\mapsto q\,e^{ip\omega}$, $k\mapsto k\,e^{il\omega}$, а в скалярном произведении остаётся $e^{i(p-l)\omega}$ (вопрос лектора аудитории, запись 24:06–36:53). Итог: параметров нет, относительность встроена, контекст масштабируется. В ЛР2 используется синусоидальное кодирование; RoPE — материал Лекции 6.

Где в конспектах: Л2 §3.6–3.8, вопрос 9; Л6 §3, вопросы 5–6.

Уточняющие вопросы

«В чём относительность RoPE, если угол зависит от абсолютной позиции?» В паре $Q/K$: транспонирование поворота у $K$ меняет знак угла, и в произведении остаётся разность позиций (Л6, вопрос 6). «Почему „тихое“ падение обучаемого кодирования опаснее явного?» Ошибку не видно в терминале, качество портится незаметно. «Зачем синус и косинус вместе?» Чтобы сдвиг выражался линейно (формула суммы углов) и кодировки были уникальны.

Ловушки

NoPE стоял в старом списке вопросов и убран в новом — в конспектах его нет. Не смешивать «обучаемое» и «относительное»: обучаемое здесь означает таблицу абсолютных позиций, а относительное может быть и обучаемым ($a_{ij}$), и без параметров (RoPE).

2.3. Внимание: self-attention, многоглавое, маскированное многоглавое, cross-attention, block-masked attention

Тезис. Внимание — сила связи между векторами, измеряемая скалярным произведением; в самовнимании обучаемая матрица $W$ раскладывается на $W_QW_K^{\top}$, что даёт $QK^{\top}$, softmax по строкам делит «единичный бюджет внимания», деление на $\sqrt D$ возвращает дисперсию оценок к единице, и результат взвешивает значения $V$. Многоглавое внимание — $H$ параллельных голов в подпространствах $d_h=D/H$ с тем же числом параметров; маскированное — прибавление $-\infty$ до softmax; перекрёстное — $Q$ из одной последовательности, $K,V$ из другой; block-masked — маска для packed batching, разрешающая внимание только внутри одного объекта и назад.

От мультипликативного внимания к самовниманию (Л2 §2.1–2.4, сл. 17–19). Для последовательностей $G$ и $H$ оценки $E=GWH^{\top}$; разложив $W=W_QW_K^{\top}$ и взяв одну последовательность $X$: $Q=XW_Q$, $K=XW_K$, $E=QK^{\top}$. SVD вместо обучаемых матриц не подходит — «очень тяжело считается» и плохо параллелится на GPU, тогда как $XW_Q$ — это GEMM (запись 55:33).

Softmax и масштабирование (§2.5–2.7, сл. 20–23). $A=\mathrm{Softmax}(QK^{\top}/\sqrt D)$ построчно: $\sum_ja_{ij}=1$ — каждый запрос распределяет единичный бюджет между ключами; поэлементная сигмоида такой сравнимости не даёт. Скалярное произведение — сумма $D$ слагаемых с единичной дисперсией, $\mathrm{Var}[q\cdot k]=D$; без деления softmax насыщается и градиенты через него затухают (проверено в конспекте: при $D=512$ дисперсия $510{,}9$, после деления $0{,}998$).

Значения и итоговая формула (§2.8–2.9, сл. 24–28): $V=XW_V$, $O=\mathrm{Softmax}(QK^{\top}/\sqrt D)\,V$. Интуиция из рекомендательных систем: Query — что ищем, Key — по чему сопоставляем, Value — что передаём дальше; $W_V$ работает как фильтр информации токена.

Многоглавое внимание (§2.10–2.11, сл. 29–32): $H$ независимых голов с $W_Q^{(h)},W_K^{(h)},W_V^{(h)}\in\mathbb R^{D\times d_h}$, $d_h=D/H$, $O^{(h)}=\mathrm{Softmax}(Q^{(h)}K^{(h)\top}/\sqrt{d_h})V^{(h)}$; выходы конкатенируются и проецируются $W_O$. Зачем: одно слово несёт разные роли (подлежащее, дополнение…), одна тройка матриц все зависимости не выразит — каждая голова учит свой паттерн. Параметров не больше, чем у одной полноразмерной головы ($H\cdot D\times d_h=D\times D$), добавляется только $W_O$; масштабировать уже на $\sqrt{d_h}$. Головы считаются параллельно — удобно для GPU и для тензорного параллелизма по головам (Л5 §4.3).

Маскированное (§2.12, сл. 33; §3.10, сл. 54). К оценкам до softmax прибавляется $M$: $m_{ij}=0$ при $j\le i$, $-\infty$ при $j\gt i$: $$\mathrm{MaskedMHA}(x)=\mathrm{Softmax}\!\Bigl(\frac{QK^{\top}}{\sqrt{d_h}}+M\Bigr)V,$$ $e^{-\infty}=0$, так что запрещённые позиции получают ровно нулевой вес, а разрешённые — корректно перенормированы; зануление уже посчитанных весов после softmax сломало бы $\sum_ja_{ij}=1$. Нужно декодировщику, чтобы токен не «заглядывал в будущее».

Перекрёстное (§2.13, сл. 34–35; §3.11, сл. 55): $\widetilde Q=XW_Q$, $\widetilde K=ZW_K$, $\widetilde V=ZW_V$ — запросы из одной последовательности, ключи и значения из другой; единственное требование $s_V=s_K$, длина $Q$ может отличаться. Так выход кодировщика $Z$ попадает в декодировщик.

Block-masked attention (методичка ЛР2; в лекциях не разбиралось). При packed batching несколько независимых последовательностей склеены в одну; каждому токену приписан идентификатор объекта $s_i$ (0 — паддинг). Обычной треугольной маски мало: токены разных объектов не должны видеть друг друга, даже если стоят левее: $$(M)_{ij}=(s_i=s_j)\wedge(j\le i)\wedge(s_i\ne0),\qquad M^{loss}_i=(s_i=s_{i+1})\wedge(s_i\ne0),$$ вторая маска исключает из лосса переход с последнего токена одного объекта на первый токен следующего. Такая маска — блочно-треугольная; при блочном вычислении внимания (Flash Attention, Л4 §2.7) полностью замаскированные блоки можно вообще не считать, а шаблонное разреженное внимание (Л6 §6) строится на той же блочной идее. Лектор в Лекции 5 отметил, что для нетреугольных масок ЛР2 балансировка Zig-Zag Ring Attention работает хуже.

Где в конспектах: Л2 §2 (сл. 15–35), вопросы 1–5, 10; маска и лосс при packed batching — методичка ЛР2, §2.1; блочный пропуск — Л4 §2.7; Zig-Zag — Л5 §5.2.

Уточняющие вопросы

«Почему softmax, а не сигмоида?» Сумма по строке равна 1 — бюджеты запросов сравнимы (Л2, вопрос 1). «Что будет без $\sqrt D$?» Дисперсия оценок $D$, насыщение, затухание градиента. «Почему число голов почти не увеличивает параметры?» $H$ матриц $D\times d_h$ в сумме дают $D\times D$; растёт только за счёт $W_O$ (вопрос 4). «Какие размерности нужны перекрёстному вниманию?» Только $s_V=s_K$ (вопрос 5).

Ловушки

Маска прибавляется до softmax, не умножается после. В многоголовом варианте делят на $\sqrt{d_h}$, а не на $\sqrt D$. У block-masked attention две маски — внимания и лосса; забыть вторую — частая ошибка в ЛР2.

2.4. Transformer-encoder, transformer-decoder. Обучение трансформера. Задача авторегрессионной генерации

Тезис. Слой кодировщика — самовнимание и FFN с остаточными связями и LayerNorm; слой декодировщика — маскированное самовнимание, перекрёстное внимание к выходу кодировщика и FFN. Обучение: над выходом стоит классификационная голова по словарю, целевая последовательность — вход, сдвинутый на один токен, лосс — кросс-энтропия, все позиции считаются параллельно. Генерация авторегрессионна: токен за токеном от <BOS> до <EOS>, следующий зависит от уже сгенерированных, разброс регулируется температурой softmax.

Постановка seq2seq (Л2 §2.2, сл. 15–16): преобразование одной последовательности в другую (перевод, чат-бот); классическое решение — кодировщик-декодировщик на RNN/LSTM, где порядок заложен архитектурно. Трансформер заменяет рекуррентность вниманием, а порядок вводит позиционным кодированием.

Слой кодировщика (§3.9, сл. 53) — $N_{enc}$ одинаковых слоёв: $$\tilde x=\mathrm{LN}\bigl(x+\mathrm{MHA}(x)\bigr),\qquad y=\mathrm{LN}\bigl(\tilde x+\mathrm{FFN}(\tilde x)\bigr),$$ $\mathrm{FFN}(x_i)=\phi(x_iW_1+b_1)W_2+b_2$ применяется к каждому токену независимо, $D_{FFN}\gt D$ (сл. 37–38); остаточная связь даёт в производной множитель $(1+\partial F/\partial x)$, спасающий градиент (сл. 43–46). Это пост-нормализация оригинальной статьи — именно её требует ЛР2; современные модели используют пре-норм (см. 5.1).

Слой декодировщика (§3.10–3.11, сл. 54–55): маскированное самовнимание, затем перекрёстное внимание к $Z$ ($Q$ из $X_2$, $K,V$ из $Z$), затем FFN: $$\tilde x=\mathrm{LN}\bigl(x+\mathrm{MaskedMHA}(x)\bigr),\quad \hat x=\mathrm{LN}\bigl(\tilde x+\mathrm{CrossAttention}(\tilde x,Z)\bigr),\quad y=\mathrm{LN}\bigl(\hat x+\mathrm{FFN}(\hat x)\bigr).$$ Для языковой модели «предсказать следующий токен» кодировщик не нужен вовсе — используется только декодировщик без блока перекрёстного внимания (decoder-only, как GPT; П2 §1.2, Л7 §3).

Обучение (§3.12, сл. 56–57). Выход трансформера — векторы; классификационная голова (LM-head) даёт логиты по словарю, потеря — кросс-энтропия. Цель на позиции $i$ — токен $i+1$: вход <BOS>, $t_1,\dots,t_n$ → цель $t_1,\dots,t_n$, <EOS>; все позиции предсказываются параллельно за один проход, маска запрещает подсматривать вперёд. Разметка не нужна — цели берутся из самого текста (self-supervised). Кросс-энтропия раскладывается как $H(p,q)=H(p)+D_{KL}\langle p\|q\rangle$: энтропия языка $H(p)$ — неустранимый минимум лосса; перплексия $\exp(H(p,q))$ — «эффективное число вариантов» на шаг (§3.12, по письменному конспекту).

Инференс — авторегрессионная генерация (§3.13, сл. 58): на каждой итерации модель предсказывает один новый токен, дописывает его ко входу и повторяет, пока не выдаст <EOS> или не упрётся в максимальную длину; в отличие от обучения процесс строго последователен. Чтобы не пересчитывать $K,V$ уже обработанных токенов, хранят KV-кэш (см. 5.4). Температура (§3.14, сл. 59): $$\mathrm{Softmax}_T(x)_k=\frac{e^{x_k/T}}{\sum_ie^{x_i/T}},$$ $T\to0$ приближает выбор к $\operatorname{argmax}$ (детерминированно), $T\gt1$ уравнивает вероятности и делает генерацию разнообразнее.

Где в конспектах: Л2 §3 (сл. 37–59), вопросы 6, 7, 11; decoder-only и next-token — П2 §1.2, Л7 §3.

Уточняющие вопросы

«Как остаточные связи спасают градиент?» Производная суммы даёт слагаемое $1$, которое не затухает даже при малой производной подслоя (Л2, вопрос 6). «Что такое перплексия 10?» Модель на каждом шаге выбирает как будто из 10 равновероятных вариантов (вопрос 11). «Почему генерация медленнее обучения?» Обучение параллельно по позициям, генерация последовательна и требует по проходу на токен.

Ловушки

При $T=0$ формула не определена (деление на ноль): «$T\to0$» означает предел, на практике — малое $T$ или сразу $\operatorname{argmax}$. В ЛР2 нужен post-norm, не pre-norm — лектор оговорил это явно. LM-head возвращает логиты: Softmax перед nn.CrossEntropyLoss ставить нельзя.

Категория 3. Обучение на ГПУ

3.1. Анатомия ГПУ: сравнение архитектур GPU и CPU, Streaming Multiprocessors (SM), иерархия памяти GPU

Тезис. CPU минимизирует задержку одной последовательной программы (мало ядер, много кэша и управляющей логики), GPU максимизирует пропускную способность на множестве независимых операций (много простых вычислительных блоков, мало управляющей логики). GPU состоит из SM; внутри SM — CUDA-ядра, тензорные ядра, варп-планировщики, регистры, разделяемая память и L1. Память — иерархия «чем ближе к вычислителю, тем быстрее и меньше»: диск → RAM хоста → глобальная память GPU → разделяемая → регистры; цель оптимизации — реже ходить в глобальную память.

CPU против GPU (Л3 §1.1–1.2, сл. 3–6). Если элементы результата независимы (как элементы произведения матриц), выигрыш от их одновременной обработки перевешивает скорость одного быстрого ядра; поэтому у GPU в сотни раз больше блоков, но на каждый приходится меньше кэша и управляющей логики. Не все операции нейросети параллелятся одинаково хорошо (см. 3.3).

SM и исполнение (§1.3–1.6, сл. 7–15). Streaming Multiprocessor — основной блок GPU, работает независимо от других. Вычисления разбиты на потоки (логические единицы), потоки объединены в варпы по 32 — базовая единица исполнения по принципу SIMT: одна инструкция применяется ко всем 32 потокам, каждому со своими данными. CUDA-ядра — ALU с версиями под fp32/fp16/fp8/fp4 и целые типы; тензорных ядер намного меньше (обычно 1–4 на SM против, например, 128 CUDA-ядер FP32), они считают только матричные умножения. Варп-планировщик (обычно 4 на SM) выбирает, какой из готовых варпов запустить; активные варпы — занявшие ресурсы SM, их число ограничено архитектурой (32/48/64 на SM) и ресурсами.

Иерархия памяти (§2, сл. 18–29). Память хоста управляется ОС постранично; для обмена с GPU используют закреплённую (pinned) память — фиксированный физический адрес, асинхронное копирование (в PyTorch pin_memory=True). Глобальная память (GMEM) — самая большая и самая медленная на устройстве, хранит веса и активации, через неё общаются программы и устройства. Разделяемая память (SMEM) — на 1–2 порядка быстрее («в 10–100 раз», запись 23:37), доступна потокам одного блока, но много меньше; опасность — конфликт банков (несколько потоков обращаются к одному банку), лечится паддингом. Регистры (RMEM) — 1–2 такта, свои у каждого потока, физически Register File из 32-битных ячеек; в одну ячейку кладут один fp32 или векторизованно два fp16 / четыре fp8. Если регистров не хватает, компилятор молча уходит в медленную local memory, а при явном лимите программа падает. L1-кэш внутри SM делит физический ресурс с SMEM (пропорцию настраивает драйвер); L2 общий для всех SM — через него идут все обращения к GMEM. Всё сказанное — про NVIDIA; у AMD архитектура иная и в курсе не рассматривается.

Согласованный доступ (§2.7, сл. 29–32): обращения потоков варпа к соседним ячейкам GPU объединяет в одну транзакцию; чтение столбца row-major матрицы — разброс по памяти и много транзакций, поэтому матрицу весов хранят транспонированной (подробнее в 3.3).

Как оценивать (§3, сл. 34–41): не задержка, а пропускная способность (FLOP/s, токены в секунду); реально достижимо 40–70 % пика, пик — во многом маркетинговая цифра. Арифметическая интенсивность $\mathrm{AI}=\mathrm{FLOPs}/(R+W)$ и roofline $\text{Performance}\le\min(\mathrm{AI}\cdot BW,\ \text{PeakFLOP/s})$ (см. 3.4); occupancy $=W_{active}/W_{max}$ — доля занятых ресурсов SM, чаще всего ограничена регистрами.

Где в конспектах: Л3 §1 (сл. 3–15), §2 (сл. 17–32), §3 (сл. 34–41), вопросы 1, 3, 5, 9, 10; связь GPU между собой — Л5 §1.

Уточняющие вопросы

«Почему регистры обязательны, а SMEM — нет?» Арифметика выполняется только над регистрами; SMEM — необязательный кэш, который разработчик заполняет сам (Л3, вопрос 3). «Почему высокая occupancy не гарантирует скорость?» Она говорит, сколько ресурсов занято, а не чем: наивный GEMM занимает много варпов и всё равно memory-bound (вопрос 5). «Что ограничивает число активных варпов?» Чаще всего регистры на поток (вопрос 10).

Ловушки

При одинаковом числе CUDA-ядер под FP32 и INT32 больше будет INT-OPS — целочисленное ядро проще (вопрос лектора для самопроверки, 46:05). Конфликт банков — не гонка данных: он лишь замедляет, а не портит результат (письменный конспект лектора, гл. 10). Программное разделение L1/SMEM — не фиксированное, его настраивает драйвер.

3.2. Программные модели CUDA и Triton. В чём отличия? Что такое стримы и события?

Тезис. В CUDA кернел описывает работу одного потока; потоки организованы иерархией сетка → блоки → потоки, блок ≤ 1024 потоков, потоки блока делят SMEM и синхронизируются барьером. В Triton единица программы — program instance, который обрабатывает целый блок данных (тайл): программист оперирует блочными операциями tl.load/tl.store, а раскладку по потокам и памяти делает компилятор при JIT-компиляции. Стрим — очередь операций на устройстве, выполняемых по порядку и асинхронно относительно хоста; разные стримы могут перекрываться. Событие — маркер в стриме, по которому один стрим (или хост) ждёт другой и по которому измеряют время.

Вне конспектов занятий

Модель CUDA, стримы и события в лекциях устно не разбирались (это материал Практики 3, сл. 50–62 колоды Лекции 3). Ниже — по письменному конспекту лектора: gpu_programming.pdf, §2 (= «САНС 2026.pdf», гл. 10); формулировки сверены с CUDA Programming Guide NVIDIA (см. «Источники»). Часть про Triton — по Лекции 4.

Стек CUDA (гл. 10.1): драйвер (управление устройством, память, запуск) → CUDA Runtime (API: выделение и копирование памяти хост↔девайс) → CUDA C/C++ с компилятором NVCC → библиотеки cuBLAS/cuBLASLt (линейная алгебра), cuDNN (примитивы сетей), NCCL (коммуникации).

Кернелы и иерархия потоков (гл. 10.2–10.4). Кернел — функция, выполняемая на устройстве и описывающая работу одного потока; запускается хостом сразу для множества потоков, каждый получает индекс и обрабатывает свой элемент. Запуск не бесплатен — kernel launch overhead, заметный при множестве мелких кернелов (тот же «штрих-код» на профиле, Л4 §4.3). Иерархия Grid → Blocks → Threads: поток исполняет код кернела по SIMT со своим индексом; варпы по 32 потока в модели явно не выделены (аппаратно исполнение всё равно варпами); блок — группа потоков программируемого размера (обычно кратного 32), потоки блока могут обращаться к общей SMEM и синхронизироваться; в блоке максимум 1024 потока (32 варпа); набор блоков одного запуска — сетка. Индексация по трём осям $x,y,z$; глобальный индекс потока считается из индекса потока в блоке, индекса блока и размера блока.

Синхронизации, гонки, редукции (гл. 10.5–10.7). Потоки асинхронны и запускаются в любом порядке; три уровня барьеров — устройства (все кернелы на всех стримах завершены), кернела (все потоки блока дошли до барьера — перед доступом к общей памяти) и варпа. Race condition — результат зависит от порядка выполнения потоков без синхронизации (две записи по одному адресу; чтение до записи); опасна тем, что портит результат без падения программы. Редукция (сумма массива): наивное сложение всеми потоками в одну переменную — гонка; правильно — по дереву: частичные суммы на поток, попарное сложение внутри варпа за $\log_2 32=5$ шагов с синхронизацией варпа между шагами (варп-редукция), частичные суммы варпов в SMEM (не более 32 на блок), затем ещё одна варп-редукция.

Triton (Л4 §3, сл. 52–56). Писать быстрые CUDA-кернелы долго и трудно; чистый PyTorch не даст собственному механизму эффективности; Triton — компромисс «20 % усилий ради 80 % результата». Кернел с декоратором @triton.jit: pid = tl.program_id(axis=0), offsets = pid*BLOCK_SIZE + tl.arange(0, BLOCK_SIZE), маска offsets < n_elements, tl.load / tl.store. Program instance обрабатывает целый блок (в реальных кернелах — тысячи элементов), а не один элемент, как поток CUDA; компилятор сам решает, какие тайлы считать, что грузить в SMEM/регистры, где задействовать тензорные ядра. Компиляция происходит при первом вызове (JIT) и кэшируется — отсюда разогревочные прогоны перед бенчмарком. По форме модель Triton похожа на SIMD (один блок данных как единое целое), исполняется же на той же SIMT-архитектуре, что и CUDA. Triton — не часть PyTorch: torch.compile через TorchInductor сливает операции в Triton-кернелы, но кернел можно вызвать и без PyTorch, передав указатели и страйды.

Стримы (гл. 10.8). Кернелы запускаются с хоста и выполняются на устройстве асинхронно: CPU ставит операцию в очередь и продолжает работу. Стрим — очередь операций на устройстве: внутри стрима операции выполняются в порядке добавления, следующая начинается после завершения предыдущей; разные стримы выполняются асинхронно друг относительно друга. Для обучения это принципиально: на одном стриме — forward/backward и обновление параметров, на втором — коммуникации между устройствами, на третьем — загрузка следующего батча; второй и третий «прячутся» под первым. Именно это видно на таймлайне профилировщика (compute stream и communication stream, Л4 §4.3) и в правиле «AllReduce градиентов в DDP прячется под backward» (Л5 §3.1). Оборотная сторона асинхронности: сложнее организовать зависимости между стримами и измерять время.

События (гл. 10.9). CUDA-событие — маркер, записанный в стрим; когда устройство доходит до маркера, событие считается выполненным. Применение первое — зависимости между стримами: перед вычислением слоя нужно дождаться, пока стрим коммуникаций соберёт данные с других устройств; синхронизация всего устройства решила бы это, но заставила бы стрим коммуникаций простаивать вместо сбора данных для следующего слоя; событие после кернела коммуникации запрещает кернелу вычислений стартовать раньше, не останавливая остальное. Применение второе — замер времени: код замера исполняет CPU, а кернел асинхронен, поэтому обычный таймер измерит лишь постановку в очередь; события до и после кернела в стриме дают время между ними. По NVIDIA CUDA Programming Guide: cudaStreamWaitEvent задерживает команды стрима до выполнения события, cudaEventRecord / cudaEventElapsedTime — стандартный способ измерения; асинхронное копирование хост↔девайс с перекрытием требует закреплённой (pinned) памяти. В PyTorch первая реализация FSDP синхронизировалась тяжело, а FSDP-2 переведена на CUDA-события (ответ лектора после Лекции 5, 01:49:06).

Где в конспектах: Л4 §3 (сл. 52–56), вопросы 9, 11; §4.2–4.3 (разогрев, стримы на таймлайне); стек и модель CUDA, стримы, события — письменный конспект лектора gpu_programming.pdf §2 / САНС гл. 10 (конспекта Практики 3 в наборе нет); FSDP-2 и события — Л5 §7.

Уточняющие вопросы

«Чем program instance отличается от потока?» Уровнем: блок данных против одного элемента; раскладку по потокам делает компилятор Triton (Л4, вопрос 9). «Зачем разогревочные прогоны?» Первый вызов запускает JIT-компиляцию; результат кэшируется (Л4 §4.2). «Почему нельзя измерять время кернела обычным таймером CPU?» Запуск асинхронен — измерится постановка в очередь, а не выполнение; нужны события.

Ловушки

На сл. 56 Лекции 4 лектор устно несколько раз менял местами SIMD и SIMT; слайд формулирует верно: форма — SIMD-подобная, исполнение — SIMT (Л4 §3.3, запись 2:07:54). Блок ≤ 1024 потоков — это же число ограничивает тайл 32×32 «по одному элементу на поток» в оптимизации GEMM (Л4 §1.4). Конфликт банков — не race condition.

3.3. CUDA-ядра, тензорные ядра, варпы. Варп-планировщики. Логические ветвления на GPU, расхождения варпов. Согласованный доступ к памяти

Тезис. CUDA-ядра — универсальные ALU, тензорные ядра — специализированные блоки для умножения матриц малого фиксированного размера с накоплением в более высокой точности; варп — 32 потока, исполняющие одну инструкцию (SIMT), варп-планировщик выбирает готовый варп. Расхождение варпа возникает, когда ветви условного оператора выполняют разные инструкции: ветви исполняются по очереди с маскированием потоков. Согласованный доступ — обращения потоков варпа к соседним адресам сливаются в одну транзакцию; для этого матрицу весов хранят транспонированной.

Ядра и варпы (Л3 §1.3–1.6, сл. 8–15). Варп — группа из 32 потоков, базовая единица исполнения: одна инструкция, разные данные (SIMT). CUDA-ядра — ALU внутри SM с версиями под fp32/fp16/fp8/fp4 и целые типы; тензорные ядра — 1–4 на SM, только матричные умножения фиксированного размера, скалярной арифметикой, сравнениями и логикой по-прежнему занимаются CUDA-ядра. Тензорное ядро выполняет MMA (Matrix Multiplication Accumulation): $C^R_{I,J}\leftarrow C^R_{I,J}+A^R_{I,T}B^R_{T,J}$ — умножение в пониженной точности, накопление в более высокой (Л4 §1.7, сл. 33): при накоплении в E5M2 частичная сумма около 1024 имеет шаг гранулярности 256, и прибавление 5 её не меняет; поэтому суммы, экспоненты и softmax держат в fp32/fp16, а умножение — в fp8/bf16. Поколения: 4-е — Hopper, 5-е — Blackwell. Варп-планировщик — аппаратный блок SM (обычно 4), решающий, какой из готовых варпов запустить; активные варпы — занявшие регистры, SMEM и вычислительные блоки; их число ограничено архитектурой и, чаще всего, регистрами.

Расхождение варпов (§1.4, сл. 11; §4.1, сл. 44). Если внутри варпа стоит if/else и потоки идут по разным ветвям, GPU выполняет ветви последовательно, отключая (маскируя) неактивные потоки — вычисления резко замедляются. Расхождение вызывает не сама конструкция, а разные инструкции в ветвях: if (x>0) out=x; else out=0; расходится (в одной ветви есть чтение из памяти, в другой нет), а тернарная форма out = x>0 ? x : 0 компилируется в одну предикатную инструкцию, как и fmaxf; логические операции (and/or/xor) ветвлений не создают. Общий совет курса — по возможности избегать if в GPU-коде.

Согласованный доступ (§2.7, сл. 29–32). Транзакция памяти переносит сразу несколько соседних ячеек (её размер — от 128 до 8192 бит в зависимости от архитектуры). Если потоки варпа читают соседние адреса, GPU объединяет обращения в минимум транзакций; если адреса разбросаны — на каждую ячейку своя транзакция. Чтение столбца row-major матрицы — как раз разбросанный доступ, поэтому матрицу весов $W$ хранят как $W^{\top}$: столбец становится строкой и читается последовательно. Числовой пример лектора: шина 256 бит, ячейка 32 бита — в согласованном случае 32 ячейки варпа читаются за 4 транзакции (по 8 ячеек в каждой), в разбросанном — за 32.

Occupancy (§3.6, сл. 41): $W_{active}/W_{max}$; на примере профилировщика ≈30 из 64 варпов; низкая occupancy чаще всего из-за нехватки регистров (реже SMEM), но высокая occupancy сама по себе скорости не гарантирует.

Где в конспектах: Л3 §1.3–1.6, §2.7, §4.1, вопросы 2, 4, 9, 10; тензорные ядра и MMA — Л4 §1.7, вопрос 4.

3.4. Оптимизация GEMM на GPU

Тезис. Наивный GEMM — memory-bound: на один элемент результата читается $2K$ чисел и делается $2K-1$ операций, интенсивность $\approx\tfrac14$ FLOP/байт при любом размере. Оптимизация — уменьшать трафик к глобальной памяти: тайлинг с кэшированием блоков в SMEM (интенсивность по GMEM растёт с размером тайла), подтайлы в регистрах, транспонированное хранение весов для согласованного доступа, пониженная точность (в 2–4 раза меньше байт на число), тензорные ядра с накоплением в высокой точности и слияние соседних мелких операций в один кернел. Итог — переход GEMM в compute-bound зону roofline.

Диагноз (Л3 §3.4–3.5, §4.3; Л4 §1.1–1.2, сл. 3–5). Roofline: $\text{Performance}\le\min(\mathrm{AI}\cdot BW,\ \text{Peak})$; слева от излома программа упирается в память. Для $C=AB$, $A\in\mathbb R^{M\times K}$, $B\in\mathbb R^{K\times N}$, наивно $C_{ij}=\sum_kA_{ik}B_{kj}$: чтений $2K$ (8К байт в fp32), FLOPs $2K-1$, $\mathrm{AI}\to\tfrac14$ при $K\to\infty$ (на $7\times7$: 14 чтений, 13 операций); «идеальная» интенсивность при чтении каждой матрицы по разу на $2^{10}$-размерах — около 170. Разрыв в сотни раз — не в операции, а в том, что одни и те же строки и столбцы перечитываются из GMEM.

Тайлинг (Л4 §1.2–1.3, сл. 6–16). Блок потоков считает тайл $B_M\times B_N$ результата, загружая блоки $A$ и $B$ в SMEM и переиспользуя их. Формально, если считать и GMEM-, и SMEM-обращения, $I_{tiled}=\frac{1}{2/B_N+2/B_M+4}\le\tfrac14$ — «всё плохо, но только формально»: SMEM на два порядка быстрее, узкое место — только GMEM, а по нему $I^{GMEM}_{tiled}=\frac{1}{2/B_N+2/B_M}=\frac{2}{4(1/B_N+1/B_M)}$ растёт с размером тайла.

Предел тайла и регистры (§1.4, сл. 17–20). Блок ≤ 1024 потоков, при одном элементе на поток максимум — тайл 32×32; дальше один поток считает подтайл (несколько элементов), что упирается в регистровое давление и роняет occupancy — на практике чаще в регистры, чем в SMEM.

Пониженная точность (§1.5–1.6, сл. 21–29). В формуле интенсивности «4» — байты на fp32; fp16/bf16 дают 2 байта, fp8 — 1, интенсивность растёт в 2–4 раза. Форматы: fp32 — 1/8/23 бита (знак/экспонента/мантисса), значение $(-1)^s2^{e-127}1.m$; fp16 — 1/5/10, диапазон $\approx6{,}1\cdot10^{-5}\dots6{,}55\cdot10^4$; bf16 — 1/8/7: диапазон как у fp32 ценой грубой мантиссы. Риски: переполнение (fp16 «улетает за край» уже около 65 тысяч) и округление (чем больше модуль числа, тем крупнее шаг) — поэтому для обучения обычно bf16.

Тензорные ядра (§1.7, сл. 30–33). Тайл 128×128 bf16 с подтайлами 4×4 на поток даёт $I=\frac{1}{1/128+1/128}=64$ — compute-bound, но 16 элементов подряд одним потоком считать долго; тензорные ядра выполняют MMA $C\leftarrow C+AB$ над блоками аппаратно: умножение в пониженной точности, накопление в fp32/fp16 (пример 1024+5 в E5M2). MFU — доля реально достигнутого от пика — редко выше ≈50 %, без тензорных ядер около 25 % (устно, 39:05).

Слияние кернелов и доступ к памяти (§1.8, сл. 34; Л3 §2.7). Kernel fusion — не выгружать промежуточный результат мелких операций (нормализация, поэлементные) в GMEM, а считать их в одном кернеле с GEMM; наивный LayerNorm из пяти отдельных кернелов — главный кандидат. Хранение $W^{\top}$ обеспечивает согласованный доступ при чтении «столбцов». Ориентир после оптимизации — интенсивность порядка 240 (Л3 §4.3, сл. 48).

Где в конспектах: Л4 §1 (сл. 3–34), вопросы 1–5; Л3 §3.4–3.5, §4.3, вопросы 4, 6, 7.

Уточняющие вопросы

«Почему тайлинг формально не повышает интенсивность, но ускоряет?» Учёт SMEM-чтений в формуле — формальность; реальный предел — трафик GMEM, который тайлинг снижает (Л4, вопрос 2). «Почему нельзя увеличивать тайл бесконечно?» 1024 потока на блок и регистровое давление (вопрос 3). «FP16 или BF16?» BF16 — диапазон fp32, грубее мантисса; безопаснее от переполнения (вопрос 5).

Устные оценки диапазонов FP8 на лекции (E5M2 «≈32 тысячи», E4M3 «≈230») ниже реальных констант спецификации OCP: 57 344 и 448 (Л4 §1.7, проверено через ml_dtypes). «Интенсивность 128» для тайла 128×128 — оговорка, верно 64.

3.5. Flash Attention

Тезис. Наивное внимание считает $S=QK^{\top}/\sqrt d$, $A=\mathrm{Softmax}(S)$, $O=AV$ тремя кернелами с записью в GMEM, а $S$ и $A$ растут квадратично по длине последовательности (при 150 000 токенов — ≈45 ГБ на слой даже в FP8). Flash Attention — тот же математический результат без материализации $S$ и $A$: выход считается по блокам $K,V$ в одном кернеле, softmax пересчитывается «онлайн» через бегущие максимум $m$ и знаменатель $l$, ненормированная сумма $U$ накапливается, деление на $l$ выполняется один раз в конце. Память линейна по длине, трафик к GMEM меньше, полностью замаскированные блоки пропускаются, а backward пересчитывает нужные блоки $A$ из сохранённых $m,l$.

Проблема (Л4 §2.1, сл. 36). Три этапа, каждый — отдельный кернел с выгрузкой в GMEM; главное — не лишние чтения (их лечит fusion), а квадратичные активации: матрицы $S$ и $A$ размера seq×seq на каждую голову и слой.

Идея (§2.2, сл. 37): применить тайлинг к вниманию — блок строк $Q$ живёт в SMEM весь внутренний цикл, для каждого блока $(K_t,V_t)$ считается частичный блок $S$, сразу применяется online-softmax и умножение на $V_t$, всё в одном кернеле.

Safe softmax (§2.3, сл. 38–40): $\mathrm{Softmax}(x-m)=\mathrm{Softmax}(x)$ при $m=\max_jx_j$ — сдвиг на максимум строки делает аргументы экспонент неположительными, чтобы в пониженной точности ничего не разрасталось.

Online softmax (§2.4, сл. 41–45). После $t-1$ блоков известны $m^{(t-1)}$ и $l^{(t-1)}=\sum_{old}\exp(x_j-m^{(t-1)})$; для нового блока $m_t=\max_jx^{(t)}_j$, $m^{(t)}=\max(m^{(t-1)},m_t)$, $\hat l^{(t)}=\sum_{j\in t}\exp(x_j-m^{(t)})$ и $$l^{(t)}=\exp\bigl(m^{(t-1)}-m^{(t)}\bigr)\,l^{(t-1)}+\hat l^{(t)}:$$ старая сумма перенормируется под новый максимум тем же множителем, что и сдвиг softmax. Ждать всю строку нельзя — варпы простаивали бы на синхронизации.

QKV-тайлинг (§2.5, сл. 46–49). Матрица весов $A$ явно не вычисляется — её знаменатель ещё не готов; вместо этого копится ненормированная сумма $U^{(t)}=\exp(m^{(t-1)}-m^{(t)})U^{(t-1)}+\exp(S_{i,t}-m^{(t)})V_t$, и после всех блоков $O_i=U^{(T)}/l^{(T)}$ — одно деление вне цикла. Реальный кернел работает с 4D-тензорами batch×heads×seq×head_dim; статистики $m,l$ становятся тензорами, всё хранится в GMEM плоско и восстанавливается через страйды.

Результат (§2.6, сл. 50): по памяти отношение naive/FA растёт от 12× при seq_len 128 до 132× при 2048; по скорости даже неоптимизированная Triton-реализация даёт ≈2× (запись 1:47:49–1:51:19); формула внимания не меняется — только порядок и группировка вычислений; NumPy-эталон в конспекте совпадает с наивным вниманием до машинной точности. История: Transformer 2017, GPT-1/2/3 — рост размера, и лишь когда встал вопрос длинных контекстов, тайлинг применили к вниманию — Flash Attention 2022, FA2 2023.

Маска и backward (§2.7–2.8, по письменному конспекту лектора): при блочной обработке маску применяют к блоку $S$ до online-softmax, блоки целиком выше диагонали (при causal) пропускают целиком, блоки на диагонали маскируют поэлементно, а $-\infty$ не влияет ни на $m$, ни на $l$, ни на $U$; на backward нужна $A$, которую FA не хранит — её блоки пересчитывают из сохранённых $m_i,l_i$: $A_{i,t}=\exp(\tilde S_{i,t}-m_i)/l_i$. Дальше в курсе: FA убирает квадратичную память, но не квадратичные вычисления — их лечит разреженное внимание (5.3); в ЛР3 требуется собственный Triton-кернел FA с подбором размеров блоков.

Где в конспектах: Л4 §2 (сл. 36–50, §2.7–2.8), вопросы 6–8; связь с TP по головам — Л5 §4.3; ограничение по вычислениям — Л6 §6.

Категория 4. Распределённое обучение

4.1. Связь нескольких GPU, устройство ноды GPU. NCCL — что это (кратко), зачем оно нужно?

Тезис. Один GPU упирается в память (параметры, градиенты, состояние оптимизатора, активации) и в скорость: предобучение современной модели — порядка $4{,}8\cdot10^{26}$ FLOPs, на одной H100 это тысячи лет. Нода — сервер с 8 GPU, CPU-сокетами, RAM, PCIe и сетевыми картами; внутри ноды GPU связаны PCIe (медленно, универсально) или NVLink/NVSwitch (быстро), между нодами — Ethernet/InfiniBand через NIC с RDMA. NCCL — библиотека NVIDIA для коллективных коммуникаций между GPU: скрывает топологию, выбирает протокол и алгоритм (Ring внутри ноды, Tree между нодами), и избавляет от ручных point-to-point обменов с их deadlock-ами.

Зачем коммуникации (Л5 §1.1, сл. 3). Два ограничения одного GPU — память и вычисления; оценка лектора «~7600 лет» для $4{,}8\cdot10^{26}$ FLOPs при пике H100 в FP16 ($\approx1979$ TFLOPS по спецификации со структурной разреженностью; проверено в конспекте).

Нода (§1.2, сл. 4): обычно 8 GPU, один-два CPU-сокета (оркестрируют запуск вычислительных и коммуникационных кернелов), RAM хоста (данные; CPU-offloading весов/градиентов при острой нехватке памяти — крайняя мера), PCIe-мост, сетевые карты. NUMA-локальность: каждый сокет «отвечает» за свои 4 GPU, и обмен с памятью хоста и NIC лучше вести через свой сокет.

Внутри ноды (§1.3, сл. 5–6): базовый путь — шина PCIe (через неё же GPU общается с CPU, RAM и NIC); NVLink — быстрая прямая связь пар GPU, подключаемая отдельно от PCIe; NVSwitch — коммутатор, избавляющий от необходимости тянуть NVLink «все со всеми». P2P-доступ позволяет GPU читать память другого GPU напрямую, без копирования через RAM.

Между нодами (§1.4–1.5, сл. 7–8): сеть Ethernet/InfiniBand через NIC. Наивный путь GPU0 → RAM0 → NIC0 → сеть → NIC1 → RAM1 → GPU1 дорог; RDMA (remote direct memory access) отправляет данные от GPU к NIC напрямую. Тысячи нод не соединить «все со всеми» — используют топологии fat-tree (выше уровень — больше связей), dragonfly, torus.

Стоимость (§1.6, сл. 9): $T_{comm}(n)\approx\alpha+n/B$ — задержка плюс объём на пропускную способность; много мелких пересылок — плохо (упор в $\alpha$), лучше объединять их в крупные.

Point-to-point и deadlock (§2.1, сл. 10–11): send/recv между двумя рангами; если GPU-0 ждёт данные от GPU-1, а GPU-1 — от GPU-0, оба ждут бесконечно, причём «падает тихо» — без ошибки, если не настроен таймаут. Поэтому реальные системы строятся на коллективных операциях с фиксированным порядком обмена.

NCCL (§2.3–2.6, сл. 18–23). NVIDIA Collective Communication Library: ранг — участник обучения (приближённо один GPU; локальные ранги внутри ноды и глобальные), коммуникатор — программная группа рангов; NCCL знает топологию кластера и скорость связей, строит коммуникационные каналы (они тоже расходуют вычислительный ресурс SM), выбирает протокол передачи (Simple / LL / LL128 — разный баланс пропускной способности и задержки) и алгоритм: Ring — $O(N)$ шагов, выгоден внутри ноды при быстрой связи; Tree — $O(\log N)$, выгоден между нодами при тысячах рангов, но узлы у корня получают больше данных; иерархический алгоритм совмещает оба. Зачем: чтобы программист вызывал all_reduce, а не писал обмены по кольцу руками и не ловил deadlock-и.

Где в конспектах: Л5 §1 (сл. 3–9), §2.1, §2.3–2.6 (сл. 10–11, 18–23), вопросы 7, 9.

Уточняющие вопросы

«Почему deadlock особенно опасен?» Нет явной ошибки — только зависание, неотличимое от медленной операции без таймаута (Л5, вопрос 7). «Ring или Tree?» Внутри ноды Ring, между нодами Tree — по числу рангов и скорости связи (вопрос 9). «Что такое ранг?» Участник коммуникаций, обычно один GPU; в TP — позиция в группе.

4.2. Коллективные коммуникационные операции: Broadcast, AllGather, AllReduce, ReduceScatter, All2All

Тезис. Broadcast копирует тензор с корневого ранга на все; AllGather собирает у каждого ранга полный тензор из частей всех рангов; AllReduce даёт всем результат редукции (суммы) по всем рангам; ReduceScatter редуцирует и раздаёт каждому только его часть; All-to-All — полный обмен, каждый ранг отправляет разные части всем. AllReduce эквивалентен Reduce + Broadcast и ReduceScatter + AllGather, но как одна операция дешевле, а вариант через ReduceScatter + AllGather распределяет редукцию по рангам вместо одного корневого.

Определения (Л5 §2.2, сл. 12–17). Reduce — результат редукции на одном ранге; Broadcast — $\text{out}[i]=\text{in}[i]$ с корневого ранга на все; Scatter/Gather — раздать части / собрать части на одном ранге; AllGather — каждый ранг хранит часть, в итоге у каждого полный тензор; AllReduce — у всех результат редукции; ReduceScatter — сначала редукция по рангам, затем результат делится, и каждый ранг получает свою часть; All-to-All — каждый ранг посылает разные части всем и получает от всех, самая дорогая операция.

Объединение операций (§2.2, запись 20:03–29:57 — сократический разбор с аудиторией). $\text{AllReduce}=\text{Reduce}\to\text{Broadcast}=\text{ReduceScatter}\to\text{AllGather}$. Последовательное выполнение двух операций дублирует накладные расходы (два запуска, две инициализации, лишние копирования), поэтому AllReduce как единая операция дешевле. Из двух разложений на практике предпочитают второе: в Reduce+Broadcast вся редукция ложится на корневой ранг — узкое место; в ReduceScatter+AllGather каждый ранг считает и хранит свою часть, нагрузка размазана равномерно.

Где что используется. AllReduce — усреднение градиентов в DDP (с bucketing — по мере готовности частей, параллельно с backward) и в конце TP-блока; ReduceScatter — градиенты в ZeRO-2 и после backward в FSDP; AllGather — сбор параметров слоя в FSDP перед вычислением, сбор последовательности перед вниманием при SP; Broadcast — вторая половина разложения AllReduce и нисходящая фаза алгоритма Tree в NCCL; All-to-All — dispatch/combine токенов к экспертам в MoE (Л8 §2.2): каждое устройство одновременно рассылает свои токены по устройствам-адресатам и принимает чужие. Стоимость любой операции — по модели $\alpha+n/B$, поэтому мелкие обмены объединяют.

Как исполняется (§2.6, сл. 21–23): алгоритмы Ring (данные обходят все $N$ рангов, $O(N)$) и Tree ($O(\log N)$, но корень перегружен), выбор делает NCCL по топологии; протоколы Simple/LL/LL128.

Где в конспектах: Л5 §2.2, §2.6 (сл. 12–17, 21–23), вопросы 1, 2, 9; All-to-All в MoE — Л8 §2.2, вопрос 6.

Уточняющие вопросы

«Как из Reduce и Broadcast получить AllReduce?» Reduce на корневой ранг, затем Broadcast результата всем; вопрос звучал на лекции (22:08). «Почему ReduceScatter+AllGather лучше?» Редукция делится между рангами, корневого узкого места нет (вопрос 2). «Какая операция самая дорогая?» All-to-All — полный обмен «каждый с каждым».

Ловушки

В списке вопросов операция названа «All2All» — это All-to-All (в глоссарии Л5 — AllToAll). Не путать Gather (на одном ранге) и AllGather (у всех). AllReduce «= Reduce + Broadcast» — равенство результата, но не стоимости.

4.3. Параллелизм данных: DDP, ZeRO-1/2/FSDP

Тезис. В DDP батч делится между рангами, параметры реплицированы, локальные градиенты усредняются AllReduce, чтобы реплики не разошлись; AllReduce прячут под backward (bucketing). Репликация параметров, градиентов и состояния оптимизатора избыточна по памяти — ZeRO шардирует их постадийно: ZeRO-1 — состояние оптимизатора, ZeRO-2 — плюс градиенты (ReduceScatter вместо AllReduce), ZeRO-3 = FSDP — плюс сами параметры (AllGather слоя перед вычислением, ReduceScatter после backward). Чем глубже стадия, тем меньше памяти на ранг и тем больше коммуникаций.

DDP (Л5 §3.1, сл. 25). На ранге $i$ считается лосс $\mathcal L_i^{(t)}=\mathcal L_{w_t}(B_i)$ по своей части батча и градиент $g_i^{(t)}=\nabla_{w_t}\mathcal L_i^{(t)}$; активации и лоссы на рангах разные — это нормально, но разные градиенты по параметрам рассинхронизировали бы реплики, поэтому перед шагом оптимизатора градиенты усредняют через AllReduce и все ранги делают одинаковый шаг. Bucketing: AllReduce запускается не после всего backward, а по мере готовности «бакетов» градиента, параллельно с вычислением следующих слоёв — коммуникация прячется под вычисления (на профиле — отдельный communication stream). В списке вопросов это «DPO» — по смыслу DDP.

Память на параметр (§3.2, сл. 26–27). В смешанной точности с Adam: 2 байта fp16-вес + 2 байта fp16-градиент + $K=12$ байт (fp32-копия веса, momentum, variance) = 16 байт. Для $\Psi=7{,}5$ млрд параметров: baseline (ZeRO-0 = DDP) — 120 ГБ на ранг. Состояние оптимизатора — самое тяжёлое (8 из 16 байт), с него и начинают.

ZeRO-1 ($P_{os}$): шардируется только состояние оптимизатора; после обычного AllReduce градиентов каждый ранг обновляет свою часть параметров, затем актуальные параметры собираются — 31,4 ГБ в примере. ZeRO-2 ($P_{os+g}$): дополнительно шардируются градиенты — вместо AllReduce используется ReduceScatter, каждый ранг сразу получает и хранит только свою часть градиента — 16,6 ГБ. ZeRO-3 = FSDP ($P_{os+g+p}$, §3.3, сл. 28): шардируются и параметры; перед вычислением слоя его параметры собираются AllGather и сразу после освобождаются («чтобы посчитать слой 1, не нужно держать веса слоя 10»), после backward градиенты раскладываются ReduceScatter — 1,9 ГБ. Плата — гораздо больше коммуникаций и нагрузка на сеть; отсюда же правило «FSDP с конвейерным параллелизмом — только на ZeRO-1» (§6). Числа проверены в конспекте по формулам слайда.

Практика. Первая реализация FSDP в PyTorch была медленной из-за лишних синхронизаций и копирований; FSDP-2 переведена на CUDA-события (ответ лектора, 01:49:06). Параллелизм данных — последняя, «внешняя» ось в иерархии 5D (§7): DP масштабируется на любое число нод, потому что его единственная коммуникация — усреднение градиентов раз в шаг.

Где в конспектах: Л5 §3 (сл. 25–28), вопрос 8; иерархия — §7; состояние оптимизатора — Л1 §4.5.

Уточняющие вопросы

«Какая проблема при backward, если на рангах разные активации и лоссы?» Опасны разные градиенты по параметрам, а не по активациям — реплики разойдутся без AllReduce (вопрос студента, 44:40). «Что шардирует каждая стадия ZeRO?» 1 — состояние оптимизатора, 2 — плюс градиенты, 3 — плюс параметры (Л5, вопрос 8). «Почему в FSDP ReduceScatter и AllGather идут подряд?» ReduceScatter закрывает backward текущего слоя, AllGather готовит параметры следующего (57:27).

Ловушки

16 байт на параметр — это mixed precision с Adam; в чистом fp32 с SGD цифры другие. ZeRO-3 и FSDP — одно и то же (FSDP — реализация в PyTorch). Не смешивать «параллелизм данных» и «мини-батч»: DP делит один батч между устройствами, шаг остаётся одним.

4.4. Идеи тензорного параллелизма, контекстного параллелизма, конвейерного параллелизма

Тезис. Тензорный параллелизм делит вычисление одного слоя между рангами по столбцам и строкам матрицы весов (в FFN — столбцы, затем строки, один AllReduce на блок; во внимании — по головам); его коммуникации тяжёлые и не прячутся, поэтому TP держат внутри ноды (TP ≤ 8), а Dropout/LayerNorm параллелят по последовательности (SP). Контекстный параллелизм делит длинный контекст между рангами: Ring Attention гоняет блоки $K,V$ по кольцу, Zig-Zag выравнивает нагрузку под причинной маской. Конвейерный параллелизм режет модель по слоям на стадии; расписания AFAB → 1F1B → interleaved/DualPipe/Zero Bubble уменьшают простой («пузырь»).

TP (Л5 §4, сл. 30–35). Два свойства умножения матриц: по столбцам $A[B_1\,B_2]=[AB_1\,AB_2]$ — каждый ранг считает свои столбцы выхода (входные активации дублируются, веса делятся), по строкам — вход делится по столбцам, веса по строкам, частичные произведения складываются AllReduce. В FFN первый слой параллелят по столбцам, второй по строкам: промежуточного сбора не нужно, потому что активация применяется поэлементно к шардированному выходу первого слоя локально; единственная коммуникация блока — один AllReduce в конце (вопрос студентки Полины, 01:07:59). Во внимании делят по головам (32 головы → по 16 на GPU): ядро FlashAttention принимает произвольное число голов, головы независимы, результат тот же; выходная проекция — по строкам. Коммуникации TP стоят на критическом пути каждого слоя и не прячутся под вычисления, поэтому TP ≤ 8 — внутри ноды по самой быстрой связи. SP (сл. 35): Dropout и LayerNorm между TP-блоками делятся по последовательности, $\text{rank(SP)}=\text{rank(TP)}$; перед вниманием последовательность собирается AllGather. AsyncTP (устно, 01:51:00) сокращает часть синхронизаций между TP и SP «сопряжёнными» коммуникациями.

CP (§5, сл. 37–39). Для контекста порядка миллиона токенов активации внимания не помещаются на один GPU: контекст делится между рангами, каждый хранит свой блок запросов $Q_i$ и на каждом шаге кольца получает очередной блок $(K_j,V_j)$ от соседа, накапливая статистики внимания по всем блокам (как online-softmax во Flash Attention). Под причинной маской нагрузка несбалансирована: ранг с ранними токенами считает маленький треугольник, с поздними — почти всю строку (1:2:3:4 на 4 ранга). Zig-Zag Ring Attention даёт каждому рангу два несмежных куска (самый ранний и самый поздний), тяжёлые и лёгкие треугольники компенсируются — нагрузка выравнивается (проверено в конспекте); для более сложных масок (как «бочная» маска ЛР2) баланс достигается хуже. Потолок CP — число пересылок по кольцу растёт с рангом.

PP (§6, сл. 41–43). Мотивация: у TP потолок 8, у CP свой, FSDP с PP работает только на ZeRO-1. Модель делится по слоям на $P$ стадий, $f(x)=s_P(\dots s_1(x))$, каждая стадия хранит только свои слои; активации передаются point-to-point. AFAB (All-Forward-All-Backward): сначала forward по всем стадиям, потом backward в обратном порядке — большой «пузырь» простоя. 1F1B: батч разбит на микробатчи, backward для готовых микробатчей начинается, не дожидаясь forward по всем, — простой заметно меньше ценой сложного расписания. Дальше — interleaved pipeline (несколько виртуальных стадий на ранг), DualPipe, Zero Bubble Pipeline — стремятся убрать пузырь ценой сложности реализации.

Иерархия 5D (§7, сл. 45–50; Л8 §2.6): TP (внутри ноды, ≤8) → CP (желательно внутри ноды, часто CP·TP > 8) → SP = TP·CP → EP (эксперты по устройствам, All-to-All) → PP (между нодами, стадии по слоям) → DP (внешняя ось, любое число нод). Порядок задаётся тяжестью коммуникаций: самые тяжёлые — на самую быструю связь.

Где в конспектах: Л5 §4 (сл. 30–35), §5 (сл. 37–39), §6 (сл. 41–43), §7 (сл. 45–50), вопросы 3–6, 10; EP — Л8 §2.

Уточняющие вопросы

«Где ставить активацию при TP в FFN и почему без лишней коммуникации?» На шардированном выходе первого слоя; она поэлементная (Л5, вопрос 3). «Почему FlashAttention не ломается при TP по головам?» Ядро работает над любым числом голов (вопрос 4). «Почему TP не выносят за ноду?» Коммуникации на критическом пути, межнодовая связь медленнее (вопрос 6). «Чем Zig-Zag отличается от Ring?» Несмежные куски выравнивают нагрузку под causal-маской (вопрос 5).

Ловушки

На сл. 32 (TP в FFN) числовой пример нарисован так, будто $Y2_k=Y1_k\cdot W2_k$, а числа на схеме соответствуют произведению $k$-го столбца $X$ на $W2_k$ — иллюстрация внутренне несогласована, идея верна (Л5 §4.2, проверено расчётом). Zig-Zag не универсален для нетреугольных масок. Zero Bubble Pipeline «убирает пузырь полностью» лишь ценой реализации, которую лектор назвал очень сложной.

Категория 5. Архитектура LLM

5.1. Улучшение архитектуры трансформера: Pre-norm vs Post-norm, Gated Linear Unit (на примере SwiGLU). Позиционное кодирование

Тезис. В оригинальном трансформере нормализация стоит после сложения с остаточной связью (post-norm) — тогда в градиенте каждого блока появляется множитель меньше единицы, и глубокая сеть затухает. Pre-norm переносит LayerNorm внутрь ветви, оставляя остаточную «магистраль» с производной 1, но не ограничивает рост активаций — в пониженной точности это грозит нестабильностью; компромисс — sandwich-norm и дешёвый RMSNorm. GLU заменяет фиксированное правило активации обучаемым шлюзом: $\mathrm{GLU}(x)=f(xW_1)\otimes(xW_2)$, SwiGLU берёт $f=\mathrm{SiLU}$. Позиционное кодирование эволюционирует от абсолютного к относительному и RoPE (см. 2.2).

Post-norm (Л6 §1.1, сл. 3): $y=\mathrm{LayerNorm}(x+f(x))$. Производная выхода по входу раскладывается на произведение производных LayerNorm (почти не затухают) и множитель $\bigl(1+\partial\mathrm{FFN}/\partial z+\partial\mathrm{MHA}/\partial x\bigr)$, в котором слагаемые с производными подслоёв затухают слабее или сильно; при десятках слоёв произведение таких множителей по сети скорее меньше единицы. Оригинальный трансформер был неглубок, и этого хватало; ЛР2 использует именно post-norm.

Pre-norm (§1.2, сл. 4): $y=x+f(\mathrm{LayerNorm}(x))$, $\partial x/\partial x=1$ — остаточная связь без дополнительных множителей. Но активации внутри остаточных связей ничем не ограничены и растут от слоя к слою, а у чисел с плавающей точкой чем больше модуль, тем крупнее шаг округления — в bf16/fp8 ошибка округления может развалить обучение (лектор довёл аудиторию до этого ответа наводящими вопросами, 03:43–08:12). Sandwich-norm (§1.3, сл. 5): $y=x+\mathrm{LayerNorm}[f(\mathrm{LayerNorm}(x))]$ — нормируется и вход, и выход блока, ценой двух редукций вместо одной. RMSNorm (§1.4, сл. 6): $$\mathrm{RMSNorm}(x)=\gamma\,\frac{x}{\sqrt{\tfrac1d\sum_{i=1}^dx_i^2+\varepsilon}}$$ — без вычитания среднего (на одну редукцию меньше, а GPU плохо справляются с редукциями) и без параметра смещения, только масштаб $\gamma$.

Gated FFN (§2, сл. 8–9). Любая активация — шлюз, решающий, что пропустить, а что подавить; у ReLU и подобных правило фиксировано (по знаку). GLU делает шлюз обучаемым, добавляя ещё один линейный слой: $\mathrm{GLU}(x)=f(xW_1)\otimes(xW_2)$ — шлюз $f(xW_1)$ не зануляет значения $xW_2$ полностью, а ослабляет, сохраняя градиент. SwiGLU: $\mathrm{SiLU}_{\beta=1}(x)=x\sigma(x)$, $\mathrm{SwiGLU}(x)=\mathrm{SiLU}(xW_1)\otimes(xW_2)$; при $\beta\to\infty$ SiLU переходит в ReLU, так что GLU-семейство — обобщение классических активаций. В FFN-блоке MoE-лекции то же записано как $\mathrm{Swish}_\beta(xW_{gate})\odot(xW_{value})$ (Л8 §1.2).

Позиционное кодирование (§3, сл. 11–14) — кратко, подробно в 2.2: синусоидальное абсолютное (уникальность + линейный сдвиг), обучаемое абсолютное (таблица, не масштабируется, «тихо» ломается за пределами контекста), относительное ($a_{ij}$ внутри оценки внимания), RoPE (поворот пар координат на угол $p\omega_k$, в $QK^{\top}$ остаётся разность позиций; без параметров).

Где в конспектах: Л6 §1 (сл. 3–6), §2 (сл. 8–9), §3 (сл. 11–14), вопросы 1–6; исходная схема слоя — Л2 §3.2–3.5.

Уточняющие вопросы

«Почему post-norm вообще использовали?» Неглубокий оригинальный трансформер, затухание не критично (Л6, вопрос 1). «При чём здесь пониженная точность?» Шаг округления растёт с модулем числа — неограниченные активации pre-norm теряют точность (вопрос 2). «Чем RMSNorm дешевле?» Нет редукции для среднего и нет параметра смещения (вопрос 3). «Чем GLU отличается от ReLU концептуально?» Обучаемый шлюз вместо фиксированного правила (вопрос 4).

5.2. Гиперсвязи, динамические гиперсвязи, mHC

Тезис. Гиперсвязи заменяют одну остаточную связь на $R$ параллельных: вход агрегируется весами $H^{\text{pre}}$, обрабатывается блоком $f$, результат дезагрегируется $H^{\text{post}}$ и смешивается с потоками через $H^{\text{res}}$. Статические матрицы схлопываются при укладке слоёв и не адаптируются к входу; динамические делают их функциями входа через $\tanh$, но произведение неограниченных $H^{\text{res}}$ по слоям может экспоненциально раздуть активации. mHC ограничивает многообразие: $H^{\text{res}}$ — дважды стохастическая матрица через $\exp$ и алгоритм Синкхорна–Кноппа, $H^{\text{pre}},H^{\text{post}}$ — через сигмоиду, причём $H^{\text{post}}$ с множителем 2, чтобы на старте вести себя как обычная остаточная связь.

Гиперсвязи (Л6 §4.1, сл. 16–17). Хранить $R$ параллельных остаточных потоков и обрабатывать блоком каждый по отдельности дорого; вместо этого — агрегация $\hat x=\sum_{i=1}^Rh_i^{\text{pre}}x_i$, обработка $f(\hat x)$, дезагрегация по потокам $h^{\text{post}}$ и смешивание потоков: $$y=H^{\text{res}}x+H^{\text{post}}f\bigl[H^{\text{pre}}x\bigr].$$ Обычная остаточная связь — частный случай $R=1$.

Две проблемы статических гиперсвязей (§4.2, сл. 17–18): (а) при укладке слоёв подряд без нелинейности линейные $H$ схлопываются в одну операцию; (б) они не адаптивны к входу. Динамические гиперсвязи: параметры делятся на статические и зависящие от входа, добавляется $\tanh$: $$H^{\text{pre}}(x)=\alpha^{\text{pre}}\tanh(\theta^{\text{pre}}x^{\top})+b^{\text{pre}},$$ аналогично $H^{\text{post}}$ и $H^{\text{res}}$.

Нестабильность (§4.3, сл. 19–20). Развернув $x_{l+1}=H^{\text{res}}_lx_l+H^{\text{post}}_lf_l[H^{\text{res}}_lx_l]$ до слоя $L$, получаем $x_L=\bigl(\prod_iH^{\text{res}}_{L-i}\bigr)x_l+\dots$: вместо гарантированно устойчивого слагаемого $x_l$ обычных остаточных связей — произведение неограниченных операторов, которое может расти экспоненциально и менять знак; при обучении в FP8 это особенно опасно (запись 43:27–49:38).

Дважды стохастическая матрица и Синкхорн–Кнопп (§4.4, сл. 21–22): все элементы положительны, суммы каждой строки и каждого столбца равны 1 — произведение таких матриц не раздувает нормы. Одноразовая нормализация невозможна: масштабирование строк сбивает столбцы и наоборот; алгоритм Синкхорна–Кноппа поочерёдно нормирует столбцы и строки и за конечное число итераций приближает матрицу к дважды стохастической («судоку на суммы», 49:38–52:05).

mHC — Manifold-Constrained Hyper-Connections (§4.5, сл. 23): $$H^{\text{pre}}=\sigma\bigl(\alpha_l^{\text{pre}}(x_l\varphi_l^{\text{pre}})+b_l^{\text{pre}}\bigr),\qquad H^{\text{post}}=2\sigma\bigl(\alpha_l^{\text{post}}(x_l\varphi_l^{\text{post}})+b_l^{\text{post}}\bigr),\qquad H^{\text{res}}_l=\mathrm{Sinkhorn\text{-}Knopp}\bigl(\exp(\dots)\bigr),$$ сигмоиды вместо $\tanh$ дают положительные ограниченные веса, $\exp$ + Синкхорн–Кнопп — положительность и «стохастичность» $H^{\text{res}}$. Множитель 2: в начале обучения параметры близки к нулю, $\sigma(0)=0{,}5$, и $2\cdot0{,}5=1$ — гиперсвязи стартуют как обычная остаточная связь, а выразительность набирают по мере обучения (54:31–56:54).

Где в конспектах: Л6 §4 (сл. 16–23), вопросы 7–9.

Уточняющие вопросы

«Зачем именно итеративный Синкхорн–Кнопп?» Одновременно выровнять строки и столбцы «в лоб» нельзя, чередование сходится (Л6, вопрос 8). «Зачем 2 перед сигмоидой?» Чтобы при нулевой инициализации $H^{\text{post}}=1$ (вопрос 9). «Почему динамические гиперсвязи нестабильны?» Произведение неограниченных операторов $H^{\text{res}}$ по слоям (вопрос 7).

Ловушки

Слово «стохастическая» здесь — про суммы строк и столбцов, а не про случайность. Гиперсвязи — не второй вид внимания и не MoE; это обобщение остаточной связи.

5.3. Эффективное внимание: проблемы базового self-attention. Разреженное внимание: шаблонное и обучаемое

Тезис. Базовое самовнимание квадратично по длине последовательности и по памяти, и по вычислениям; Flash Attention убирает квадратичную память, но не вычисления, а KV-кэш переносит проблему на память инференса. Разреженное внимание считает не всю матрицу: шаблонное (BigBird) задаёт связи заранее — локальные, глобальные, случайные — блоками, совместимыми с тайлингом FlashAttention; обучаемое (DSA) поручает выбор связей индексатору, который в два этапа учится приближать плотное внимание и затем отбирать top-k позиций; сжатое внимание (CSA, HCA) дополнительно схлопывает соседние токены в один вектор обучаемыми весами.

Проблемы базового внимания. $S=QK^{\top}$ — матрица seq×seq на каждую голову и слой: память $O(n^2)$ (при 150 000 токенов ≈45 ГБ на слой в FP8, Л4 §2.1), вычисления $O(n^2d)$, на инференсе — пересчёт $K,V$ для всех предыдущих токенов (лечится KV-кэшем, 5.4). Flash Attention считает выход блоками без материализации $S$ и $A$ — память становится линейной, вычисления остаются квадратичными (Л6 §6.1, запись 1:05:12).

Шаблонное разреженное внимание (Л6 §6.1, сл. 34). Не все связи одинаково важны: сильнее всего локальные (соседние токены), но нужны и глобальные (несколько токенов, видимых всем), и случайные связи. BigBird комбинирует их по фиксированному, не зависящему от входа шаблону; разрежение делается блоками, а не отдельными элементами — так полностью замаскированные блоки пропускаются в тайлинге FlashAttention, а согласованный доступ к памяти не ломается случайными элементами. Из письменного текста лектора: скользящее оконное внимание с окном $w$ имеет сложность $O(w\cdot n)$. Слабость: шаблон один для всех входов, а разным токенам нужны разные связи.

Обучаемое разреженное внимание — DSA (Л7 §1, сл. 3–7). DeepSeek Sparse Attention: Lightning Indexer считает дешёвую оценку связи текущего запроса $t$ с предыдущими токенами $s$: $$I^{t,s}=\sum_jw_j^t\,\mathrm{ReLU}\bigl(q_j^tk_j^s\bigr),$$ (индексатор дешевле полного внимания и может считаться в более низкой точности — fp8 или даже fp4, сл. 7) и отбирает $s^t=\mathrm{Top}_k(I^{t,:})$ — только на этих позициях считается настоящее внимание. Обучение в два этапа: сначала веса внимания заморожены, индексатор учится приближать распределение плотного внимания — $\mathcal L^I=\sum_tD_{KL}\bigl(p^{t,:}\,\|\,\mathrm{Softmax}(I^{t,:})\bigr)$; затем внимание размораживается, включается top-k, и $\mathcal L^I$ считается уже по отобранному множеству. Сразу с top-k учить нельзя — нет надёжного «эталона» (Л7, вопрос 2).

Сжатое внимание (Л7 §2, сл. 9–16). Сжатие по оси $n$: несколько соседних токенов объединяются в один вектор обучаемыми коэффициентами $s_i=\mathrm{Softmax}(HW^Z)$, а не усреднением; матрицы $S$ и $C$ считаются из исходного $H$, а не из сжатого $C$ — чтобы вычислять их параллельно в одном кернеле; проекции понижают ранг $W=W_{\text{down}}W_{\text{up}}$. CSA (сжатие 4:1) после сжатия ещё применяет DSA; HCA (128:1) в разреженном отборе уже не нуждается — контекст до миллиона токенов.

Где в конспектах: Л6 §6 (сл. 34), вопрос 11; Л7 §1 (сл. 3–7), §2 (сл. 9–16), вопросы 1–4; квадратичная память — Л4 §2.1.

Уточняющие вопросы

«Зачем обучаемое разрежение, если шаблонное уже линейно?» Шаблон не зависит от входа, а разным токенам нужны разные связи (Л7, вопрос 1). «Почему разрежать блоками?» Совместимость с тайлингом FlashAttention и согласованным доступом (Л6, вопрос 11). «В чём разница CSA и HCA?» Только коэффициент сжатия — 4:1 против 128:1 (Л7, вопрос 4).

Ловушки

В старом списке вопросов стояло «sparse attention, sliding-window attention», в новом — «шаблонное и обучаемое»: sliding window в записях есть только как «вне слайдов» из письменного текста Лекции 6. Flash Attention — не разреженное внимание: оно точное и убирает память, а не вычисления.

5.4. KV-кэш. MQA и GQA. MLA

Тезис. При авторегрессионной генерации новый токен смотрит на все предыдущие, а не наоборот, поэтому достаточно посчитать одну новую строку внимания, а $K,V$ прошлых токенов хранить в KV-кэше — вычисления перестают быть квадратичными, но память растёт как batch × seq × слои × головы × 2 × $d_{\text{head}}$ × байт. MQA убирает множитель голов (одна пара $K,V$ на все головы — резкая потеря выразительности), GQA — компромисс через группы голов, MLA сжимает $K,V$ в общий латентный вектор и восстанавливает их для каждой головы линейно, причём проекции «сворачиваются» без потери точности.

Идея (Л6 §5.1, сл. 25–26). При обучении предсказываются все позиции сразу — нужна вся матрица внимания; при инференсе вход $X_{t+1}$ отличается от $X_t$ одним токеном, и из-за треугольной маски достаточно одной новой строки: $K,V$ предыдущих токенов не меняются — их кэшируют. Инференс — это генерация целой последовательности, пересчитывать всё каждый шаг «жалко». Заодно меняется характер вычислений: умножения становятся матрица-на-вектор (GEMV, Л3 §4.3), memory-bound.

Цена (§5.2, сл. 27): $$\mathrm{size}(\text{KV-cache})=\text{batch\_size}\times\text{seq\_length}\times N_l\times N_h\times2\times d_{\text{head}}\times\text{dtype\_size},$$ множитель 2 — отдельно $K$ и $V$; при батчевом инференсе и длинных контекстах — главный потребитель памяти GPU.

MQA (§5.3, сл. 28): $Q_i=XW_{Q,i}$ для каждой головы, но $K=XW_K$, $V=XW_V$ — одна общая пара; кэш меньше в $N_h$ раз, обучение дешевле, но выразительность заметно падает — лектор назвал решение «слишком резким».

GQA (§5.4, сл. 29): головы запросов делятся на группы, у группы $g$ своя пара $K_g=XW_{K,g}$, $V_g=XW_{V,g}$; одна группа — MQA, число групп равно числу голов — обычный MHA; кэш меньше в $N_h/N_{\text{groups}}$ раз.

MLA (§5.5–5.6, сл. 30–32). Multi-head Latent Attention (DeepSeek): $K,V$ не хранятся по головам, а сжимаются в общее латентное представление $L_{KV}=XW_{DKV}$, из которого каждая голова декодирует свои $K=L_{KV}W_{UK}$, $V=L_{KV}W_{UV}$; хранится только $L_{KV}$. Наивно это лишние умножения, но $QK^{\top}=XW_Q(L_{KV}W_{UK})^{\top}=X\bigl(W_QW_{UK}^{\top}\bigr)L_{KV}^{\top}$ — матрицы $W_Q$ и $W_{UK}^{\top}$ перемножаются заранее в $\widetilde W_Q$, аналогично $W_{UV}$ с выходной проекцией в $\widetilde W_O$: меньше операций и параметров без потери точности. Сжатие применяется при обучении с прицелом на память инференса.

Практика. В ЛР4 (инференс) требуется реализовать GQA и KV-кэш для инференса своей модели (при нехватке памяти — уменьшить число групп GQA или использовать CPU offloading), обучить её до перплексии ≤ 40/25 и показать скрипт генерации (методичка ЛР4). Так GQA и KV-кэш из этого вопроса — прямо материал последней лабораторной.

Где в конспектах: Л6 §5 (сл. 25–32), вопрос 10; GEMV — Л3 §4.3; генерация — Л2 §3.13.

Уточняющие вопросы

«Как MQA, GQA и MLA решают проблему памяти и какой ценой?» Множитель голов, группы, латентное сжатие; цена — выразительность (MQA сильно, GQA умеренно, MLA почти без потери) (Л6, вопрос 10). «Почему при генерации достаточно одной строки внимания?» Треугольная маска: новый токен видит прошлые, прошлые его — нет. «Почему GEMV memory-bound?» Мало операций на байт прочитанной матрицы (Л3 §4.3).

В ASR-транскрипте Лекции 6 модель с контекстом в миллион токенов распознана как «DCQ4» — по транскрипту название не восстанавливается, на экзамене конкретную модель лучше не называть.

5.5. Законы масштабирования. Закон Шиншиллы

Тезис. Законы масштабирования — эмпирические степенные зависимости лосса от объёма данных $D$, числа параметров $N$ и компьюта $C$: на лог-лог графике прямая; ниже слагаемого $c$ (энтропия данных) опуститься нельзя. Совместный закон $\mathcal L(N,D)=c+AN^{-\alpha}+BD^{-\beta}$ при $C=C_0ND$ переформулирует bias-variance: параметры снижают bias, данные — variance. Закон Шиншиллы — найденное при фиксированном компьюте оптимальное соотношение $D=20N$ для плотной GPT-подобной архитектуры; для других архитектур (MoE) в исходном виде не работает.

Предпосылки (Л7 §5.1, сл. 29): данные (в том числе через SSL и мультимодальность — текстов в интернете конечное количество), удачно масштабируемая модель (трансформер с улучшениями) и вычислительные мощности с распределённым обучением.

Эмпирические законы (§5.2–5.3, сл. 30–32). Растёт модель при фиксированных данных — лосс падает; растут данные при фиксированной модели — падает; и то и другое — падает сильнее. Зависимости $L\propto X^{-a}$: логарифмируя, $\log L=\log k-a\log X$ — прямая с наклоном $-a$. Пример лектора: увеличение данных в 10 раз снижает лосс с 3,6 примерно до 2,8 (по формуле слайда $D^{-0{,}095}$ получается 2,89). Статья «Scaling Laws for Neural Language Models» (Kaplan и др., OpenAI, 2020) — теоретическое обоснование самой возможности LLM: обучать GPT-3 на 175 млрд решились, потому что закон обещал выигрыш.

Совместный закон (§5.4, сл. 33): $$\mathcal L(N,D)=c+AN^{-\alpha}+BD^{-\beta},\qquad C(N,D)=C_0ND.$$ Слагаемое $c$ не зависит ни от $N$, ни от $D$ — для многих продолжений текста есть несколько правдоподобных вариантов, вероятность 1 недостижима (та же энтропия $H(p)$, что в кросс-энтропии, 1.1).

Bias-variance через масштабирование (§5.5, сл. 34): $\mathrm{bias}\sim N^{-\alpha}$, $\mathrm{variance}\sim D^{-\beta}$, отношение $R(N,D)=\mathrm{variance}/\mathrm{bias}\sim N^{\alpha}D^{-\beta}$: $R\ll1$ — недообучение (модель мала для данных), $R\gg1$ — переобучение. Переход не строго математический, но логически обоснованный.

Закон Шиншиллы (§5.6–5.7, сл. 35–37). При фиксированном компьюте $C\sim ND$ ищут $D=f(N)$, дающее оптимальное $R$: строят кривые лоссов для моделей одной архитектуры разного размера на разных объёмах данных; оптимальные $N$ и $D$ от компьюта — обе прямые на лог-лог, откуда $D=20N$ (20 токенов на параметр; по модели Chinchilla, DeepMind). По письменному конспекту лектора: $\alpha=0{,}34$, $\beta=0{,}28$, $A=406{,}4$, $B=410{,}7$, $C_0=6$; GPT-3 175B обучали при $D\approx1{,}7N$ — сильно «недокормленно». Не железное правило: соотношение зависит от архитектуры; для MoE не работает в исходном виде, потому что общее число параметров растёт почти без роста компьюта на токен (активна лишь часть экспертов) — лектор прямо назвал это темой следующей лекции; сам он отметил, что «закон Шиншиллы сейчас не очень актуален».

Где в конспектах: Л7 §5 (сл. 29–37), вопросы 10–11; bias-variance — Л1 §5.2.

Уточняющие вопросы

«Почему степенной закон — прямая?» Логарифмирование обеих частей (Л7, вопрос 10). «Почему лосс не уходит в ноль?» Слагаемое $c$ — энтропия данных. «Почему $D=20N$ не работает для MoE?» Связь $C=C_0ND$ предполагает один $N$, отвечающий за все вычисления; у MoE активная часть меньше общей (вопрос 11).

Приложение. MoE (вопрос 6 категории «Архитектура LLM» из списка OLD, в NEW убран)

MoE — Mixture of Experts

Тезис. FFN-блок — «база знаний» модели: столбцы $W_1$ — семантические концепции, активация зануляет нерелевантные сопоставления, значит в плотном FFN большая часть вычислений бесполезна. MoE разбивает широкий FFN на много узких экспертов, а маршрутизатор для каждого токена выбирает top-k релевантных — общее число параметров растёт на порядки при почти том же компьюте на токен. Обучаемость роутера обеспечивается взвешиванием выходов экспертов его вероятностями; мелкозернистые и общие эксперты уточняют специализацию; экспертный параллелизм раскладывает экспертов по устройствам через All-to-All; балансировку нагрузки обеспечивают ёмкость эксперта, auxiliary loss или смещение при отборе.

Роль FFN (Л8 §1.1–1.4, сл. 3–6). Внимание добавляет в токен контекст остальных токенов, но для генерации нужны ещё знания о мире, заложенные в весах, — их извлекает FFN: $z_1=xW_1$ проецирует токен в пространство большей размерности, каждый столбец $W_1$ — выученная концепция, скалярное произведение — релевантность токена концепции; активация отсеивает нерелевантное; $y=z_2W_2$ возвращает в исходную размерность, столбцы $W_2$ — «кодировщики» найденных соответствий. В современных моделях активация — SwiGLU: $\mathrm{Swish}_\beta(xW_{gate})\odot(xW_{value})$.

Потолок и разреженность (§1.5–1.7, сл. 7–9). Чтобы модель «знала больше», нужно больше концепций — шире $W_1,W_2$, больше вычислений и памяти. Но конкретный токен не соответствует всем концепциям сразу: нерелевантные всё равно зануляются — вычисления впустую. Решение — разбить FFN на множество экспертов, каждый проецирует не в десятки тысяч, а в сотни–тысячу измерений; для токена активируется лишь несколько релевантных экспертов — разреженность. Обозначение «total–active» (например, 235B-A22B: 235 млрд всего, 22 млрд активных на токен).

Маршрутизатор и дифференцируемость (§1.8–1.9, сл. 10–11). Роутер — линейный слой, дающий логиты по экспертам (задача классификации); выбираются $k$ наибольших. Top-k недифференцируем, поэтому выход каждого выбранного эксперта домножается на вероятность роутера: $$y=\sum_{i\in\mathrm{TopK}(p)}E_i(x)\cdot p_i(x),$$ и Softmax считается только по логитам отобранных экспертов — если брать Softmax по всем, а потом отсеивать, сумма вероятностей отобранных окажется меньше 1 и занизит сигнал; порядок top-k по логитам и по вероятностям совпадает (монотонность Softmax).

Мелкозернистые и общие эксперты (§1.10, сл. 12). Fine-grained MoE — много узких экспертов (например, 256 при top-8) для точной специализации при том же бюджете параметров; общие (shared) эксперты — 1–2 всегда активных, берущих на себя универсальную информацию (язык токена и т. п.), чтобы routed-эксперты не дублировали её и специализировались точнее. По отчёту DeepSeek-V3: 256 routed (top-8) + 1 shared, то есть 9 активных из 257; 671 млрд параметров всего, 37 млрд активных.

Экспертный параллелизм (§2.1–2.2, сл. 13–14). Веса разных экспертов размещают на разных устройствах: не нужно хранить всех экспертов на одном GPU (можно наращивать их число), и каждое устройство считает FFN только для «своих» токенов. Dispatch — пересылка токенов к устройствам с назначенными экспертами, combine — возврат результатов на исходные устройства в исходном порядке с весом из роутера; обе операции — All-to-All (каждое устройство одновременно рассылает и принимает). По письменному конспекту: перед отправкой — local permute (группировка по целевому устройству), на устройстве — grouped GEMM (несколько GEMM разного размера одним кернелом без паддинга).

Ёмкость и балансировка (§2.3–2.5, письменный конспект + запись). $\mathrm{Capacity}(E)=\lfloor\frac{T\cdot k}{N_{\text{experts}}}\cdot C\rfloor$ — максимум токенов на эксперта за батч; $C=1$ — «в среднем достаточно», без запаса, лишние токены не обрабатываются; $C\gt1$ — запас ценой буферов. Без регулирования дисбаланс самоусиливается: эксперт, получивший больше токенов, лучше учится, роутер направляет туда ещё больше (36:13). Auxiliary loss $\mathcal L_{LB}=\alpha N\sum_if_iP_i$ (доля назначенных токенов × доля вероятностей) минимален при равномерности, но при большом $\alpha$ конфликтует с основной задачей — «проблема инженерная». Метод DeepSeek без auxiliary loss: к оценкам роутера добавляется смещение $b_i$ (растёт для недогруженных, падает для перегруженных), которое влияет только на отбор top-k, а вес вклада эксперта берётся из несмещённой оценки — балансировка «снаружи» лосса, без мешающих градиентов.

Пятое измерение (§2.6, сл. 15): EP — пятая ось параллелизма рядом с TP/CP/PP/DP; сочетание EP+TP невыгодно — эксперты и так узкие, а коммуникации TP ложатся поверх тяжёлых All-to-All. Закон Шиншиллы для MoE в исходном виде не работает (5.5).

Уточняющие вопросы

«Почему top-k по логитам, а не по вероятностям?» Softmax по всем экспертам с последующим отсевом занижает результат (Л8, вопрос 2). «Зачем shared-эксперты?» Иначе универсальная информация дублируется во всех routed-экспертах (вопрос 4). «Что означает 90B-5A?» Общий и активный размер (вопрос 3). «Почему EP+TP невыгодно?» Узкие эксперты, лишние коммуникации (вопрос 5).

Ловушки

«256 экспертов, 8 активных» на слайде относится к DeepSeek в целом; по отчёту V3 точнее — 256 routed + 1 shared, 9 из 257 активных. Формула балансировки DeepSeek в письменном конспекте изложена через сигмоиду вместо Softmax; по первоисточнику смещение $b_i$ участвует только в отборе, не в весе (Л8 §2.5). Auxiliary loss — не часть модели, а инженерная добавка к обучению.
