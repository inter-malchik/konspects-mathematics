§1. Токенизация (сл. 3–13)

1.1. Зачем нужна токенизация (сл. 3)

Нейронные сети работают с числовыми тензорами, а не с текстом в «сыром» виде (тип данных string). Значит, текст нужно преобразовать в тензор. Для этого исходный сплошной текст разбивают на части — токены; сам процесс разбиения называется токенизацией (сл. 3).

Из записи лекции [07:42–08:55]

Лектор анонсирует лекцию целиком: путь от сырого текста до задачи предсказания следующего токена. Дальше — к самой токенизации: текст в типе string нейросеть не обрабатывает, потому что сети «заточены» под числовые тензоры; текст нужно разбить на токены — это и есть токенизация.

На пальцах

Токенизация — как разложить предложение по ячейкам для сортировки: пока текст — сплошная строка символов, компьютер не может присвоить ему числа для арифметики; разбив на «кусочки» (буквы, части слов или целые слова), каждому кусочку можно сопоставить номер, а дальше — вектор.

1.2. Посимвольная токенизация (сл. 4)

Идея: разбить текст на отдельные символы. Преимущества: малый словарь; хорошо подходит для иероглифических языков. Недостатки: очень длинная итоговая последовательность (сл. 4).

Рисунок (сл. 4). Таблица кодировки (фрагмент UTF/ASCII): столбцы Dec, Hex, UTF-8 Hex, Char, Description — построчно перечислены символы вроде «(», «)», цифры 0–9, заглавные латинские буквы с их числовыми кодами; иллюстрирует идею «словарь = таблица кодировки».
Из записи лекции [08:55–10:26]

Первое, что приходит в голову для разбиения текста — разбить его на символы. Главное преимущество — малый словарь; хорошо подходит для иероглифических языков (для них само утверждение о «малом» словаре уже не совсем корректно, но словарь всё равно будет меньше, чем при токенизации по словам). Главный недостаток — очень длинная последовательность: в большом текстовом документе число символов может достигать нескольких миллионов, а такую последовательность тяжело «запихнуть» в нейросеть.

На пальцах

Для русского текста «Привет, мир!» посимвольно получится 12 токенов (включая пробел и знаки препинания) — почти в 2 раза больше, чем токенов-слов («Привет», «,», «мир», «!» — 4 токена), при словаре из полусотни букв и знаков вместо десятков тысяч слов.

1.3. Токенизация по словам (сл. 5)

Идея: разбить текст по словам. Преимущество: малая длина последовательности. Недостаток: огромный размер словаря, так как каждая форма слова (падеж, окончание) — отдельный токен; особенно критично для русского языка (сл. 5).

Рисунок (сл. 5). Пример конвейера: предложение «Посимвольная токенизация приводит к очень большой длине входной последовательности.» → токенизация по словам даёт список токенов («Посимвольная», «токенизация», «приводит», «к», «очень», «большой», «длине», «входной», «последовательности», «.») → преобразование в индексы даёт список чисел (1523, 4872, 3157, 151, 326, 5156, 892, 911, 7241, 13).
Из записи лекции [10:26–11:20]

Второй способ — токенизация по словам: делить текст на слова. Преимущество — гораздо меньшая длина последовательности, чем при разбиении на символы. Недостаток — огромный размер словаря, так как любая форма слова записывается как отдельный токен, даже если отличие — только в окончании; особенно эта проблема характерна для русского языка.

На пальцах

«Слово», «слова», «словом», «словами» — для человека одно и то же слово в разных падежах, а для словаря по словам — 4 разных токена с четырьмя разными строками в embedding-таблице; умножьте это на число падежей, чисел и склонений русского языка — и словарь распухает до сотен тысяч–миллионов записей.

1.4. BPE: идея компромисса и стартовый словарь (сл. 6)

Есть две крайности — токенизация по символам и по словам. BPE (Byte-Pair Encoding) — компромиссный вариант, сочетающий их преимущества. Задаётся стартовый словарь: символы алфавита и специальные токены <PAD>, <BOS>, <EOS>, <UNK> (сл. 6).

Из записи лекции [11:20–12:21]

Раз есть две крайности, попробуем найти что-то вроде компромисса. Зададим словарь: сначала в него помещают символы начального алфавита (например, только русские буквы, если токенизатор обучается на русских текстах, либо символы UTF-кодировки для мультиязычного токенизатора), затем добавляют специальные токены: паддинга, начала последовательности/текста, конца последовательности/текста и токен для замены всех неизвестных элементов.

На пальцах

<PAD> — «пустая клетка» для выравнивания коротких последовательностей в батче под общую длину; <BOS>/<EOS> — «начало» и «конец» текста, как открывающая и закрывающая кавычки; <UNK> — универсальная «заглушка» для всего, чего нет в словаре.

1.6. От merge-правил до итогового словаря; токенизация нового текста (сл. 10–11)

Частоты пар вычисляются до достижения желаемого размера словаря. Поскольку алфавит уже в словаре, часть будущих токенов неизбежно окажется подстроками других — для этого и хранят merge-правила: новый текст не ищут по словарю «с нуля», а последовательно применяют выученные merge-правила в том порядке, в котором они были записаны при обучении (сл. 10–11).

Из записи лекции [13:25–23:01]

Раз в начале в словарь уже добавлен весь начальный алфавит, любые новые токены, которые в него допишут, обязательно будут состоять из подстрок уже имеющихся элементов; если токенизировать текст поиском первой попавшейся подстроки в словаре, рано или поздно текст «развалится» обратно до посимвольного разбиения. Поэтому к новому тексту применяют не поиск по словарю, а сами merge-правила — последовательно, в порядке обучения: первое выученное правило (объединение e+n) применяется первым, следующее (допустим, en+c) — вторым, и так далее.

На пальцах

Обучение BPE — это как коллекционирование самых частых «выгодных» слияний: сначала есть только буквы, а каждое новое merge-правило — это купленный «набор» из двух более мелких элементов. Применяя набор правил по порядку покупки к новому тексту, вы гарантированно можете «собрать» любое слово хотя бы из букв — просто где-то сборка остановится раньше (получится более крупный токен), а где-то — позже.

1.7. Byte-level BPE (сл. 12)

Если текст мультиязычный или содержит эмодзи, стартовый словарь символов может стать огромным. Решение — перевести текст в последовательность байт (через UTF-кодировку) и применять BPE уже к байтам, а не к буквам (сл. 12).

Из записи лекции [23:01–24:09]

Эмодзи очень много и появляются новые постоянно, поэтому стартовый словарь символов легко «взрывается». Решение — кодировка UTF: перевести текстовую последовательность в последовательность байт и в дальнейшем выучивать и применять merge-правила уже не к буквам, а к байтам — записывая итоговый словарь как словарь байт.

На пальцах

Байт — «алфавит» ровно из 256 возможных значений, независимо от языка; это как если бы вместо алфавитов десятков языков и тысяч эмодзи-символов у вас был один универсальный набор «кирпичиков», из которого механизм BPE-склейки уже сам собирает всё нужное.

1.8. Embedding-слой: от индекса к вектору, семантическое пространство (сл. 13)

Словарь — это таблица «текстовый токен → индекс». Индексы уже числа, но нейросети всё ещё неудобно работать с одним числом на токен: индексы создают ложный «псевдопорядок» между токенами (сл. 13). Решение — обучаемая таблица «индекс → вектор», embedding-слой: матрица, где номер строки — индекс токена, а сама строка — обучаемый вектор этого токена.

Рисунок (по записи, доска «Лекция 2»; таймкод ≈27:00–27:45; на слайде 13 этого рисунка нет). От руки: токены tok, en, a с индексами 28, 411, 29 в столбик; справа — таблица embedding-слоя, где строке с индексом 28 сопоставлен вектор вида (1.0, 0.82, −0.7, …), аналогично для строк 29 и 411; рядом — набросок формулы косинусной близости $\cos(\widehat{a,b})=\langle a,b\rangle/(|a||b|)=\sum_i a_ib_i/(|a||b|)$.
Из записи лекции [24:09–33:39]

Индексы — уже числа, но если просто подавать их в сеть напрямую, между токенами закладывается ложное отношение порядка: если ток=28, a=29, en=411, из самих чисел следует, что «ток» меньше «a», а «a» меньше «en» — хотя семантически это бессмысленно. Поэтому строится embedding-слой: обучаемая матрица, строка которой — вектор, а номер строки — индекс токена.

Важная деталь — размерность этих векторов обычно зависит от размера итоговой модели (чем больше модель, тем больше размерность скрытого пространства); чётких теорем на этот счёт нет, есть в основном эмпирически подобранные значения, которые лектор пообещал уточнить дополнительно и написать в беседе.

Приятное свойство обучаемого embedding-слоя: токены, часто встречающиеся в похожих контекстах (близкие по смыслу), получают близкие вектора. Близость двух векторов $a,b$ измеряется косинусной близостью — отношением скалярного произведения к произведению норм, $\cos(\widehat{a,b})=\langle a,b\rangle/(|a||b|)$; чем меньше угол между векторами, тем больше косинусная близость.

В таком пространстве работает «векторная арифметика»: если взять токен «король», вычесть вектор «мужчина» и прибавить вектор «женщина», получится вектор, близкий к вектору «королева» (известный пример). Пространство эмбеддингов с таким свойством называется семантическим пространством.

Вопрос студента (28:49): как строятся эти векторы и как выбирается их размер? Ответ лектора приведён выше (размерность эмпирически связана с размером модели, точных формул лектор не привёл).

На пальцах

Мини-пример на числах: пусть векторы «король» $\approx(0{,}9,\,0{,}1)$, «мужчина» $\approx(0{,}8,\,0{,}0)$, «женщина» $\approx(0{,}1,\,0{,}9)$. Тогда «король» − «мужчина» + «женщина» $\approx(0{,}2,\,1{,}0)$ — вектор с маленькой первой и большой второй компонентой, то есть «похожий на женщину, но статусный» — качественно это и есть направление на «королеву».

Переходим к механизму внимания — основе трансформера, начиная с задачи seq2seq: преобразование одной последовательности в другую, например перевод или ответ чат-бота на вопрос. Раньше эта задача решалась рекуррентными сетями — RNN, LSTM, GRU — в архитектуре кодировщик-декодировщик.

На пальцах

Seq2seq — «вход-последовательность → выход-последовательность произвольной, вообще говоря другой длины»: 3 английских слова могут перевестись в 4 французских, вопрос из 5 слов — получить ответ из 20.

2.2. Архитектура кодировщик-декодировщик (сл. 16)

Кодировщик кодирует входную последовательность в скрытое латентное представление $H$; декодировщик, принимая $H$ и уже сгенерированную часть последовательности, генерирует следующий токен. Генерация — авторегрессионная: начинается с токена <BOS>, заканчивается на <EOS> (сл. 16).

Рисунок (сл. 16). «Архитектура LSTM кодировщик-декодировщик». Слева Encoder — три блока LSTM, принимающие на вход токены I, love, cats, последнее скрытое состояние $h_t$ (кружок) передаётся вправо. Справа Decoder — четыре блока LSTM: первый принимает <BOS> и $h_t$, дальше цепочка получает на вход уже сгенерированные токены j'aime, les, chats и генерирует на выходе j'aime, les, chats, <EOS> (последний токен выделен зелёным).
Из записи лекции [34:41–36:55]

Кодировщик пробегает по всем элементам входной последовательности и получает скрытое состояние $H$, которое передаётся декодировщику. Декодировщик стартует с токена begin-of-sentence: на LSTM подаётся этот токен и скрытое состояние из кодировщика, LSTM генерирует новый элемент выходной последовательности, этот элемент добавляется на вход декодировщика, шаг повторяется — и так до токена end-of-sentence. Такой способ генерации токен за токеном называется авторегрессионным.

Важно: информация о порядке токенов в этой архитектуре закладывается не явно, а через индуктивный байес — LSTM обрабатывает входную последовательность в том порядке, в котором элементы поданы на вход, и порядок «зашит» в том, на каком шаге какой токен обрабатывается. Это понадобится дальше — в трансформере такой встроенной подсказки о порядке нет (см. §3.6).

На пальцах

«Авторегрессионная генерация» — как заполнение кроссворда по одному слову за раз, каждый раз опираясь на уже вписанные слова: декодировщик не видит будущих токенов, только прошлые (свои же сгенерированные) плюс «сводку» от кодировщика.

2.3. Мультипликативное внимание (сл. 17)

Внимание — сила связи между векторами двух последовательностей $G=\{g_i\}\in\mathbb{R}^{s_1\times D}$ и $H=\{h_j\}\in\mathbb{R}^{s_2\times D}$, оцениваемая скалярным произведением: $e_{ij}=g_ih_j^{\intercal}$. Для большей выразительности вводится билинейная форма с обучаемой матрицей $W\in\mathbb{R}^{D\times D}$: $e_{ij}=g_iWh_j^{\intercal}$, или в матричном виде $E=GWH^{\intercal}$ (сл. 17).

Из записи лекции [36:55–40:14]

Внимание — сила связи между векторами, оцениваемая скалярным произведением; это тоже связано с семантическим пространством — близкие по смыслу вектора дают большое скалярное произведение, далёкие — маленькое. Чтобы увеличить выразительную силу, между векторами вставляют обучаемую матрицу весов $W$ размера $D\times D$: она определяет, какие компоненты скалярного произведения важнее. Вопрос лектора: откуда взять матрицу $W$? Ответ студента (Speaker 5, 40:08): обучить на множестве текстов/переводов — лектор подтверждает: $W$ должна быть обучаемой матрицей, а не выставляться вручную.

На пальцах

Без матрицы $W$ скалярное произведение $g_ih_j^\intercal$ сравнивает векторы «в лоб», компонента к компоненте с равным весом; матрица $W$ — как настраиваемый «фильтр значимости»: она может решить, что первая координата векторов для данной задачи важнее десятой.

2.4. От мультипликативного внимания к самовниманию (сл. 18–19)

На $W$ накладывается ограничение в виде разложения на две матрицы той же размерности: $W=W_QW_K^{\intercal}$, $W_Q,W_K\in\mathbb{R}^{D\times D}$. Тогда $E=GWH^{\intercal}=G(W_QW_K^{\intercal})H^{\intercal}=(GW_Q)(W_K^{\intercal}H^{\intercal})$; пользуясь тождеством $B^{\intercal}A^{\intercal}=(AB)^{\intercal}$, получаем $E=(GW_Q)(HW_K)^{\intercal}$. Если вместо двух последовательностей $G,H$ подать одну и ту же последовательность $X$: $E=(XW_Q)(XW_K)^{\intercal}$, $XW_Q=Q$, $XW_K=K$ — внимание последовательности направлено само на себя: $E=QK^{\intercal}$. Это механизм самовнимания (self-attention) (сл. 18–19).

Из записи лекции [40:14–44:43]

Матрицу $W$ раскладывают на произведение $W_QW_K^{\intercal}$, переписывают формулу мультипликативного внимания и получают «красивую запись» $(GW_Q)(HW_K)^{\intercal}$. Вопрос студента (41:26, «зачем транспонировать $W_K$?»): это математический трюк ради именно такой компактной формы записи. Далее, поскольку обрабатывается только одна входная последовательность (а не две разные, $G$ и $H$), заменяют обе матрицы на $X$ и вводят обозначения $Q=XW_Q$, $K=XW_K$ — получается механизм самовнимания.

Уточняющие вопросы студента (43:10–44:43): «$X$ — это то, что получилось из перемножения $G$ на $H$?» — нет: $X$ — это просто входная матрица эмбеддингов (например, для входа I, love, cats — три строки, $D$ столбцов). «Как образовались матрицы $W_Q$, $W_K$?» — они получены разбиением исходной матрицы $W$ мультипликативного внимания на две матрицы (наложенное ограничение на возможность такого разложения).

На пальцах

Разложение $W=W_QW_K^{\intercal}$ — это как замена одной «толстой» настройки на две более простые независимые ручки: вместо одной большой матрицы $D\times D$, которая одновременно решает «что искать» и «чем отвечать», получаем отдельно матрицу для формирования запросов и отдельно — для ключей.

2.5. Матрица оценок внимания и softmax по строкам (сл. 20)

Строка $i$ матрицы $E$ отвечает за вектор $q_i$, «смотрящий» на все векторы $K$: $e_{ij}=q_ik_j^{\intercal}$, $e_i=(e_{i1},\dots,e_{is})$. Применяя к каждой строке функцию softmax, получаем распределение весов внимания: $a_i=\mathrm{Softmax}(e_i)$, или в матричной форме $A=\mathrm{Softmax}(QK^{\intercal})$ (сл. 20).

Из записи лекции [44:43–48:06]

Вопрос лектора — зачем применяем softmax? Студент отвечает: получить распределение (44:43), затем — что значения лежат в интервале $[0,1]$ (46:48). Лектор подтверждает оба пункта и ведёт к главному вопросу: почему именно softmax, а не поэлементная сигмоида, которая тоже даёт значения в $[0,1]$?

На пальцах

Softmax применяется «по строкам» матрицы $E$: каждая строка — это все оценки внимания одного конкретного вектора-запроса $q_i$ ко всем ключам, и нормируется она независимо от других строк.

2.6. Зачем именно softmax: единичный «бюджет внимания» (сл. 21)

Softmax можно рассматривать как многомерную сигмоиду; проблема у неё та же, что у сигмоиды — насыщение функции. Ключевое отличие softmax от поэлементной сигмоиды: сумма весов внимания в каждой строке равна единице, $\sum_j a_{ij}=1$ (сл. 21).

Из записи лекции [48:06–1:05:28]

Это самый долгий содержательный обмен вопросами лекции (Speaker 3 «Александр» и Speaker 6 «Полина»). Итоговый ответ лектора: главное отличающее свойство softmax — сумма всех элементов строки равна единице; это даёт трактовку «бюджета внимания» — вектор $q_i$ имеет бюджет внимания, равный единице, и распределяет его между всеми векторами $k_j$ последовательности (например, 0,8 одному вектору и по 0,1 — двум другим). Без этого свойства (как у поэлементной сигмоиды) веса разных векторов $q_i$ были бы просто несравнимы: ничто не мешало бы одному $q_i$ «раздать» в сумме больше внимания, чем другому, хотя в этом нет смысла — при самовнимании все элементы последовательности равноправны.

Промежуточный неточный ответ Полины (1:00:36 — «софтмакс не затухает»): лектор поправляет — softmax затухает так же, как и сигмоида, обе построены на отношении экспонент, и это тоже проблема (см. §2.7); путать «свойство суммы = 1» с «отсутствием насыщения» не стоит — это два разных вопроса.

На пальцах

Если бы вместо softmax к каждому элементу строки $e_i$ применили обычную сигмоиду, у вектора $q_1$ сумма выданного внимания могла бы получиться 2,3, а у вектора $q_2$ — 0,4: тогда «$q_1$ уделяет больше суммарного внимания всем соседям, чем $q_2$» — хотя оба вектора должны быть в равных условиях. Softmax искусственно уравнивает эти «бюджеты» в единицу для каждой строки.

2.7. Масштабирование на $\sqrt D$: откуда берётся дисперсия суммы (сл. 22–23)

$q_ik_j^{\intercal}=\sum_{k=1}^D q_i^{(k)}k_j^{(k)}$. Если $\mathbb{E}[q_i^{(k)}]=0$, $\mathrm{Var}[q_i^{(k)}]=1$ и аналогично для $k_j^{(k)}$, а слагаемые независимы, то $\mathbb{E}\big[\sum_k q_i^{(k)}k_j^{(k)}\big]=0$, $\mathrm{Var}\big[\sum_k q_i^{(k)}k_j^{(k)}\big]=D$. Деля на $\sqrt D$, возвращают дисперсию к единице: $A=\mathrm{Softmax}\!\left(\dfrac{QK^{\intercal}}{\sqrt D}\right)$ (сл. 22–23).

Из записи лекции [48:06–50:42] (продолжение обмена, см. 2.6)

Проблема насыщения softmax растёт с ростом размерности $D$: при вычислении $q_ik_j^\intercal$ складывается $D$ слагаемых, и чем больше $D$, тем больше по модулю получается сумма — это раздувает дисперсию оценок внимания и «пересыщает» softmax, из-за чего градиенты начинают затухать (та же проблема, что у сигмоиды). Оценивая статистику суммы при заданных предположениях (среднее 0, дисперсия 1 у каждой компоненты, независимость слагаемых), получают дисперсию суммы, равную $D$; чтобы вернуть её к единице, каждый элемент делят на $\sqrt D$.

На пальцах

Проверено в песочнице (симуляция $2\times10^5$ пар случайных векторов, $\mathbb{E}=0$, $\mathrm{Var}=1$ на компоненту): при $D=8$ дисперсия $q\cdot k$ получилась $7{,}998$ (теория — 8); при $D=512$ — $510{,}9$ (теория — 512); после деления на $\sqrt D$ дисперсия в обоих случаях $\approx1{,}00$ — предсказание лектора подтверждается численно с точностью до случайного шума выборки.

2.8. От весов внимания к преобразованию: матрица $W_V$ как фильтр (сл. 24–26)

Матрица $A$ сама по себе — только веса, без преобразования. Простейший вариант — агрегировать последовательность $X$ напрямую: $O=AX$, то есть $o_i=\sum_j a_{ij}x_j$ (средневзвешенное, так как $\sum_j a_{ij}=1$). Такой подход ограничен, поэтому вводится обучаемая матрица $W_V$: $V=XW_V$, $O=AV$. Матрица $W_V$ — «фильтр», определяющий, с каким весом и какую информацию извлекать из каждой компоненты $x_j$: $v_j=x_jW_V$ (сл. 24–26).

Из записи лекции [50:42–55:09]

Матрица весов внимания $A$ имеет размерность «длина последовательности на длину последовательности» и сама по себе не выполняет преобразования — только распределяет веса. Простейшее преобразование — агрегация исходных векторов $X$ по этим весам, но это ограниченный подход (по аналогии с мультипликативным вниманием). Поэтому вводится ещё одна обучаемая матрица $W_V$: элемент строки $v_j$ переставляют местами внутри суммы и видят, что $W_V$ действует как фильтр, взвешивающий вклад каждой компоненты вектора $x_j$.

Вопрос студента (55:33, «почему не сингулярное разложение $X$?»): сингулярное разложение тяжело считается и очень плохо параллелится на видеокартах — это его главная проблема; при всей его мощности как инструмента, для этой задачи оно непрактично.

На пальцах

$O=AX$ — это как «смешать краски по рецепту $A$, но использовать сами исходные цвета $X$ без изменений»; $O=AV=A(XW_V)$ — сначала пропустить исходные цвета через фильтр $W_V$ (получить новые оттенки $V$), а уже потом смешивать их по рецепту $A$. Второй вариант гибче: фильтр $W_V$ можно обучить решать, какие «оттенки» вообще стоит передавать дальше.

2.9. Финальная формула self-attention; интуиция Q, K, V (сл. 27–28)

Итоговая форма преобразования: $O=\mathrm{Softmax}\!\left(\dfrac{QK^{\intercal}}{\sqrt D}\right)V$. Матрицы $Q$, $K$, $V$ называются запросами (queries), ключами (keys) и значениями (values): $q_i$ — что текущий элемент хочет найти в остальных; $k_j$ — ключ, по которому сопоставляется запрос; $v_j$ — то, что реально передаётся дальше после взвешивания по вниманию (сл. 27–28).

Из записи лекции [1:05:28–1:13:14]

Развёрнутый диалог о смысле $W_V$ (Александр, 1:05:28–1:10:55): студент предлагает трактовать $W_V$ как «усиление внимания», делающее одни компоненты более контрастными. Лектор уточняет: это не совсем усиление контраста — $W_V$ работает вне самого механизма внимания, как фильтр над входной последовательностью $X$ (превращая её в $V$), а уже после этого поверх $V$ применяется взвешивание матрицей $A$. Разложение исходной матрицы $W$ на $W_Q,W_K$ — это то, что делает внимание более сложным (позволяет находить нетривиальные зависимости), а $W_V$ — отдельный, независимый фильтр «что передавать дальше».

Итоговая интуиция (1:10:55–1:13:14): $q_i$ — запрос, «что текущий элемент хочет найти» среди остальных элементов (включая себя — это самовнимание); $k_j$ — ключ, отвечающий на запрос (совпадение $q_i$ и $k_j$ даёт большое скалярное произведение, несовпадение — маленькое); $v_j$ — значение, которое передаётся дальше согласно матрице $W_V$. Терминология запросов/ключей/значений пришла из рекомендательных систем.

На пальцах

Аналогия с библиотечным каталогом: $q_i$ — ваш запрос библиотекарю («книги про архитектуру трансформеров»); $k_j$ — ключевые слова на карточках всех книг в каталоге; чем ближе ключевые слова карточки к вашему запросу, тем выше «внимание» (совпадение); $v_j$ — содержимое самой книги, которое вы получите, если библиотекарь сочтёт её релевантной. Итоговый вектор $o_i$ — это «смесь содержимого» всех книг, взвешенная по релевантности каждой из них вашему запросу.

2.10. Многоглавое внимание: мотивация и формула по головам (сл. 29–30)

Одна тройка матриц $W_Q,W_K,W_V$ задаёт только одно распределение внимания, но реальные зависимости между элементами (например, синтаксические роли слов) слишком сложны и разнообразны для одной тройки. Решение — несколько параллельных независимых голов: $W_Q^{(h)},W_K^{(h)},W_V^{(h)}\in\mathbb{R}^{D\times d_h}$, $d_h=D/H$ ($H$ — число голов). Самовнимание одной головы: $O^{(h)}=\mathrm{Softmax}\!\left(\dfrac{Q^{(h)}K^{(h)\intercal}}{\sqrt{d_h}}\right)V^{(h)}$ (сл. 29–30).

Из записи лекции [1:13:14–1:29:56]

Мотивация через «помощь зала» (1:13:14–1:21:24, реплики Александра, Полины и Романа): одно слово в предложении может нести разные грамматические роли (подлежащее, дополнение и т. д.), и одной тройкой $W_Q,W_K,W_V$ всю грамматику линейно не описать. Студенты по цепочке предлагают: «своя тройка у каждого нейрона» → «ещё один слой» → «параллельные механизмы внимания» — лектор подтверждает последнюю идею и вместе со студентами восстанавливает на доске схему: к входу $X$ пристраивается вторая параллельная ветка внимания рядом с первой, что и называется «головами внимания». Стакать механизмы внимания можно не только последовательно (это очевидно и всегда напрашивается), но и параллельно — что вдобавок хорошо параллелится на видеокартах (подробнее — Лекция 4, Flash Attention: lecture4_konspekt.html#p2; Лекция 3 посвящена архитектуре GPU).

Почему масштабирование меняется с $\sqrt D$ на $\sqrt{d_h}$ (1:22:39–1:28:12, вопрос лектора, отвечает Полина после долгих наводящих вопросов): в многоголовом внимании векторы $Q,K$ сжимаются с исходной размерности $D$ до $d_h=D/H$; сумма в скалярном произведении $q_i k_j^\intercal$ теперь состоит из $d_h$, а не $D$ слагаемых, поэтому по той же логике, что и в §2.7, дисперсия суммы становится $d_h$, и для её нормировки к единице делят на $\sqrt{d_h}$, а не на $\sqrt D$.

Вопрос студента (1:28:52 — «головы обязательно должны быть одного размера?»): строго не обязательно, но желательно — это уже не вопрос математики, а вопрос инженерной реализации: одинаковая размерность голов удобнее для эффективной утилизации ресурсов GPU (подробнее — Лекция 3).

На пальцах

Пример на числах: пусть $D=512$, $H=8$ голов, тогда $d_h=64$. 2.11. Объединение голов, матрица $W_O$; параметрическая стоимость (сл. 31–32)

Головы объединяются конкатенацией: $O_{\mathrm{concat}}=\mathrm{Concat}[O^{(1)},\dots,O^{(H)}]$. Информация в $O_{\mathrm{concat}}$ всё ещё разделена покомпонентно по головам; чтобы её перемешать, добавляется обучаемое линейное преобразование $W_O\in\mathbb{R}^{D\times D}$: $O=O_{\mathrm{concat}}W_O$. Несмотря на кажущуюся сложность, рост числа параметров и вычислений связан только с появлением $W_O$ (сл. 31–32).

Из записи лекции [1:29:56–1:33:49]

После вычисления $H$ голов их конкатенируют в один вектор размерности $D$ — той же, что была на входе. Но информация всё ещё разделена по головам покомпонентно, поэтому добавляется ещё одно обучаемое линейное преобразование $W_O$ — проекция из пространства, где каждая компонента взята из своего отдельного семантического пространства головы, в единое общее пространство.

Подсчёт параметров и вычислений (1:31:49–1:32:50): каждая из $H$ троек матриц $W_Q^{(h)},W_K^{(h)},W_V^{(h)}$ в $H$ раз меньше матрицы одноголового внимания; $H$ матриц по $D/H\times D$ дают в сумме то же число параметров $D\times D$, что и одна голова. Рост происходит только за счёт добавления $W_O$ размера $D\times D$ — то есть примерно на 33% (три исходные матрицы плюс одна новая четвёртая) относительно одноголового варианта.

2.12. Маскированное многоглавое внимание (сл. 33)

До сих пор каждый элемент последовательности мог обратить внимание на любой другой. Иногда это недопустимо — вводится маска: к матрице оценок $E$ прибавляется матрица $M$ из $-\infty$ на запрещённых позициях и нулей на разрешённых, применяемая до softmax (а не после, чтобы не портить свойство «сумма строки $=1$»): $\mathrm{Softmax}(x)_j=\exp(x^{(j)})/\sum_k\exp(x^{(k)})$, а $\exp(-\infty)=0$ (сл. 33).

Правильный путь — применять маску до softmax, добавляя к оценкам внимания $-\infty$ на запрещённых позициях (а не 0): тогда после softmax эти позиции автоматически получат вес ровно 0 (так как $\exp(-\infty)=0$), а распределение весов по оставшимся, разрешённым позициям не будет искусственно смещено — оно останется таким же по форме, каким было бы без учёта запрещённых элементов.

Маскирование через $-\infty$ до softmax — «выключить микрофон до голосования, а не censurировать уже объявленные результаты»: если сначала честно посчитать веса, а потом обнулить часть из них, оставшиеся веса перестанут суммироваться в единицу и придётся пересчитывать всё заново; если же запретить кандидату участвовать в голосовании заранее ($-\infty$ до softmax), результат по разрешённым кандидатам сразу корректно нормирован.

2.13. Перекрёстное внимание (сл. 34–35)

При переходе от мультипликативного внимания к самовниманию было сделано упрощение — подавать на вход только одну последовательность $X$: $E=(GW_Q)(W_K^{\intercal}H^{\intercal})=\widetilde Q\widetilde K^{\intercal}$. Но ничто не мешает последовательностям $Q$ и $K$ происходить из разных источников и быть разной длины — важно лишь, чтобы $s_{\widetilde V}=s_{\widetilde K}$. Пусть $\widetilde Q=XW_Q$ из последовательности $X$, а $\widetilde K=ZW_K$, $\widetilde V=ZW_V$ — из другой последовательности $Z$. Механизм внимания на основе двух последовательностей называется перекрёстным вниманием (cross-attention): $O=\mathrm{Softmax}\!\left(\dfrac{\widetilde Q\widetilde K^{\intercal}}{\sqrt{d_h}}\right)\widetilde V$ (сл. 34–35).

Из записи лекции [1:39:04–1:44:02]

Упрощение до одной последовательности $X$ было сделано «из здравого смысла», но все предыдущие выкладки не запрещают последовательностям $Q$ и $K$ происходить из разных источников и иметь разную длину; единственное реальное требование для корректности матричных умножений — совпадение длины $V$ и $K$ (длина $Q$ при этом может отличаться). Далее вводится переобозначение: $Q$ строится из входа $X$, а $K$ и $V$ — из другой последовательности $Z$; получившийся механизм называется перекрёстным вниманием.

Разбор размерностей на доске (1:40:18–1:43:22): $Q$ имеет размер $s_Q\times d_h$, $K^\intercal$ — $d_h\times s_K$; их произведение схлопывается в $s_Q\times s_K$ (после деления на $\sqrt{d_h}$ и построчного softmax размер не меняется); дальше матрица весов $s_Q\times s_K$ умножается на $V$ размера $s_K\times d_h$ (так как $s_V=s_K$), что даёт итоговую матрицу $O$ размера $s_Q\times d_h$ — той же «входной» размерности по $d_h$, что и $Q$.

Лекция прерывается на перерыв сразу после этого вывода (1:43:40); запись останавливается в 1:44:02, дальнейшая часть лекции (§3, §4) в этой записи не зафиксирована — см. легенду документа.

На пальцах

Перекрёстное внимание — это ровно то, что нужно декодировщику в архитектуре кодировщик-декодировщик (§3.11): запросы $Q$ идут от последовательности, которую декодировщик уже сгенерировал, а ключи и значения $K,V$ — от выхода кодировщика $Z$, то есть от исходного (например, английского) предложения. Так декодировщик «спрашивает» у входного предложения, какая его часть сейчас релевантна для генерации следующего слова перевода.

3.1. FFN-слой (сл. 37–38)

Механизм внимания отвечает за обмен информацией между токенами; после него к каждому токену независимо применяется нелинейное преобразование — двухслойная сеть с активацией: $\mathrm{FFN}(x_i)=\phi(x_iW_1+b_1)W_2+b_2$, $W_1\in\mathbb{R}^{D\times D_{FFN}}$, $W_2\in\mathbb{R}^{D_{FFN}\times D}$. Внутренняя размерность $D_{FFN}$ обычно больше $D$ (расширение пространства признаков), что может вести к переобучению — для борьбы с этим добавляют Dropout: $\mathrm{FFN}(x_i)=\mathrm{Dropout}\big[\phi(x_iW_1+b_1)\big]W_2+b_2$, иногда ещё и после второго слоя (сл. 37–38).

На пальцах

Внимание — «обмен информацией между словами» (горизонтальное смешивание по последовательности), FFN — «переработка информации внутри одного слова» (вертикальное преобразование признаков): у каждого токена одна и та же сеть $W_1,W_2$, но применяется к нему независимо от соседей.

3.2. LayerNorm (сл. 39–40)

LayerNorm и BatchNorm основаны на одной идее нормализации активаций; разница — как считаются $\mathbb{E}[X]$ и $\mathrm{Var}[X]$: BatchNorm — по батчу, LayerNorm — по одному объекту. LayerNorm работает одинаково при обучении и инференсе (в отличие от BatchNorm, которому нужно накапливать статистики по батчу), лучше подходит для последовательностей разной длины и для малых батчей (сл. 39–40).

Рисунок (сл. 39–40). Два «кубика» с осями $C$ (каналы), $B$ (батч), $H,W$ (пространственные размерности, унаследовано из CNN-иллюстрации). У Batch Norm синим закрашен «срез» вдоль $H,W$ и $C$ при фиксированном элементе батча B; у Layer Norm — срез вдоль $H,W$ и $B$ при фиксированном канале $C$. На сл. 40 лектор добавил собственную пометку: «Это не совсем корректная иллюстрация».
На пальцах

Пометка лектора «не совсем корректная иллюстрация» справедлива: рисунок — стандартная CNN-картинка с осями $C,H,W,B$, а в трансформере LayerNorm нормирует не признаковую карту свёрточной сети, а один вектор-токен по его $D$ компонентам (для каждого токена и каждого элемента батча — независимо); иллюстрация передаёт общую идею «нормировать не по батчу, а по признакам одного объекта», но сама ось разбиения ($C$ против $B$) в трансформере не соответствует буквально осям $C,H,W$ картинки.

3.3. Наивный слой трансформера: проблема затухающих градиентов (сл. 41–42)

Собрав модули вместе «в лоб»: $\mathrm{TransformerLayer}(x)=\mathrm{LN}\circ\mathrm{FFN}\circ\mathrm{LN}\circ\mathrm{MHA}(x)$ — такую сеть обучить не получится: градиенты будут сильно затухать уже после первого слоя (сл. 41–42).

На пальцах

Даже один такой слой — это уже четыре последовательных матричных умножения внутри MHA, softmax, две нормализации и два линейных преобразования FFN с активацией; при глубине в десятки таких слоёв градиент, умножаясь через все эти нелинейности, гаснет, не успевая дойти до первых слоёв сети.

3.4. Residual connections (сл. 43)

Чтобы избежать затухания градиентов, к выходу каждого крупного подслоя добавляется его вход (остаточная связь): $z=\mathrm{LN}\big(x+\mathrm{MHA}(x)\big)$, $y=\mathrm{LN}\big(z+\mathrm{FFN}(z)\big)$ (сл. 43).

На пальцах

Residual connection — «объездная дорога» рядом с основной магистралью (MHA или FFN): даже если сигнал через магистраль сильно ослабнет, копия входа всё равно доходит до выхода слоя напрямую, и градиенту есть по какому пути распространяться назад, не затухая полностью.

3.5. Дифференцирование трансформера: как residual connections спасают градиент (сл. 44–46)

Продифференцировав $y$ по $z$ и $z$ по $x$: $\dfrac{\partial y}{\partial z}=\dfrac{\partial \mathrm{LN}(z+\mathrm{FFN}(z))}{\partial(z+\mathrm{FFN}(z))}\Big(1+\dfrac{\partial \mathrm{FFN}(z)}{\partial z}\Big)$, аналогично для $\partial z/\partial x$. Перемножив и сгруппировав множители: $$\dfrac{\partial y}{\partial x}=\dfrac{\partial \mathrm{LN}(\tilde z)}{\partial \tilde z}\cdot\dfrac{\partial \mathrm{LN}(\tilde x)}{\partial(\tilde x)}\cdot\Big(1+\dfrac{\partial \mathrm{FFN}(z)}{\partial z}\Big)\Big(1+\dfrac{\partial \mathrm{MHA}(x)}{\partial x}\Big).$$ Раскрыв скобки, произведение распадается на слагаемое, где градиенты почти не затухают (произведения производных LayerNorm), слагаемые, где градиенты затухают слабее (по одной из веток FFN/MHA), и слагаемое, где градиенты затухают сильно (обе ветки FFN и MHA перемножены) (сл. 44–46).

Рисунок (сл. 46). Развёрнутая формула $\partial y/\partial x$ с фигурными скобками снизу, подписанными: «Градиенты почти не затухают» — под произведением производных двух LayerNorm; «Градиенты затухают слабее» — под суммой $\partial FFN/\partial z+\partial MHA/\partial x$; «Градиенты сильно затухают» — под их произведением $\partial FFN/\partial z\cdot\partial MHA/\partial x$.
На пальцах

Ключевая единица «1 +» в каждой скобке — это буквально вклад остаточной связи: даже если $\partial\mathrm{FFN}(z)/\partial z\to0$ (градиент внутри FFN затух), множитель $(1+0)=1$ всё равно пропускает градиент дальше без ослабления. Без residual connections на месте каждой «1 +» стоял бы просто сам (потенциально крошечный) член $\partial\mathrm{FFN}/\partial z$ — и после десятков слоёв произведение таких малых чисел стремилось бы к нулю.

3.6. Зачем нужно позиционное кодирование (сл. 47–48)

Внимание смотрит на всю последовательность разом (преобразование вектора не зависит от его порядка), а FFN и LayerNorm обрабатывают токены по отдельности и независимо — нигде в слое трансформера нет информации о порядке токенов. Между тем порядок слов критичен для смысла: «Er kommt morgen nicht» (он не придёт завтра) vs «Er kommt nicht morgen» (он придёт, но не завтра) — одинаковые слова, разный порядок, противоположный смысл (сл. 47–48).

На пальцах

Без позиционного кодирования механизм внимания «видит» последовательность как мешок токенов (bag of tokens): переставьте слова местами, и для самого механизма внимания (без учёта порядка) ничего не изменится — как и упомянуто в §2.2, эта проблема в LSTM решалась «бесплатно» самим порядком обработки шагов, а в трансформере эту информацию нужно добавлять явно.

3.7. Абсолютное позиционное кодирование (сл. 49)

К каждому токену прибавляется вектор, кодирующий его абсолютную позицию: $\hat x_{\mathrm{pos}}=x_{\mathrm{pos}}+PE(\mathrm{pos})$, где $PE:\mathbb{N}\to\mathbb{R}^D$. Требования к функции $PE$: разные позиции кодируются разными векторами; близкие позиции — близкими векторами; модель способна восстановить относительные сдвиги между позициями (сл. 49).

На пальцах

Третье требование — самое содержательное: если знать вектор позиции 5, для модели должно быть легко «вычислить» вектор позиции 5+3=8, не глядя на абсолютное значение «8» — именно это свойство и обеспечивает синусоидальное кодирование ниже (§3.8).

3.8. Синусоидальное кодирование (сл. 50–52)

Для выполнения третьего требования естественно использовать синус и косинус, пользуясь тождествами $\sin(\alpha+\beta)=\sin\alpha\cos\beta+\cos\alpha\sin\beta$, $\cos(\alpha+\beta)=\cos\alpha\cos\beta-\sin\alpha\sin\beta$: если в паре компонент записать $\sin(\omega\cdot\mathrm{pos})$ и $\cos(\omega\cdot\mathrm{pos})$, то кодировка позиции $\mathrm{pos}+k$ выражается через кодировку позиции $\mathrm{pos}$ и сдвиг $k$ при той же частоте $\omega$. Задав каждой паре компонент свою частоту: $PE(\mathrm{pos},2i)=\sin\!\big(\mathrm{pos}/10000^{2i/D}\big)$, $PE(\mathrm{pos},2i+1)=\cos\!\big(\mathrm{pos}/10000^{2i/D}\big)$ — малые $i$ соответствуют низким частотам, большие — высоким (сл. 50–52).

На пальцах

Числовая проверка тождества (песочница, $\omega=0{,}5$, $\mathrm{pos}=3$, $k=2$): $\sin(0{,}5\cdot5)=\sin(0{,}5\cdot3)\cos(0{,}5\cdot2)+\cos(0{,}5\cdot3)\sin(0{,}5\cdot2)$ — обе части точно совпадают ($0{,}598472\ldots$, разница $0$ в пределах машинной точности), подтверждая, что кодировка позиции $\mathrm{pos}+k$ действительно линейно выражается через компоненты позиции $\mathrm{pos}$ (это и значит, что модель в принципе может «выучить» сдвиг на $k$ линейным преобразованием координат).

3.10. Трансформер-декодировщик и маскированное внимание (сл. 54)

Декодировщик преобразует последовательность $X_2$ не в латентное представление $Z$, а в продолжение $Y$. Обычное внимание здесь не подходит — каждый токен видел бы все последующие, «заглядывая в будущее»; используется маскированное внимание с $m_{ij}=0$ при $j\le i$ и $m_{ij}=-\infty$ при $j\gt i$: $\mathrm{MaskedMHA}(x)=\mathrm{Softmax}\!\left(\dfrac{QK^\intercal}{\sqrt{d_h}}+M\right)V$ (сл. 54; маска — частный, причинный случай общей маски §2.12).

На пальцах

Условие $j\le i$ на маске — это ровно нижнетреугольная маска с рисунка сл. 33 (§2.12): токен $i$ видит себя и всех предыдущих ($j\le i$), но не видит будущих ($j\gt i$).

3.11. Кодировщик-декодировщик и перекрёстное внимание (сл. 55)

В архитектуре кодировщик-декодировщик выход кодировщика $Z$ нужно передать в декодировщик — это делается перекрёстным вниманием (§2.13): $\tilde x=\mathrm{LN}\big(x+\mathrm{MaskedMHA}(x)\big)$, $\hat x=\mathrm{LN}\big(\tilde x+\mathrm{CrossAttention}(\tilde x,Z)\big)$, $y=\mathrm{LN}\big(\hat x+\mathrm{FFN}(\hat x)\big)$; в перекрёстном внимании $Q$ идёт из $X_2$, а $K,V$ — из $Z$ (сл. 55).

Полная схема из статьи «Attention is all you need»: слева блок кодировщика ($N\times$: Multi-Head Attention → Add&Norm → Feed Forward → Add&Norm) с Input Embedding и Positional Encoding снизу; справа блок декодировщика ($N\times$: Masked Multi-Head Attention → Add&Norm → Multi-Head Attention [со стрелками от выхода кодировщика] → Add&Norm → Feed Forward → Add&Norm) с Output Embedding (Outputs, shifted right) и Positional Encoding снизу; сверху — Linear → Softmax → Output Probabilities.
На пальцах

В декодировщике теперь две разновидности внимания подряд: сначала маскированное самовнимание (декодировщик смотрит только на уже сгенерированную часть $X_2$), затем перекрёстное внимание (декодировщик «спрашивает» у входа кодировщика $Z$, что из исходного предложения сейчас релевантно).

3.12. Обучение трансформера: постановка задачи и сдвиг на 1 токен (сл. 56–57)

Выход трансформера — последовательность векторов; нужна последовательность токенов, поэтому над выходом строится классификационная голова, предсказывающая токен словаря по вектору, с функцией потерь кросс-энтропии. Во время обучения нужно предсказать последовательность токенов, сдвинутую на 1 шаг влево: если на вход подаётся <BOS>, <Архитек> <тура/w>, < >, <Трансфор>, <мер/w>, то целевая последовательность — <Архитек> <тура>, < >, <Трансфор>, <мер/w>, <EOS> (сл. 56–57).

Вне слайдов

Разложение кросс-энтропии $H(p,q)=H(p)+D_{KL}\langle p\Vert q\rangle$ (стандартный результат теории информации): $H(p)$ — энтропия истинного распределения следующего токена при заданном контексте (шум данных, который никаким обучением не убрать), $D_{KL}\langle p\Vert q\rangle\ge0$ — та часть, на которую влияет обучение модели $q$. В пределе идеального обучения функция потерь не опускается ниже $H(p)$.

Вне слайдов

Перплексия (по письменному конспекту лектора; на слайдах не встречается). Взяв экспоненту от кросс-энтропии, $\exp(H(p,q))=\prod_i q_i^{-p_i}$, получают величину, называемую перплексией: $\mathrm{Perplexity}(p,q)=\exp(H(p,q))$. Чем выше вероятность, которую модель назначает правильным токенам, тем меньше перплексия; её можно трактовать как «среднее число вариантов», между которыми колеблется модель на каждом шаге — например, $\mathrm{Perplexity}=10$ означает, будто на каждом шаге модель выбирает из 10 равнозначных вариантов. Перплексия используется как метрика качества обучения языковой модели.

3.13. Инференс трансформера (сл. 58)

Во время инференса модель на каждой итерации предсказывает новый токен, пока не будет предсказан <EOS> либо не достигнута максимальная длина последовательности; в отличие от обучения (все позиции предсказываются параллельно), инференс строго последователен, так как каждый следующий токен зависит от уже сгенерированных (сл. 58).

На пальцах

Простейшая стратегия выбора токена — жадный алгоритм (всегда самый вероятный токен); альтернатива — сэмплирование из полученного распределения, с риском выбрать маловероятный «случайный» токен; компромисс — сэмплирование из top-$k$ вариантов.

3.14. Температура трансформера (сл. 59)

Распределение логитов классификатора превращается в распределение вероятностей через softmax; чтобы регулировать разброс значений вероятностей, используют softmax с температурой: $\mathrm{Softmax}_T(x)=\dfrac{e^{x_k/T}}{\sum_{i=0}^{n-1}e^{x_i/T}}$ (сл. 59).

На пальцах

При $T\to0$ softmax с температурой стягивается к argmax (жадной генерации, детерминированной и однообразной); при $T\gt1$ распределение «выравнивается» — большим логитам отдаётся меньше приоритета, генерация становится более разнообразной, но и более рискованной по качеству.

4.1. Проблемы CNN и идея адаптации трансформера (по конспекту лектора; сл. 60)

У свёрточных сетей (CNN) две проблемы: (1) отсутствие восприятия глобального контекста — на каждом слое CNN обрабатывает изображение через локальные поля, дальние области связываются только косвенно и постепенно; (2) одинаковые фильтры применяются ко всему изображению, что неэффективно при неравномерно распределённой полезной информации. Обе проблемы решает механизм внимания — самовнимание может отдавать приоритет разным участкам, а архитектура трансформера рассчитана на последовательности произвольной длины, то есть в принципе применима к изображениям разного размера.

На пальцах

Свёрточное «локальное поле зрения» — это как читать книгу через узкую трубку, видя всего пару слов за раз: чтобы связать первое и последнее предложение главы, нужно последовательно «сдвигать трубку» много раз; самовнимание — это как посмотреть на всю страницу сразу и сравнить любые два слова напрямую, независимо от расстояния между ними.

4.2. Токенизация изображений: патчи вместо пикселей (по конспекту лектора; сл. 60)

Если считать токеном один пиксель, изображение $256\times256$ даёт 65536 токенов — контекстного окна не хватит для изображений покрупнее; кроме того, отдельный пиксель (для RGB — трёхмерный вектор) плохо сравним с плотным embedding-вектором токена (например, размерности 512). Авторы ViT предложили резать изображение $x\in\mathbb{R}^{H\times W\times C}$ на патчи $16\times16\times C$ и проецировать каждый патч в вектор размерности $D$ — линейным слоем либо сверткой с размером ядра и шагом 16; архитектура кодировщика трансформера при этом не меняется, различия с оригинальной статьёй о трансформере — только в способе подготовки входа.

Рисунок (сл. 60). Архитектура ViT (из статьи «An Image is Worth 16×16 Words»). Изображение разбито на сетку патчей (3×3 фрагмента показаны слева снизу), каждый патч стрелкой ведёт к блоку «Linear Projection of Flattened Patches»; результат — пронумерованные токены 0–9 (0 — дополнительный обучаемый токен [class], помечен звёздочкой) с добавленным Position Embedding, идущие в «Transformer Encoder»; сверху — «MLP Head», выдающий класс (Bird/Ball/Car/…).
На пальцах

Патч $16\times16\times3$ — это $768$ чисел на входе; после линейной проекции в вектор размерности $D$ (скажем, 768 или 1024) он становится «токеном» ровно того же формата, что и текстовый embedding-вектор — с этого момента ViT обрабатывает последовательность патчей буквально так же, как трансформер-кодировщик обрабатывает последовательность слов из §3.9.

4.3. Позиционное кодирование для изображений (по конспекту лектора; сл. 60)

Изображения, в отличие от текстовых последовательностей, имеют двумерную структуру; логичным шагом кажется двумерное позиционное кодирование патчей. Авторы ViT сравнили одномерное и двумерное обучаемое (не синусоидальное, как в §3.8) абсолютное позиционное кодирование и показали, что для изображений фиксированного размера существенного прироста точности от двумерного варианта нет — используется одномерное кодирование, как и в текстовом трансформере.

На пальцах

Патчи всё равно разворачиваются в один плоский список слева направо и сверху вниз (растровый порядок); можно было бы ожидать, что модели нужно явно «знать» и строку, и столбец патча — но эмпирически модель неплохо восстанавливает двумерную структуру и из одномерной нумерации патчей.

4.4. CLS-токен (по конспекту лектора; сл. 60)

Токен под номером 0 на схеме — CLS-токен (концепция впервые предложена в BERT). Он добавляется в начало входной последовательности и служит для агрегации информации всей последовательности через механизм самовнимания; его финальное скрытое состояние используется для классификации. Это позволяет избежать предвзятости, которая возникла бы при выборе для агрегации какого-то одного «обычного» токена последовательности.

На пальцах

CLS-токен — «пустой протокол собрания», в который через внимание постепенно «стекается» сводка со всех патчей-участников; в конце (после прохождения всех слоёв кодировщика) именно из него читают итоговое решение — класс изображения, — а не из вектора какого-то конкретного, произвольно выбранного патча.

Раздел 3. Вопросы для подготовки к защите лабораторных (теория)

Формат ответа: сначала тезис (1–2 предложения), затем аргументация от лица студента; ссылки на слайды и таймкоды — для самопроверки.

1. Почему в самовнимании используется именно softmax, а не поэлементная сигмоида — ведь обе дают значения в интервале $[0,1]$?

Тезис: потому что у softmax, в отличие от сигмоиды, сумма значений по строке равна единице — это даёт корректную трактовку «единичного бюджета внимания», который каждый вектор-запрос распределяет между всеми ключами; у поэлементной сигмоиды такой гарантии нет, и «бюджеты» разных запросов были бы несравнимы.

Аргументация: $A=\mathrm{Softmax}(QK^\intercal/\sqrt D)$ построчно даёт $\sum_ja_{ij}=1$ (сл. 20–21). Без этого свойства (как у сигмоиды, применённой к каждому элементу независимо) ничто не мешало бы сумме внимания одного вектора $q_i$ оказаться, скажем, 2,3, а другого — 0,4, хотя все элементы последовательности при самовнимании равноправны (запись 59:09–1:04:50). Оба варианта одинаково страдают от насыщения при больших по модулю аргументах экспоненты (запись 1:01:11) — это отдельная, не решаемая выбором функции проблема, устраняемая масштабированием на $\sqrt D$ (см. вопрос 2).

2. Зачем оценки внимания делят на $\sqrt D$ (а в многоголовом варианте — на $\sqrt{d_h}$)? Что случится, если этого не делать?

Тезис: скалярное произведение $q_ik_j^\intercal$ — сумма $D$ (или $d_h$) слагаемых с дисперсией 1 каждое, поэтому дисперсия суммы растёт пропорционально размерности; без нормировки при большом $D$ softmax насыщается (переходит в почти one-hot), и градиенты через него перестают течь. Деление на $\sqrt D$ возвращает дисперсию к единице.

Аргументация: при $\mathbb{E}[q^{(k)}]=0$, $\mathrm{Var}[q^{(k)}]=1$ (и аналогично для $k^{(k)}$) и независимости слагаемых $\mathrm{Var}\big[\sum_{k=1}^Dq^{(k)}k^{(k)}\big]=D$ (сл. 22). Численно проверено в песочнице: при $D=512$ дисперсия $q\cdot k$ по $2\times10^5$ случайным парам получилась $510{,}9$ (теория 512), после деления на $\sqrt D$ — $0{,}998$. В многоголовом варианте векторы сжаты до $d_h=D/H$, поэтому и делить нужно уже на $\sqrt{d_h}$, а не на $\sqrt D$ (сл. 30; запись 1:22:39–1:28:12) — иначе для узких голов масштаб снова окажется неверным.

3. Почему маску в маскированном внимании накладывают прибавлением $-\infty$ до softmax, а не обнулением уже посчитанных весов после softmax?

Тезис: обнуление весов $a_{ij}$ после softmax ломает свойство $\sum_ja_{ij}=1$ и смещает распределение оставшихся весов непредсказуемым образом; прибавление $-\infty$ к оценкам внимания до softmax даёт после softmax ровно 0 на запрещённых позициях, а распределение по разрешённым — корректно перенормированным.

Аргументация: $\mathrm{Softmax}(x)_j=e^{x^{(j)}}/\sum_ke^{x^{(k)}}$, и $e^{-\infty}=0$ (сл. 33; запись 1:33:49–1:39:04). Если бы вместо этого веса зануляли уже после softmax, сумма строки перестала бы равняться 1 (см. вопрос 1), и потребовался бы дополнительный шаг перенормировки; проще и корректнее не допустить запрещённые позиции до нормировки вообще.

4. Почему увеличение числа голов в многоголовом внимании почти не увеличивает число параметров и вычислений по сравнению с одной головой?

Тезис: каждая из $H$ голов работает в урезанном пространстве $d_h=D/H$, поэтому $H$ матриц размера $D\times d_h$ в сумме дают ровно $D\times D$ параметров — столько же, сколько у одной «полноразмерной» головы; единственный источник дополнительных параметров — матрица $W_O$ на выходе.

Аргументация: $W_Q^{(h)},W_K^{(h)},W_V^{(h)}\in\mathbb{R}^{D\times d_h}$, $H\cdot(D\times d_h)=D\times D$ (сл. 30–32; запись 1:31:49–1:32:50). Рост идёт только за счёт добавления $W_O\in\mathbb{R}^{D\times D}$ — то есть примерно на треть (четвёртая матрица той же формы к трём исходным) относительно одноголового варианта.

5. В чём разница между самовниманием и перекрёстным вниманием? Какое ограничение на размерности необходимо для перекрёстного внимания?

Тезис: в самовнимании $Q,K,V$ строятся из одной и той же последовательности $X$; в перекрёстном внимании $Q$ строится из одной последовательности, а $K,V$ — из другой, возможно другой длины. Единственное жёсткое требование — совпадение длины последовательностей $V$ и $K$ (длина $Q$ может отличаться).

Аргументация: $\widetilde Q=XW_Q$, $\widetilde K=ZW_K$, $\widetilde V=ZW_V$, необходимо $s_{\widetilde V}=s_{\widetilde K}$ (сл. 34–35; запись 1:39:04–1:44:02). Разбор размерностей на доске: $Q$ — $s_Q\times d_h$, $K^\intercal$ — $d_h\times s_K$, их произведение — $s_Q\times s_K$; после умножения на $V$ ($s_K\times d_h$, так как $s_V=s_K$) получаем $O$ размера $s_Q\times d_h$. Именно перекрёстное внимание передаёт выход кодировщика $Z$ в декодировщик (сл. 55, §3.11).

6. Как residual connections спасают трансформер от затухающих градиентов? Покажите на производной.

Тезис: без остаточных связей градиент проходит через все нелинейности слоя как единое произведение и может затухать экспоненциально с глубиной; с остаточными связями в каждом множителе появляется слагаемое «1 +», которое пропускает градиент даже если производная самого подслоя (MHA или FFN) близка к нулю.

Аргументация: $z=\mathrm{LN}(x+\mathrm{MHA}(x))$ даёт $\partial z/\partial x=\frac{\partial\mathrm{LN}(\tilde x)}{\partial\tilde x}\big(1+\frac{\partial\mathrm{MHA}(x)}{\partial x}\big)$ (сл. 41–46). После группировки множителей итоговое произведение $\partial y/\partial x$ распадается на слагаемое из одних LayerNorm-производных (почти не затухает), слагаемые с одной из веток FFN/MHA (затухают слабее) и слагаемое с обеими ветками перемноженными (затухает сильно) — но поскольку это сумма, а не произведение всех веток разом, доминирует наименее затухающий член.

7. Почему в трансформере используют LayerNorm, а не BatchNorm?

Тезис: LayerNorm считает статистики по признакам одного объекта (одного токена), а не по батчу — поэтому не зависит от размера батча и работает одинаково на обучении и инференсе, что критично для последовательностей переменной длины и генерации токен за токеном, где по определению нет «батча» из будущих токенов для накопления статистик.

Аргументация: BatchNorm вычисляет $\mathbb{E}[X]$, $\mathrm{Var}[X]$ по батчу и требует накопленных на обучении статистик для инференса; для малых батчей и разной длины последовательностей эти статистики становятся шумными (сл. 39–40). Лектор сам пометил иллюстрацию слайда как «не совсем корректную» (сл. 40) — стандартная CNN-картинка с осями $C,H,W,B$ не отражает буквально то, что в трансформере LayerNorm нормирует один $D$-мерный вектор-токен независимо для каждого элемента батча.

8. Почему BPE-токенизация гарантирует отсутствие токенов вне словаря на новом тексте — в отличие, например, от токенизации по словам?

Тезис: словарь BPE изначально содержит весь стартовый алфавит (или все байты), и каждое новое merge-правило лишь объединяет уже присутствующие в словаре элементы; применяя merge-правила по порядку обучения, текст можно токенизировать вплоть до отдельных символов алфавита — то есть всегда «собрать» его из известных словарю кусочков, при токенизации по словам же любая незнакомая форма слова целиком заменяется на <UNK>.

Аргументация: стартовый словарь = алфавит + спецтокены; merge-правила запоминаются и применяются в порядке обучения (сл. 6–11; запись 13:25–23:01). Если стартовый алфавит покрывает все символы (например, вся таблица UTF при byte-level BPE, сл. 12), то после применения всех merge-правил каждый оставшийся «несклеенный» символ либо уже в начальном алфавите, либо был явно добавлен merge-правилом — то есть по построению лежит в словаре (ответ студента, дополненный лектором, запись 17:31–23:01).

9. Зачем нужно позиционное кодирование и почему выбрано именно синусоидальное, а не, например, просто номер позиции как число?

Тезис: самовнимание, FFN и LayerNorm обрабатывают элементы последовательности без учёта их порядка, поэтому без явного кодирования позиции трансформер «не видит» порядок слов; синусоидальное кодирование выбрано, потому что позволяет линейно выразить кодировку позиции $\mathrm{pos}+k$ через кодировку позиции $\mathrm{pos}$ и сдвиг $k$ — то есть облегчает модели «выучивание» относительных сдвигов, чего не даёт кодирование одним сырым числом позиции.

Аргументация: нигде в слое трансформера нет информации о порядке токенов (сл. 47); пример «Er kommt morgen nicht» / «Er kommt nicht morgen» показывает, что порядок критичен для смысла (сл. 48). Синус/косинус с тождествами суммы углов дают $\sin(\omega(\mathrm{pos}+k))=\sin(\omega\,\mathrm{pos})\cos(\omega k)+\cos(\omega\,\mathrm{pos})\sin(\omega k)$ — линейное преобразование от кодировки позиции $\mathrm{pos}$ (сл. 50). Численно проверено (песочница, $\omega=0{,}5$, $\mathrm{pos}=3$, $k=2$): обе части тождества совпадают точно (разница $0$ в пределах машинной точности).

10. На лекции был задан вопрос: почему бы не получить матрицы Q/K сразу через сингулярное разложение входной матрицы $X$, вместо того чтобы вводить и обучать отдельные матрицы $W_Q,W_K$?

Тезис: сингулярное разложение (SVD) даёт похожую по духу декомпозицию, но вычислительно намного дороже и, что важнее, плохо параллелится на GPU; обучаемые матрицы $W_Q,W_K,W_V$ вычисляются простым (и хорошо параллелящимся) матричным умножением и оптимизируются градиентным спуском заодно со всей остальной сетью.

Аргументация (вопрос студента, запись 55:33–56:02): лектор ответил, что SVD — «очень тяжело считается» и «очень тяжело парализуется» на видеокартах, притом что это мощный инструмент, широко применяемый в других задачах. Матричное умножение $X\cdot W_Q$, напротив, — ровно та операция (GEMM), под которую оптимизировано железо GPU, и именно поэтому масштабирование трансформеров опирается на обучаемые линейные проекции, а не на разложения матриц, требующие итеративных численных методов (сл. 17–19).

11. Что такое перплексия, как она связана с кросс-энтропией и как её интерпретировать?

Тезис: перплексия — это экспонента от кросс-энтропии между истинным и предсказанным распределением следующего токена; её удобно трактовать как «эффективное число вариантов», между которыми колеблется модель на каждом шаге генерации — чем перплексия ниже, тем увереннее и точнее модель угадывает следующий токен.

Аргументация (по письменному конспекту лектора — на слайдах не встречается): $\mathrm{Perplexity}(p,q)=\exp(H(p,q))=\prod_iq_i^{-p_i}$; кросс-энтропия, в свою очередь, раскладывается как $H(p,q)=H(p)+D_{KL}\langle p\Vert q\rangle$ (сл. 56, расширено конспектом), где $H(p)$ — неустранимая «энтропия языка» (шум данных), а $D_{KL}$ — та часть, на которую модель способна повлиять обучением. $\mathrm{Perplexity}=10$, например, читается как «модель на каждом шаге выбирает как будто между 10 равновероятными вариантами».

"""

(object-ID маска: элементы одного объекта в паке видят друг друга, чужие - нет).

O^(h) = Softmax(Q^(h) K^(h)^T / sqrt(d_h) + M) V^(h), O = Concat[O^(1)..O^(H)] W_O.
"""
import numpy as np

rng = np.random.default_rng(42)

def multihead_self_attention(X, WQ, WK, WV, WO, H, mask=None):
    """
    X:  (S, D)           - входная последовательность (одна "строка" батча)
    WQ,WK,WV: (D, D)     - как в лекции: W = concat по головам W_Q^(h)
    WO: (D, D)
    H:  число голов, d_h = D // H
    mask: (S, S) из {0, -inf}; mask[i, j] = -inf означает "i не смотрит на j"
    """
    S, D = X.shape
    assert D % H == 0, "D должно делиться на H (сл. 30)"
    dh = D // H

    Q = X @ WQ   # (S, D)
    K = X @ WK
    V = X @ WV

    Qh = Q.reshape(S, H, dh).transpose(1, 0, 2)  # (H, S, dh)
    Kh = K.reshape(S, H, dh).transpose(1, 0, 2)
    Vh = V.reshape(S, H, dh).transpose(1, 0, 2)

    scores = Qh @ Kh.transpose(0, 2, 1) / np.sqrt(dh)     # (H, S, S)  формула сл. 30
    if mask is not None:
        scores = scores + mask[None, :, :]

    scores = scores - scores.max(axis=-1, keepdims=True)   # для устойчивости softmax
    exp = np.exp(scores)
    A = exp / exp.sum(axis=-1, keepdims=True)               # (H, S, S), построчно (сл. 20)

    Oh = A @ Vh                                              # (H, S, dh)
    O_concat = Oh.transpose(1, 0, 2).reshape(S, D)            # сл. 31
    O = O_concat @ WO                                         # сл. 31
    return O, A


def causal_mask(S):
    """Маскированное внимание декодировщика (сл. 33, m_ij = 0 если j<=i, иначе -inf)."""
    m = np.triu(np.full((S, S), -np.inf), k=1)
    return m


def packed_object_mask(object_ids):
    """
    ЛР1-совместимая object-ID маска: элемент i видит элемент j, только если
    object_ids[i] == object_ids[j] (несколько последовательностей упакованы в один блок).
    """
    S = len(object_ids)
    same = (object_ids[:, None] == object_ids[None, :])
    m = np.where(same, 0.0, -np.inf)
    return m


if __name__ == "__main__":
    D, H, S = 16, 4, 6
    X = rng.standard_normal((S, D))
    WQ = rng.standard_normal((D, D)) * 0.1
    WK = rng.standard_normal((D, D)) * 0.1
    WV = rng.standard_normal((D, D)) * 0.1
    WO = rng.standard_normal((D, D)) * 0.1

    # 1) без маски
    O_full, A_full = multihead_self_attention(X, WQ, WK, WV, WO, H)
    row_sums = A_full.sum(axis=-1)

    # 2) причинная (декодерная) маска
    cmask = causal_mask(S)
    O_causal, A_causal = multihead_self_attention(X, WQ, WK, WV, WO, H, mask=cmask)
    upper_tri_zero = np.allclose(A_causal[:, np.triu_indices(S, k=1)[0], np.triu_indices(S, k=1)[1]], 0.0)

    # 3) packed object-id маска: два "объекта" в одном блоке [0,0,0,1,1,1]
    obj_ids = np.array([0, 0, 0, 1, 1, 1])
    pmask = packed_object_mask(obj_ids)
    O_packed, A_packed = multihead_self_attention(X, WQ, WK, WV, WO, H, mask=pmask)
    cross_object_zero = np.allclose(A_packed[:, 0, 3:], 0.0) and np.allclose(A_packed[:, 3, :3], 0.0)

    print(f"D={D}, H={H}, d_h={D//H}, S={S}")
    print(f"Без маски:      shape O = {O_full.shape}, сумма по строкам A (все H,S) в [1-eps,1+eps]: "
          f"{np.allclose(row_sums, 1.0)}")
    print(f"Причинная маска: верхний треугольник A == 0: {upper_tri_zero}")
    print(f"Packed object-id маска: между объектами 0 и 1 внимание == 0: {cross_object_zero}")
    print(f"O (без маски), первая строка, первые 4 компоненты: {np.round(O_full[0, :4], 4)}")

Результат прогона: $D=16$, $H=4$, $d_h=4$, $S=6$. Без маски: форма выхода $O$ — $(6,16)$, сумма весов внимания по каждой строке (для всех голов и позиций) равна 1 в пределах машинной точности — подтверждает свойство softmax (§2.6). С причинной маской: все веса внимания строго выше главной диагонали равны 0 — подтверждает корректность маскирования (§2.12, §3.10). С packed object-id маской (два объекта длиной 3 в одном блоке из 6 токенов): внимание между разными объектами равно 0, а внутри объекта — считается свободно, что соответствует формату упакованных батчей ЛР1 (объектные маски вместо простого паддинга).
